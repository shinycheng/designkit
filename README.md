# DesignKit · AI 商品图生成平台

上传商品图，选一个提示词模板，AI 自动生成电商商品图/场景图/营销套图。
支持接入 ChatGPT 生图 API（含国内中转平台），并提供标准对外 API 供 ERP 等系统对接。

---

## 一、怎么启动（Mac 本机）

打开「终端」，进入本项目文件夹，运行：

```bash
./start.sh
```

首次运行会自动安装依赖（约 1-2 分钟）。看到启动提示后，用浏览器打开：

**http://127.0.0.1:8787**

- 初始账号：`admin`　初始密码：`admin123456`（登录页上也印着这一行，第一次部署不会找不到入口）
- **首次登录时网页会要求你设置新密码**，设置完才进入工作台
  （这个窗口关不掉——按 Esc、点窗口外面都没用；不想现在设就点窗口左下角的「退出登录」）
  这不只是个提示：**不改掉初始密码，任何功能都用不了**，点什么都会提示
  「请先修改初始密码，再使用其他功能」
- 以后想再改密码：左侧导航最下面那个「我的」（页面标题是「我的账户」）→「修改密码」
  （管理员在「系统设置」页底部也有一个，两个是同一件事；手机上导航在屏幕底部）
- 给同事开账号：见下面「七、给同事开账号（成员账号）」
- 停止服务：在终端里按 `Ctrl + C`

## 二、怎么接入真实的生图 API

本机用 `./start.sh` 启动时默认是「模拟生图」模式：生成的是占位图，**不花钱**，
用来先把流程跑通。

> ⚠️ **服务器/NAS 部署不一样**：部署用的 `example.env` 模板里已经写成了真实生图模式
> （`DESIGNKIT_PROVIDER=openai`），但 Key 是空的。所以部署完第一次点生成会直接报
> 「尚未配置生图 API Key」，而不是出占位图。按下面第 1-3 步把 Key 填上即可。
> 想先零成本跑通流程，就把 `.env` 里的 `DESIGNKIT_PROVIDER` 改成 `mock`。

拿到网关/中转平台的 API Key 后：

1. 登录后进入「系统设置」→「生图服务」
2. 服务模式选择「OpenAI 兼容接口」
3. 填写三项（**改完必须先点「保存此区域」**，再点「测试已保存的连接」——
   没保存就点测试，只会提示「请先保存当前更改」）：
   - **API 地址**：网关地址（例如自建网关 `http://192.168.31.235:8090/v1`，末尾带不带 `/v1` 都可以）
   - **API Key**：平台给你的密钥（一般 `sk-` 开头）
   - **生图模型**：默认 `gpt-image-2`（自建网关），其他平台按其文档填
5. 看到连接成功的提示后，「生成工作台」出的就是真实 AI 图了

> 生图费用由网关按张收取，与本系统无关。「测试连接」不产生生图费用。

> **这里填的是「全局 Key」**：默认情况下全公司共用它，所有人的生图费用记在一起。
> 想让每个成员各花各的钱（各自一把 Key、账单分得清），见
> 「七、给同事开账号（成员账号）」的 7.4 节。ERP 对外接口用的也是这把全局 Key。

**商品图会自动预处理**（建议保持开启）：发送前按所选比例补边（不裁产品）；
iPhone/Mac 的 HEIC 照片自动转码；手机竖拍照片按方向摆正。
输入图的透明通道怎么处理，取决于下面「出图底色」这个设置——
默认合成白底（避免变黑块），选了透明底则原样保留。

> **关于出图比例**（实测 2026-08-09，自建 Sub2API 网关 + gpt-image-2）：
> 该网关**忽略 size 参数**。出图比例由两件事决定，优先级从高到低：
> 1. **提示词里的构图措辞**——写 "tall/upright/bursting upward" 就出竖图，压过一切。
>    系统现在会自动把目标画幅（如 "The final image must be a square 1:1 image."）
>    写进提示词，并要求 AI 按该画幅构图，这是最可靠的控制手段。
> 2. **输入图比例**——所以「按比例预处理」开关要保持开启（把商品图补边到目标比例）。
>
> 两道保险都已默认启用。
>
> **出图要等多久**：单张约 1~5 分钟，参考图越多越慢（系统最多等 6 分钟才判超时）。
> 开启「AI 现场写提示词」再多花约 30 秒。网关空闲时可能快到 20 秒，
> 但等上几分钟是正常的，不是卡死。

## 二点二、出图比例：覆盖常用电商版位

尺寸下拉里现在有 8 个比例，都是按各平台版位选的：

| 比例 | 尺寸 | 拿来干嘛 |
|---|---|---|
| 1:1 | 1024×1024 | 淘宝/京东主图 |
| 3:4 | 1024×1360 | 详情页、小红书 |
| 4:5 | 1024×1280 | 社媒信息流 |
| 2:3 | 1024×1536 | 长图详情 |
| 9:16 | 1024×1824 | 抖音/快手封面 |
| 3:2 | 1536×1024 | 场景与横幅 |
| 4:3 | 1360×1024 | PC 端 banner |
| 16:9 | 1824×1024 | 视频封面 |

比例不是写死的清单，而是一套**护栏规则**（边长必须是 16 的倍数、最长边不超 2048、
长短比不超过 3:1）。以后要加新版位，只要在 `backend/app/services/sizing.py`
的预设表里加一行，网页端会自动跟着变——不用改五个地方。

## 二点三、透明底出图（免抠图，可选）

「系统设置 → 生图服务 → 出图底色」选**透明底 PNG**后，出图直接带透明通道：
同一张商品图可以随便叠任何背景，不用再一张张抠图。

选了之后系统会同时做三件事，否则参数发了也没用：模板里的「纯白背景」措辞会被
自动改写成「透明背景」；商品图预处理不再合成白底、补边也补透明；缩略图仍会
垫一层白（不然列表里透明区是黑块）。

> ⚠️ **你当前的网关不支持这个功能**。2026-08-09 实测自建 Sub2API 网关 + `gpt-image-2`，
> 返回 `Transparent background is not supported for this model.`，
> 系统会明确提示你改回「跟随模型」，不会白花生图的钱（只花了一次写提示词的文本开销）。
>
> 这个开关先留着——换成支持透明底的模型（如 OpenAI 官方 `gpt-image-1`）即可用。
> 换网关后第一次用请先出 1 张确认：多数网关不支持时会直接报错，但也有网关会
> **静默忽略**该参数、照常出实底图。

## 二点四、生成方式：选分类，不选模板

生成页的「生成方式」直接用提示词库的分类（电商主图、产品营销、社交媒体帖子…）。
你**不需要挑某一条具体提示词**，选个分类就行，剩下的交给 AI：

1. **通览**：把该分类下提示词的标题一次性给 `gpt-5.6-sol` 看，连同你的商品图。
   电商主图 420 条全部参与；超过 700 条的大分类（产品营销 4063 条、社交媒体
   5527 条）先按「像不像商品摄影」预筛，再随机抽 700 条——每次任务抽的都不一样，
   所以新同步进来的提示词能选上，不同商品也不会总撞同一批参考
2. **挑选**：它选出风格最搭这件商品的 4 条，返回编号
3. **精读**：系统取回这 4 条的**完整**提示词
4. **改写**：结合完整提示词 + 你的商品图 + 你填的「补充要求」+ 目标画幅，
   现场写出一条只属于这件商品的提示词，再交给生图模型

实测（可乐罐 + 电商主图分类）挑出来的是
「Hyper-Realistic Commercial Soda Can Advertisement」「Ice-Cold Cola Splash Ad」
「Splash Hero Beverage Photography」「Luxury Sparkling Water Can Ad」——
四条全是易拉罐/饮料广告，最终提示词写出了冷凝水珠、罐底冰爽水花、湿润反光台面。

**为什么不直接把库里的提示词发给生图模型**：库里 91% 的提示词把别人的商品写死在
里面了（"a bottle of oolong tea..."）。直接用会画出别人的商品——上传吹风机出来茶叶
就是这么来的。所以它们只作**风格参考**，永远不原样发出。

- 两次文本调用合计约 16 秒（出图本身 1-5 分钟，可忽略）
- 「自由模式」不参考提示词库，完全按你写的描述出图
- 在「生成记录」的详情里能看到 AI 实际发出的提示词

实测效果：上传吹风机 + 选「纯白背景商品图」+ 补充「突出金色点缀、背景略带暖调」，
AI 写出的提示词准确描述了 *"champagne-silver metallic body, glossy black accents,
refined gold trim, TIARALEEN REPRONIZER 107D Plus branding"*，出图的金色点缀明显强化。

- 文本模型调用失败时自动回退，不会挡住出图（画质会差一点）
- 可在「系统设置 → 生图服务」更换文本模型（需支持看图）
- ⚠️ 关掉「AI 现场写提示词」会让「按分类生成」失去意义——那时系统没有东西可写，
  只会用一句通用描述出图。想关就改用自由模式自己写。

## 二点五、灵感库：1.4 万条现成提示词

左侧导航「灵感库」内置了 YouMind 开源提示词库（CC BY 4.0，上游每日更新）：

- 管理员点「同步上游」即可拉取/更新全部约 1.4 万条提示词（约 1-2 分钟，同步中不要重复点）
- 支持关键词搜索（英文命中率更高）和 11 个分类筛选
- 看中某一条想单独用：点开详情 →「用它生成」带到生成工作台（走自由模式，原文照发）
- **平时不用来这里翻**：生成页选个分类，AI 会自己在这个库里挑，见「二点四」

> **一条提示词常同时属于多个分类**，按分类筛选时以它的全部标签为准。
> （早期只认第一个标签，导致「电商主图」416 条里有 398 条被前面的分类抢走、
> 只剩 18 条，按分类几乎什么都找不到——已修好。）

**自动更新**：上游每天更新两次，系统默认每 12 小时自动同步一次，无需手动点。
可在「系统设置 → 运行参数」调整间隔或关闭。多进程/多容器部署时靠数据库锁保证
只有一个进程真正同步；连续失败会自动退避（15 分钟 → 1 小时 → 6 小时），不会反复冲击上游。

> **同步需要访问 GitHub**（raw.githubusercontent.com）。部分地区直连不通，
> 这时到「系统设置 → 运行参数 → 同步代理」填一个代理地址（如 `http://127.0.0.1:7890`），
> 保存后点「测试同步连接」——它只拉一个很小的文件，几秒就知道通不通，
> 不用等两分钟的完整同步。
>
> 代理**只作用于灵感库同步**：生图网关是局域网地址，永远直连、不走代理。

## 二点六、出图之后能做什么

结果区除了「下载」，还有三个按钮：

- **用这张继续改** —— 把这张结果图放回商品图位置，作为下一轮的参考。
  电商修图的常态是「在满意的那版上微调背景/角度」，而不是拿原图重赌一次；
  这样上一版的构图和光影会被保留下来，废图率明显更低。
  「生成记录」页的详情里也有同样的「继续改」按钮，可以翻出几天前的图接着改。
- **导出平台尺寸** —— 在你自己电脑上把图裁成淘宝 800×800、小红书 1080×1440、
  抖音 1080×1920 等常用版位。**完全本地处理，不调用生图接口、不花钱**。
  可选「裁切填满」（适合主图）或「补白边」（怕裁到商品时用）。
- **再补 N 张** —— 只补缺的那几张，不把已经出好的重跑一遍。
  以前 4 张里坏 1 张只能整单重来，等于为 1 张图付 4 张的钱。
  补图会沿用上一批实际发出的提示词，所以补出来的图和原来是同一套设定。

## 三、怎么导入你自己的提示词库

进入「提示词模板」→ 右上角「导入」，上传 JSON 文件即可，同名模板会自动覆盖更新。

**不用记字段格式**：先在同一个页面点「导出 JSON」下载一份现有模板当样板，
照着它改就行——导入格式和导出格式完全一致。字段是：
`name`、`category_id`、`description`、`prompt_template`、`variables`、
`default_params`、`requires_input_image`、`is_enabled`、`sort`。

也可以直接把你的提示词库文件连同导出的样板一起发给 AI 助手（比如 Claude），
让它帮你转成导入格式。

模板里可以用 `{变量名}` 占位（比如 `{scene}`），并在模板编辑弹窗的「变量」区域添加输入框或下拉框，
使用者生成时填写即可。

## 四、ERP / 第三方系统对接

1. 「API 对接」页面 →「创建密钥」，把生成的 **API Key** 和 **Webhook Secret** 交给对接方（两者只显示这一次，请立刻保存）
2. 对接文档：[docs/erp-api.md](docs/erp-api.md)（可直接发给对方开发人员）
3. 在线接口调试页面：http://127.0.0.1:8787/docs

关于 API Key，有三件事要知道：

- **每把 Key 都有主人**（列表里的「归属」那一列，就是创建它的那个账号）。
  **用这把 Key 提交的任务，生图费用记在主人头上。** 今天所有 Key 都归 admin，
  行为和以前一样；但如果你按 7.4 节改成了「每人一把 Key」、并且给 admin 也配了
  个人 Key，那 ERP 的费用就开始从 admin 的个人余额走。
- **停用一个成员账号不会连带停用他名下的 Key**。要断开某个对接方，
  必须在这一页把那把 Key 单独停用。
- **停用一把 Key，会让它此前发出去的所有图片链接立刻全部失效**。
  这是止血手段（Key 泄露时用），但也意味着：如果对接方突然反馈
  「所有历史图片集体打不开」，先看看是不是这把 Key 被停用了。

> ⚠️ **发给对接方的图片地址变了**：从 2026-08-10 起，图片链接后面带
> `?k=&e=&t=` 三个签名参数，默认 7 天有效，**必须整条保存**（截掉问号后面那段
> 就打不开了）。已经接入的系统请让对方看一遍 `docs/erp-api.md` 的第 6 节，
> 只有两处要改。

## 五、部署到服务器

项目已 Docker 化，**服务器上用 PostgreSQL**（本机开发仍是零安装的 SQLite）。
镜像由 GitHub Actions 自动构建并发布到 `ghcr.io`（同时提供 x86 和 ARM 版本），
部署时直接拉现成镜像，**不需要上传源码，也不需要在目标机器上编译**。

> 📘 **部署到群晖 NAS 请直接看 [docs/deploy-synology.md](docs/deploy-synology.md)**——
> 那是一份照着做就行的分步指南（含权限、备份、排错）。下面是通用说明。

在装有 Docker 的机器上建一个空文件夹，下载两个文件：

```bash
curl -fLo docker-compose.yml https://raw.githubusercontent.com/shinycheng/designkit/main/docker-compose.yml
curl -fLo .env https://raw.githubusercontent.com/shinycheng/designkit/main/example.env
```

改完 `.env`（见文件内注释，必改项只有 4 处）后：

```bash
sudo docker compose up -d
```

> **本章和第六章的命令，前面的 `sudo` 都不能省。** 你 SSH 上群晖用的是自己的普通
> 账号，而 Docker 只让 root 使唤，不加 `sudo` 会得到一句英文的
> `permission denied ... docker daemon socket`——那不是你装错了，只是少了 `sudo`。
> 敲下去如果提示输密码，输**你自己的登录密码**（屏幕上不会显示，输完直接回车）。

这一条命令会同时起两个容器：PostgreSQL 数据库 + DesignKit 应用，应用会等数据库
健康检查通过后再启动，首次会自动建表。

**必改项**：`.env` 里的 `POSTGRES_PASSWORD` 没设置容器会拒绝启动——这是故意的，
防止默认弱口令被带上生产。密码可以放心用特殊字符，应用会正确处理。

**文件权限**：`.env` 里的 `PUID`/`PGID` 填成数据目录属主的 uid/gid
（在目标机器上执行 `id` 查看）。一般情况下容器启动会自动把数据目录属主纠正过来，
不用手工 `chown`；填错了通常是你在文件管理器里打不开这些图，而不是系统不能用。

但如果你挂载的目录里还放着**别的文件**，容器出于安全考虑不会去动它——
这时启动日志里会有 `[entrypoint]` 开头的警告，按提示手工执行一次 `chown` 即可。
**建议给 DesignKit 单独建一个空目录挂载**，不要和别的东西混在一起。

**关于对外访问**：compose 默认把 8787 绑在所有网卡（`0.0.0.0`），同局域网可访问。
⚠️ **切勿**把这个端口转发到公网——当前是 HTTP 明文，登录密码会在网上裸奔。
确需公网访问请在前面加一层 Nginx/Caddy 并配 HTTPS。
只想本机访问就在 `.env` 里设 `DESIGNKIT_BIND_HOST=127.0.0.1`。

**更新版本**：`sudo docker compose pull && sudo docker compose up -d`。
升级会自动补数据库新增的列；灵感库的分类标签也会用本地缓存自动回填（约 1 秒、不联网），
不需要你手动做什么。

> ⚠️ **升级前必做两件事**，顺序不能反：
> 1. **先备份**（数据库 + `data` 目录，见「六、数据在哪里 / 怎么备份」）
> 2. **再钉版本**——把 `.env` 里的 `DESIGNKIT_VERSION` 从 `latest` 改成当前正在跑的
>    那个标签并抄下来，见「升级前先钉版本」。
>
> 不钉版本的话，新版出问题时你连「该退回哪一版」都说不清楚；而升级之后表结构变了，
> 旧备份要按「怎么恢复」里的步骤（先清空数据库再灌）才能往回灌。
> 这两件事一起做才有意义。

**部署后必做**：在「系统设置」→「对外访问地址」填实际访问地址（如 `https://你的域名`），
否则生成图片的链接和回调里还是本机地址，外部系统打不开。
（保存后回填的值可能和你输入的不完全一样——系统会自动去掉末尾的斜杠，这是正常的。）

**关于「系统设置 → 图片访问与多用户」这一节**（部署后通常不用动，但要知道它在）：

| 设置项 | 默认 | 说明 |
|---|---|---|
| 生图费用怎么算 | 共用一把 Key | 改成「每人一把」的完整步骤见第七章 7.4 |
| 图片链接需要凭证才能打开 | **开启** | 关掉之后任何人知道地址就能打开平台上任何一张图。只用于临时兼容对接方手里的老链接 |
| 网页取图凭证有效期 | 7 天 | 范围 7–30 天。到期重新登录一次即可，一般察觉不到 |
| 对接方图片链接有效期 | 168 小时（7 天） | 范围 1–8760 小时 |
| 允许跨站调用的地址 | `*`（不限制） | **改完必须重启服务才生效**（`sudo docker compose up -d`）。页面提示保存成功也不会立刻起作用，这是正常的，不要反复保存 |

同一节里还有一个「无凭证访问统计」，显示本次启动以来有多少次没带凭证的取图请求。
它是判断「敢不敢临时关掉图片凭证限制」的唯一客观依据（服务重启后归零）。

### 把本机数据搬到服务器（可选，想保留本机的提示词库和记录时才做）

**顺序很重要**，请照这个来：

```bash
# 1) 在本机看看会搬多少（不写入任何东西，也不需要连上服务器）
.venv/bin/python -m backend.migrate_sqlite_to_pg --dry-run

# 2) 在服务器上起好数据库（此时先不要启动应用，避免它先写入数据）
sudo docker compose up -d db

# 3) 把本机的 data/ 整个传到服务器（图片和 SQLite 库文件都在里面）
#    ⚠️ 拷之前先在本机终端按 Ctrl+C 停掉 DesignKit——数据库开着 WAL 模式，
#    服务还在跑时拷到的库文件可能不完整，迁过去会少数据甚至打不开。
rsync -av data/ 用户@服务器IP:/volume1/docker/designkit/data/

# 4) 在服务器上，用应用容器自己跑迁移。
#    数据库端口没有对外开放，但应用容器本来就在同一个网络里，直接连得到；
#    目标库连接串由容器的配置自动组装，密码里有 @ % 等字符也不会出错。
sudo docker compose run --rm designkit \
    python -m backend.migrate_sqlite_to_pg --source "sqlite:////app/data/designkit.db"

# 5) 最后再启动应用
sudo docker compose up -d
```

脚本会按外键顺序搬、分批提交（带稳定排序，不会漏行），并自动把 PostgreSQL 的自增
序列推到当前最大 id——不做这步，迁完新建记录会主键冲突。

- **目标库已有数据时会直接中止**，避免误覆盖。如果是上一次迁移中途失败留下的半个库，
  确认可以清空后加 `--truncate` 重跑（该参数会**删光目标库里这些表的全部数据**，慎用）
- 迁移完成后，记得到「系统设置 → 对外访问地址」填服务器地址（迁移会把这项也一起搬过去，
  所以要在迁移**之后**改）

## 六、数据在哪里 / 怎么备份

数据分**四**部分，**四部分都要备份，缺一不可**：

| 内容 | 本机（SQLite） | 服务器（Docker + PostgreSQL） |
|---|---|---|
| 数据库（模板、任务、设置、成员账号） | `data/designkit.db` | **PostgreSQL 容器**（在 `pgdata` 数据卷里，**不在** `data/`） |
| 图片（上传图、生成图） | `data/` 下的子目录 | `data/` 下的子目录 |
| **登录密钥 `.secret_key`** | `data/.secret_key` | `data/.secret_key` |
| **凭据加密钥匙 `.enc_key`** | `data/.enc_key` | `data/.enc_key` |

> ⚠️ 服务器部署下只拷 `data/` **不会**备份到数据库——数据库在 Docker 数据卷里。

> ⚠️ **两个隐藏文件是最容易漏、后果又最难查的**。它们的名字以 `.` 开头，
> File Station 和 `ls` 默认都看不见，但少了任何一个，恢复出来的系统都是坏的：
>
> | 文件 | 丢了会怎样 |
> |---|---|
> | `data/.secret_key` | 所有人被踢下线要重新登录；**已经发给 ERP 对接方的 Webhook Secret 全部失效**，对方那边一路验签失败，且不会有任何报错提示你原因 |
> | `data/.enc_key` | **全体成员的个人网关 Key 全部解不开**。表现是「所有人突然都不能生图」，而数据库看起来完好无损、界面上那些人还明明白白写着「已配置 Key」。只能到网关后台把每个人的 Key 重新抄一遍、在「成员账号」页逐个重填 |
>
> 好消息是下面的命令本来就会把这两个都带上——前提是你备份的是**整个 `data` 目录**，
> 而不是只挑里面的图片文件夹。备完请按下面的「检查」那步确认一遍。

> **`user_gateway_accounts` 这张表也丢不起**：它存着每个成员的网关 Key（密文）。
> 它在**数据库**里，不在 `data/` 目录里——所以「只拷 data 目录」和
> 「只备数据库」两种做法，各自都会让成员的 Key 变成一堆废数据。必须两样都备。

> 如果你在 `.env` 里显式设置了 `DESIGNKIT_SECRET_KEY` 或 `DESIGNKIT_ENCRYPTION_KEY`，
> 那么系统用的是这两个值，`data/.secret_key` / `data/.enc_key` 不再起作用——
> 这种情况下要备份的是 `.env` 文件。默认两个都没设置。

### 本机（SQLite）

```bash
# 先停止服务（Ctrl+C），再整个 data/ 目录拷走
cp -r data ~/designkit-backup-$(date +%Y%m%d)
```

数据库开了 WAL 模式，运行中只拷 `designkit.db` 会丢数据，必须停服后整目录一起拷，
或用 `sqlite3 data/designkit.db ".backup 'backup.db'"` 在线备份。

`cp -r data ...` 会连隐藏的 `.secret_key` 和 `.enc_key` 一起拷走，所以务必拷**整个目录**，
不要只挑 `designkit.db` 和图片文件夹。拷完检查一下这两个文件在不在：

```bash
ls -a ~/designkit-backup-$(date +%Y%m%d) | grep -E '^\.(secret|enc)_key$'
# 应该打印出两行：.enc_key 和 .secret_key。少一行就是没备全
```

### 服务器（PostgreSQL）

> 下面这些命令都在群晖上用 SSH 执行，**前面的 `sudo` 不能省**（Docker 只让 root
> 使唤）。提示输密码时，输你自己的登录密码。

```bash
cd /volume1/docker/designkit

# 1) 备份数据库（不用停服）
#    --clean --if-exists 一定要带：它让导出的 SQL 里自带「先删掉旧表」的语句。
#    不带的话，这份备份只能灌进一个空库，往有数据的库里灌会全程报「表已存在」。
sudo docker compose exec -T db pg_dump --clean --if-exists -U designkit designkit | gzip > db-$(date +%Y%m%d).sql.gz

# 2) 备份图片和两把钥匙（整个 data 目录，隐藏文件也在里面）
tar czf images-$(date +%Y%m%d).tar.gz -C /volume1/docker/designkit data

# 3) 检查备份是不是真的备到了东西 —— 这步别省
#    第一条应该打印一个大于 0 的数字（表的数量）
#    第二条必须打印出两行：data/.enc_key 和 data/.secret_key。只有一行就是没备全
gunzip -c db-$(date +%Y%m%d).sql.gz | grep -c 'CREATE TABLE'
tar tzf images-$(date +%Y%m%d).tar.gz | grep -E 'data/\.(secret|enc)_key$'
```

> 第 3 步为什么必须做：`pg_dump | gzip > 文件` 这种写法，万一数据库容器没起来，
> pg_dump 失败了，`gzip` 照样会给你生成一个**看起来正常、其实是空的** `.gz` 文件，
> 整条命令还返回「成功」。等到真要恢复的那天才发现备份是空的就来不及了。

### 怎么恢复

**先分清你要的是哪一种回退**，这一步决定了后面完全不同的两条路：

| 你的处境 | 该走哪条路 |
|---|---|
| 升级后新版本有毛病，但**数据本身是好的**（绝大多数情况都是这种） | **只把镜像钉回旧版本，数据库原样不动**——见下一节「升级前先钉版本」。这条路经过实测：旧版程序跑在升级过的库上一切正常，不用碰备份，也不会丢任何记录，是风险最小的一条 |
| **数据也要退回**到备份那天（误删了东西、数据被写坏了） | 才走下面这套「灌回备份」 |

> ⚠️ 「灌回备份」会把**备份那天之后产生的全部记录抹掉**（新建的账号、新生成的图、
> 改过的设置）。别把它当成「重启一下试试」来用，先试上面那条钉版本的路。

**恢复前先看一眼「升级前先钉版本」那段**：如果这份备份是升级之前导出的，
要先把版本改回当时那个，再恢复——新版本的表结构和旧备份对不上。

动手前先确认三件事：

- **备份文件在哪**：每日定时任务存到 `/volume1/docker/designkit-backup`，
  手工按上面那节备的则在 `/volume1/docker/designkit`。下面的命令按定时任务那个目录写，
  如果你恢复的是手工备的那份，把 `-backup` 去掉即可。
- **哪一天的**：把命令里的 `20260810` 全部换成你要恢复的日期。
- **这份备份不是空的**：先用上一节「检查备份是不是真的备到了东西」那两条命令验一遍
  （`grep -c 'CREATE TABLE'` 要打印出一个大于 0 的数字）。
  ⚠️ 下面第 2 步会**把数据库清成一张白纸**，清完了才发现备份是空的就没有退路了。

```bash
cd /volume1/docker/designkit

# 1) 先停应用。它一直占着数据库连接，不停的话第 2 步会卡住
sudo docker compose stop designkit

# 2) 把数据库清空。**这一步不能省**，原因见下面那段说明
sudo docker compose exec -T db psql -v ON_ERROR_STOP=1 -U designkit -d designkit \
  -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public;'

# 3) 灌回数据库
#    -v ON_ERROR_STOP=1 一定要带：出错就立刻停下并返回失败。
#    不带的话 psql 会「一路报错一路继续往下跑」，最后给你一个新旧混杂的库，
#    退出码还是 0，在群晖任务计划里显示成「执行成功」——这是最坏的情况。
gunzip -c /volume1/docker/designkit-backup/db-20260810.sql.gz \
  | sudo docker compose exec -T db psql -v ON_ERROR_STOP=1 -U designkit -d designkit

# 4) 恢复图片和两把钥匙（会覆盖 data 目录里的同名文件）
tar xzf /volume1/docker/designkit-backup/images-20260810.tar.gz -C /volume1/docker/designkit

# 5) 把应用起回来
sudo docker compose start designkit
```

> **第 2 步（清空数据库）为什么不能省**：升级会往数据库里**加新表**。旧备份是升级
> 之前导出的，里面根本不认识这些新表，所以它自带的「先删旧表」语句会被新表挡住，
> 灌到一半就停下来报一句纯英文的
> `cannot drop constraint users_pkey on table public.users because other objects depend on it`。
> 更糟的是**它是灌了一半才停的**：停下来之前已经把库里所有的外键和
> 「用户名不许重复」「API Key 不许重复」这些约束删光了，而系统还能照常启动、
> 页面一切正常——坏了但看不出来。先清空再灌就不会有这个问题，
> 清空之后旧备份是灌进一个空库，和它当初被导出时的情形完全一样。

恢复完打开网页，如果提示你重新登录，属于正常现象——第 4 步换回了旧的 `.secret_key`，
之前那把钥匙签发的登录状态就失效了。密码还是备份那天的密码。

> ⚠️ **第 3 步和第 4 步必须一起做，不能只做一个。** 数据库里存着每个成员的
> 网关 Key（密文），而解开它的钥匙是 `data/.enc_key`。只灌数据库不恢复
> `.enc_key`，或者反过来，结果都是「全体成员突然都不能生图」，
> 而界面上他们还写着「已配置 Key」——这种故障从现象上完全看不出根因。
> 万一真的只剩数据库、`.enc_key` 找不回来了，唯一的办法是到网关后台
> 把每个人的 Key 重新抄一遍，在「成员账号」页逐个重新填一次。

**万一第 3 步还是中途停下并报错**（屏幕上出现 `ERROR:` 开头的英文）：

1. **不要反复重试**，重试的结果一模一样。
2. 此时数据库是空的、应用还停着，**先别急**——这不是不可挽回的状态。
3. 先确认第 2 步真的执行成功了（它应该打印 `DROP SCHEMA` 和 `CREATE SCHEMA` 两行）。
   如果第 2 步被跳过或报错了，把它补做一次，再重来第 3 步。
4. 第 2 步没问题却还是报错，那多半是**这份备份文件本身坏了**（比如当初 pg_dump
   就失败了，只留下一个空的 `.gz`）。换一天的备份文件再试。
5. 手上没有能用的备份时，走这条保底路线：把 `.env` 里的 `DESIGNKIT_VERSION`
   改回纸上抄的旧版本，执行 `sudo docker compose up -d`，让系统用**当前这个空库**
   重新建表启动——数据回不来了，但系统能重新用起来，账号需要重新建。

### 升级前先钉版本（每次升级前都做，30 秒）

`docker-compose.yml` 里镜像版本默认是 `latest`，也就是「永远跟最新」。
一旦新版本出问题要往回退，你会发现说不清楚「原来跑的是哪个版本」——
`latest` 今天指向的东西和昨天不是一回事。所以升级前先把当前版本记下来并钉住：

1. 查出当前正在跑的是哪个版本，打印出来的是 7 位字符，例如 `6ca035d`：

```bash
cd /volume1/docker/designkit
sudo docker inspect --format '{{index .Config.Labels "org.opencontainers.image.revision"}}' designkit | cut -c1-7
```

2. **把这 7 位字符抄在纸上**（或记事本里），前面加 `sha-`，例如 `sha-6ca035d`
3. 编辑 `.env`，把 `DESIGNKIT_VERSION=latest` 改成 `DESIGNKIT_VERSION=sha-6ca035d`
4. 执行 `sudo docker compose up -d` 确认这个版本能正常起来（这一步不会换版本，
   只是把「跟随最新」换成「钉死在你现在跑的这一版」）
5. 之后要升级，就把 `.env` 里的版本改成新的标签（或改回 `latest`），再 `up -d`。
   出问题就把 `.env` 改回纸上抄的那个 `sha-xxxxxxx`，`up -d` 即可退回去

> 每次推送代码，GitHub 都会自动为该次提交打一个 `sha-` 开头的镜像标签，所以任何一版
> 都能这样退回去。如果第 1 步打印出来是空的（早期镜像没带这个标记），
> 就去 GitHub 仓库页面 → 右侧 **Packages** → `designkit`，在标签列表里挑日期对得上的
> `sha-xxxxxxx`。

- 建议把备份加到服务器的每日定时任务里（群晖的做法见
  [docs/deploy-synology.md](docs/deploy-synology.md) 第 6 步）
- `data/` 必须放在**本地磁盘**，不要放网络盘/云同步盘

## 七、给同事开账号（成员账号）

系统里有两种角色：

| 角色 | 能看到什么 | 能做什么 |
|---|---|---|
| **管理员**（admin） | 全部 8 个页面 | 建成员账号、改系统设置、管 API Key、看所有人的生成记录 |
| **成员**（member） | 生成、记录、模板、灵感、我的 —— 五项 | 只能看到**自己**上传的图和自己的生成记录 |

> ⚠️ **角色是建号时选的，建完就改不了**——系统没有「把管理员降回成员」这个功能，
> 也没有「删除账号」（原因见 7.1 末尾）。也就是说选错一次，就会永久多出一个
> 能改系统设置、能看所有人记录的管理员，只能把这个账号「停用」了事。
> 建号时那个「角色」下拉**保持默认的『成员』**就对了，别顺手改。

成员之间是互相看不见的：别人的图片链接、别人的任务详情，一律显示「不存在」。
管理员能看到所有人的图（要帮人排障），但**不能替别人点「重新生成」或「补图」**——
那会花那个人的钱。

### 7.1 建一个成员账号

1. 管理员登录 → 左侧导航「成员」→ 标题右边的「新建成员」按钮
2. 弹窗里从上到下有**四项**：
   - **用户名**：登录时输入的名字，只能用字母、数字和 `.` `_` `-`，长度 3~32 位
     （例如 `zhangsan` 或 `li.si`）。**建号之后改不了**，想改只能重新建一个
   - **显示名**：界面上显示的名字，可以写中文，随便填。留空就显示用户名
   - **角色**：一个下拉框，默认已经选好「成员（只能看到自己的图和任务）」，
     **保持默认不动就对了**。只有当你确实需要「第二个人也能改系统设置、看所有人的
     记录、管所有人的 Key」时，才改成「管理员」。
     ⚠️ **建完之后角色改不了，账号也删不掉**——选错只能把这个账号停用，
     系统里就会永久留着一个多余的管理员
   - **初始密码**：至少 8 位，你自己定
3. 点「创建账号」后会弹一个窗口显示这个初始密码，并有「复制密码」按钮。
   **把它当面告诉本人**——这个密码不会再显示第二次
4. 本人第一次登录会被强制要求改掉这个密码，不改就什么都用不了

> **没有「删除成员」这个功能**，这是故意的：人删了，他名下的生成记录和商品图
> 就变成没人认领的孤儿数据，谁也说不清那些图是谁的、当时花了谁的钱。
> 人走了就用「停用」，记录原样保留，随时可以再启用回来。

### 7.2 停用一个成员（离职、账号可能泄露）

在「成员」页那一行点「停用」，会弹出二次确认。确认之后**立刻**生效：

- 他当前的登录状态作废，下一次点任何东西都会被踢回登录页
- **他手上的图片链接立刻打不开**（包括已经发给别人的）
- 他没法再用原来的密码登录

他名下的商品图和生成记录**原样保留**，随时点「启用」就能恢复。

> ⚠️ 停用成员账号**不会**连带停用他名下的 API Key。ERP 那头照常调得通。
> 要断开对接，得到「API 对接」页把那把 Key 单独停用。

### 7.3 他忘了密码怎么办

在「成员」页那一行点「重置密码」，由**你**输入一个新的初始密码（至少 8 位），
然后当面告诉他。他登录后会被再次要求马上改掉。

重置之后他在所有设备上的登录立刻失效。系统不提供「找回密码」邮件——
内部使用，当面给最省事也最安全。

### 7.4 让每个人花自己的钱（每人一把 Key）

默认情况下，全公司共用「系统设置 → 生图服务」里那**一把全局 Key**，
所有人的生图费用记在一起，账单上分不出是谁用的。

想让每个人各花各的：

**第一步**：给每个成员配一把他自己的网关 Key。
「成员」页那一行 →「配置生图 Key」→ 把网关那边给这个人开的 Key 整串粘进去 → 保存。
保存后可以点「测试连接」验证（只查一次模型列表，**不出图、不花钱**）。

**第二步**：「系统设置 → 图片访问与多用户 →「生图费用怎么算」改成
**「每人一把 Key（各花各的）」** → 保存。

> ⚠️ **两步都做完才生效**。只做第一步的话，界面提示「已保存」，
> 但费用照旧记在全局 Key 上；只做第二步的话，没配 Key 的成员一点生成就被拦住。
> 顺序建议：先给所有人配好 Key，最后再改这个开关。

改成「每人一把」之后：

- 成员点生成时用的是**他自己那把 Key**，费用从他自己的网关余额走
- **没配 Key 的成员会被直接拦住**，任务显示失败，原因写着
  「你的账号还没有开通生图额度，请联系管理员在『成员账号』页配置」。
  这种失败**重试多少次都一样**，别让他反复点重试，去把 Key 配上就好
- **管理员自己**如果没配个人 Key，仍然用全局那把（全局 Key 本来就是管理员配的）
- **ERP 对外接口**用的是「这把 API Key 的主人」那把 Key。今天所有 API Key
  都归 admin，所以行为和以前一样；哪天 admin 给自己配了个人 Key，
  ERP 的费用就开始从 admin 的个人余额走——这是预期行为，不是 bug
- **模拟生图模式（mock）不受影响**：没配 Key 也照样能出占位图，
  所以新部署时先用 mock 跑通流程这条路没被堵掉

> 🔒 **Key 在界面上永远看不到**，连末 4 位都不显示——已经配过的成员，
> 输入框里是 8 个星号占位符。想改就把新的整串重新粘一遍；
> 不动它直接保存，系统会认为「没改」，提示语是「没有填写新的 Key，原有配置保持不变」
> 而不是「保存成功」。
>
> Key 在数据库里是加密存放的，钥匙是 `data/.enc_key` 这个文件。
> **备份时千万别漏了它**，见上面「六、数据在哪里 / 怎么备份」。

### 7.5 成员自己能看到什么

成员登录后，左侧导航最下面的「我的」（我的账户）页里有：

- 自己的显示名 / 用户名 / 角色
- **「我的生图额度」**：只有「可用 / 不可用」两种显示。不可用时会直接写清原因
  （通常就是「让管理员去『成员账号』页给你配 Key」）
- 自测两个模型的连接（不出图、不花钱）
- 修改自己的密码

**这一页没有任何 API Key 输入框**——成员不能自己填 Key，也看不到自己那把 Key
长什么样。这是有意的：Key 由管理员统一从网关后台开、统一配置，
免得出现「我自己填了一个，怎么还是不能用」这种谁也说不清的状态。

## 八、技术说明（给开发者）

- 后端：Python 3.9+ / FastAPI / SQLAlchemy 2.0；数据库本机 SQLite（WAL）、服务器 PostgreSQL，
  切换只改 `DESIGNKIT_DATABASE_URL`（或分开传 `DESIGNKIT_DB_*`）；搜索统一用 SQLAlchemy 的
  `icontains`（在 PostgreSQL 上编译成 ILIKE，在 SQLite 上编译成大小写不敏感的 LIKE），
  保证两边行为一致
- 生成任务：数据库任务队列 + 线程池 worker，失败自动重试。
  服务重启时会把上次中断的任务捞回队列，但只捞已经开始超过 75 分钟的——
  如果恰好在某个任务刚开始时重启，它会卡在「生成中」，既不能重试也删不掉，
  要等一个多小时后再重启一次服务才会被自动恢复
- 生图：OpenAI 兼容 Images API（`/v1/images/edits` 图生图、`/v1/images/generations` 文生图），
  base_url / key / model 均可配置；中转网关拒绝单请求多图时，会自动拆分为
  多次单图请求并聚合结果；另有 mock 模式
- 前端：无构建纯 JS SPA（`frontend/`），零 Node 依赖，由后端直接托管
- 对外 API：`/api/v1/*`，X-API-Key 鉴权，异步任务 + HMAC-SHA256 签名回调；
  另有 `GET /api/v1/generations/{job_id}/images/{index}` 凭 Key 直接取图（不过期）
- 图片访问：`/files/<相对路径>` 是**带鉴权的路由**（`backend/app/routers/files.py`），
  不是静态目录。网页端靠登录时下发的 httpOnly Cookie `dk_files`（`path=/files`）取图，
  对外 API 靠 `?k=&e=&t=` 签名；两者都验归属，越权一律 404、无凭证 403。
  改密码 / 停用账号 / 退出登录都会让已发出的凭证立刻失效
- 多用户：`users` + `user_gateway_accounts` 两张表。成员的网关 Key 用 AES-256-GCM
  加密存库，钥匙是独立的 `data/.enc_key`（与 `.secret_key` 刻意分开：后者随时可换，
  前者一换就等于所有凭据永久作废）。「谁的任务花谁的 Key」只在
  `settings_service.resolve_for_user()` 一处决定，且找不到 Key 时**绝不回落全局 Key**
- 网页接口：`/api/web/users`（管理员，7 条）、`/api/web/account`（用户侧）、
  `/api/web/auth/{login,me,change_password,set_password,logout}`
- 目录结构：`backend/app/`（routers 路由 / services 业务 / models 模型），`frontend/`（页面：
  `css/` 分层样式、`js/core/` 应用外壳与轮询、`js/views/` 各页面），`tests/`（回归测试），
  `docs/`（文档），`data/`（运行数据，勿提交）
