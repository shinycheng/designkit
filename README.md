# DesignKit · AI 商品图生成平台

上传商品图，选一个提示词分类（或用自由模式自己描述画面），AI 自动生成
电商商品图/场景图/营销套图。
支持接入 ChatGPT 生图 API（含国内中转平台），并提供标准对外 API 供 ERP 等系统对接。

账号一共有**三种**开法（管理员逐个建 / 邀请码自助注册 / 手机号短信验证码自助注册），
下面这张表先分清楚，再去看对应的章节。

---

## 先分清三种「开号」方式（很容易混）

这三个名字长得像，而且系统设置里还有一个**名字更像、但根本不是开号方式**的
「网关自动开通」。混过一次的人不止一个，所以这张表放在最前面：

| 叫什么 | 谁动手 | 对方要有什么 | 默认 | 在哪开 | 看哪一章 |
|---|---|---|---|---|---|
| **管理员建号** | **你**，一个一个建 | 什么都不用，你把初始密码当面给他 | 一直可用 | 「成员账号」页 →「新建成员」 | [第七章](#七给同事开账号成员账号) |
| **邀请码自助注册** | **他自己**注册 | 你发给他的一串邀请码 | **关闭** | 系统设置 →「自助注册（邀请码）」 | [第八章](#八让别人自己注册邀请码) |
| **手机号自助注册** | **他自己**注册 | 一个能收短信的手机号（可以再要求填邀请码） | **关闭** | 系统设置 →「短信服务（手机号注册）」 | [第九章](#九让别人用手机号自己注册短信验证码) |

> 🚫 **「网关自动开通」不是第四种开号方式，它和「谁能进来」毫无关系。**
> 它管的是**账号已经建好之后**的事：系统替这个人跑到生图网关那边开一个账号、
> 领一把只属于他的 Key，好让他能生图。上面三种方式建出来的号都会走它。
> 换句话说：前三种决定「他能不能登进来」，「网关自动开通」决定「他登进来之后
> 能不能出图」。**打开它不会让任何陌生人多一条注册的路。**
> 详见 [7.6](#76-让系统自动去网关开号领-key可选) 和 [docs/auto-provision.md](docs/auto-provision.md)。

两条自助注册的路是**并列**的，互不影响：可以只开一条，也可以两条都开，
也可以两条都关（默认就是两条都关，此时登录页上连「去注册」的入口都不会出现）。
两条共用同一套**硬前置条件**和同一份全站每日名额，见 [8.1](#81-打开之前必须满足的三条硬前提)。

## 一、怎么启动（Mac 本机）

打开「终端」，进入本项目文件夹，运行：

```bash
./start.sh
```

首次运行会自动安装依赖（约 1-2 分钟）。看到启动提示后，用浏览器打开：

**http://127.0.0.1:8787**

- 初始账号：`admin`　初始密码：`admin123456`（登录页上也印着这一行，第一次部署不会找不到入口）
- **首次登录时网页会要求你设置新密码**，设置完才进入工作台
  （这个窗口关不掉——按 Esc、点窗口外面都没用；不想现在设就点窗口底部那个「退出登录」，
  它在黑色的「设置新密码并进入」按钮左边）
  这不只是个提示：**不改掉初始密码，任何功能都用不了**，点什么都会提示
  「请先修改初始密码，再使用其他功能」
- 以后想再改密码：左侧导航最下面那个「我的」（页面标题是「我的账户」）→「修改密码」
  （管理员在「系统设置」页底部也有一个，两个是同一件事；手机上导航在屏幕底部）
- 给同事开账号：见下面「七、给同事开账号（成员账号）」；
  想发邀请码让对方自己注册，见「八、让别人自己注册（邀请码）」
- 停止服务：在终端里按 `Ctrl + C`

## 二、怎么接入真实的生图 API

本机用 `./start.sh` 启动时默认是「模拟生图」模式：生成的是占位图，**不花钱**，
用来先把流程跑通。

> ⚠️ **服务器/NAS 部署不一样**：部署用的 `example.env` 模板里已经写成了真实生图模式
> （`DESIGNKIT_PROVIDER=openai`），但 Key 是空的。所以部署完第一次点生成会直接报
> 「尚未配置生图 API Key」，而不是出占位图。按下面第 1-3 步把 Key 填上即可。
> 想先零成本跑通流程，就把 `.env` 里的 `DESIGNKIT_PROVIDER` 改成 `mock`。

拿到网关/中转平台的 API Key 后：

1. 登录后进入「系统设置」→「生图服务」
2. 服务模式选择「OpenAI 兼容接口」
3. 填写三项（**改完必须先点「保存此区域」**，再点「测试已保存的连接」——
   没保存就点测试，只会提示「请先保存当前更改」）：
   - **API 地址**：网关地址（例如自建网关 `http://192.168.31.235:8090/v1`，末尾带不带 `/v1` 都可以）
   - **API Key**：平台给你的密钥（一般 `sk-` 开头）
   - **生图模型**：默认 `gpt-image-2`（自建网关），其他平台按其文档填
5. 看到连接成功的提示后，「生成工作台」出的就是真实 AI 图了

> 生图费用由网关按张收取，与本系统无关。「测试连接」不产生生图费用。

> **这里填的是「全局 Key」**：默认情况下全公司共用它，所有人的生图费用记在一起。
> 想让每个成员各花各的钱（各自一把 Key、账单分得清），见
> 「七、给同事开账号（成员账号）」的 7.4 节。ERP 对外接口用的也是这把全局 Key。

**商品图会自动预处理**（建议保持开启）：发送前按所选比例补边（不裁产品）；
iPhone/Mac 的 HEIC 照片自动转码；手机竖拍照片按方向摆正。
输入图的透明通道怎么处理，取决于下面「出图底色」这个设置——
默认合成白底（避免变黑块），选了透明底则原样保留。

> **关于出图比例**（实测 2026-08-09，自建 Sub2API 网关 + gpt-image-2）：
> 该网关**忽略 size 参数**。出图比例由两件事决定，优先级从高到低：
> 1. **提示词里的构图措辞**——写 "tall/upright/bursting upward" 就出竖图，压过一切。
>    系统现在会自动把目标画幅（如 "The final image must be a square 1:1 image."）
>    写进提示词，并要求 AI 按该画幅构图，这是最可靠的控制手段。
> 2. **输入图比例**——所以「按比例预处理」开关要保持开启（把商品图补边到目标比例）。
>
> 两道保险都已默认启用。
>
> **出图要等多久**：单张约 1~5 分钟，参考图越多越慢（系统最多等 6 分钟才判超时）。
> 开启「AI 现场写提示词」再多花约 30 秒。网关空闲时可能快到 20 秒，
> 但等上几分钟是正常的，不是卡死。

## 二点二、出图比例：覆盖常用电商版位

尺寸下拉里现在有 8 个比例，都是按各平台版位选的：

| 比例 | 尺寸 | 拿来干嘛 |
|---|---|---|
| 1:1 | 1024×1024 | 淘宝/京东主图 |
| 3:4 | 1024×1360 | 详情页、小红书 |
| 4:5 | 1024×1280 | 社媒信息流 |
| 2:3 | 1024×1536 | 长图详情 |
| 9:16 | 1024×1824 | 抖音/快手封面 |
| 3:2 | 1536×1024 | 场景与横幅 |
| 4:3 | 1360×1024 | PC 端 banner |
| 16:9 | 1824×1024 | 视频封面 |

比例不是写死的清单，而是一套**护栏规则**（边长必须是 16 的倍数、最长边不超 2048、
长短比不超过 3:1）。以后要加新版位，只要在 `backend/app/services/sizing.py`
的预设表里加一行，网页端会自动跟着变——不用改五个地方。

## 二点三、透明底出图（免抠图，可选）

「系统设置 → 生图服务 → 出图底色」选**透明底 PNG**后，出图直接带透明通道：
同一张商品图可以随便叠任何背景，不用再一张张抠图。

选了之后系统会同时做三件事，否则参数发了也没用：模板里的「纯白背景」措辞会被
自动改写成「透明背景」；商品图预处理不再合成白底、补边也补透明；缩略图仍会
垫一层白（不然列表里透明区是黑块）。

> ⚠️ **你当前的网关不支持这个功能**。2026-08-09 实测自建 Sub2API 网关 + `gpt-image-2`，
> 返回 `Transparent background is not supported for this model.`，
> 系统会明确提示你改回「跟随模型」，不会白花生图的钱（只花了一次写提示词的文本开销）。
>
> 这个开关先留着——换成支持透明底的模型（如 OpenAI 官方 `gpt-image-1`）即可用。
> 换网关后第一次用请先出 1 张确认：多数网关不支持时会直接报错，但也有网关会
> **静默忽略**该参数、照常出实底图。

## 二点四、生成方式：选分类，不选模板

生成页的「生成方式」直接用提示词库的分类（电商主图、产品营销、社交媒体帖子…）。
你**不需要挑某一条具体提示词**，选个分类就行，剩下的交给 AI：

1. **通览**：把该分类下提示词的标题一次性给 `gpt-5.6-sol` 看，连同你的商品图。
   电商主图 420 条全部参与；超过 700 条的大分类（产品营销 4063 条、社交媒体
   5527 条）先按「像不像商品摄影」预筛，再随机抽 700 条——每次任务抽的都不一样，
   所以新同步进来的提示词能选上，不同商品也不会总撞同一批参考
2. **挑选**：它选出风格最搭这件商品的 4 条，返回编号
3. **精读**：系统取回这 4 条的**完整**提示词
4. **改写**：结合完整提示词 + 你的商品图 + 你填的「补充要求」+ 目标画幅，
   现场写出一条只属于这件商品的提示词，再交给生图模型

实测（可乐罐 + 电商主图分类）挑出来的是
「Hyper-Realistic Commercial Soda Can Advertisement」「Ice-Cold Cola Splash Ad」
「Splash Hero Beverage Photography」「Luxury Sparkling Water Can Ad」——
四条全是易拉罐/饮料广告，最终提示词写出了冷凝水珠、罐底冰爽水花、湿润反光台面。

**为什么不直接把库里的提示词发给生图模型**：库里 91% 的提示词把别人的商品写死在
里面了（"a bottle of oolong tea..."）。直接用会画出别人的商品——上传吹风机出来茶叶
就是这么来的。所以它们只作**风格参考**，永远不原样发出。

- 两次文本调用合计约 16 秒（出图本身 1-5 分钟，可忽略）
- 「自由模式」不参考提示词库，完全按你写的描述出图
- 在「生成记录」的详情里能看到 AI 实际发出的提示词

实测效果：上传吹风机 + 选「纯白背景商品图」+ 补充「突出金色点缀、背景略带暖调」，
AI 写出的提示词准确描述了 *"champagne-silver metallic body, glossy black accents,
refined gold trim, TIARALEEN REPRONIZER 107D Plus branding"*，出图的金色点缀明显强化。

- 文本模型调用失败时自动回退，不会挡住出图（画质会差一点）
- 可在「系统设置 → 生图服务」更换文本模型（需支持看图）
- ⚠️ 关掉「AI 现场写提示词」会让「按分类生成」失去意义——那时系统没有东西可写，
  只会用一句通用描述出图。想关就改用自由模式自己写。

## 二点五、灵感库：1.4 万条现成提示词

左侧导航「灵感库」内置了 YouMind 开源提示词库（CC BY 4.0，上游每日更新）：

- 管理员点「同步上游」即可拉取/更新全部约 1.4 万条提示词（约 1-2 分钟，同步中不要重复点）
- 支持关键词搜索（英文命中率更高）和 11 个分类筛选
- 看中某一条想单独用：点开详情 →「用它生成」带到生成工作台（走自由模式，原文照发）
- **平时不用来这里翻**：生成页选个分类，AI 会自己在这个库里挑，见「二点四」

> **一条提示词常同时属于多个分类**，按分类筛选时以它的全部标签为准。
> （早期只认第一个标签，导致「电商主图」416 条里有 398 条被前面的分类抢走、
> 只剩 18 条，按分类几乎什么都找不到——已修好。）

**自动更新**：上游每天更新两次，系统默认每 12 小时自动同步一次，无需手动点。
可在「系统设置 → 运行参数」调整间隔或关闭。多进程/多容器部署时靠数据库锁保证
只有一个进程真正同步；连续失败会自动退避（15 分钟 → 1 小时 → 6 小时），不会反复冲击上游。

> **同步需要访问 GitHub**（raw.githubusercontent.com）。部分地区直连不通，
> 这时到「系统设置 → 运行参数 → 同步代理」填一个代理地址（如 `http://127.0.0.1:7890`），
> 保存后点「测试同步连接」——它只拉一个很小的文件，几秒就知道通不通，
> 不用等两分钟的完整同步。
>
> 代理**只作用于灵感库同步**：生图网关是局域网地址，永远直连、不走代理。

## 二点六、出图之后能做什么

结果区除了「下载」，还有三个按钮：

- **用这张继续改** —— 把这张结果图放回商品图位置，作为下一轮的参考。
  电商修图的常态是「在满意的那版上微调背景/角度」，而不是拿原图重赌一次；
  这样上一版的构图和光影会被保留下来，废图率明显更低。
  「生成记录」页的详情里也有同样的「继续改」按钮，可以翻出几天前的图接着改。
- **导出平台尺寸** —— 在你自己电脑上把图裁成淘宝 800×800、小红书 1080×1440、
  抖音 1080×1920 等常用版位。**完全本地处理，不调用生图接口、不花钱**。
  可选「裁切填满」（适合主图）或「补白边」（怕裁到商品时用）。
- **再补 N 张** —— 只补缺的那几张，不把已经出好的重跑一遍。
  以前 4 张里坏 1 张只能整单重来，等于为 1 张图付 4 张的钱。
  补图会沿用上一批实际发出的提示词，所以补出来的图和原来是同一套设定。

## 三、怎么导入你自己的提示词库

进入「提示词模板」→ 右上角「导入」，上传 JSON 文件即可，同名模板会自动覆盖更新。

**不用记字段格式**：先在同一个页面点右上角的「导出」下载一份现有模板当样板
（导出的就是 JSON 文件），照着它改就行——导入格式和导出格式完全一致。字段是：
`name`、`category_id`、`description`、`prompt_template`、`variables`、
`default_params`、`requires_input_image`、`is_enabled`、`sort`。

也可以直接把你的提示词库文件连同导出的样板一起发给 AI 助手（比如 Claude），
让它帮你转成导入格式。

模板里可以用 `{变量名}` 占位（比如 `{scene}`），并在模板编辑弹窗的「变量」区域添加输入框或下拉框，
使用者生成时填写即可。

## 四、ERP / 第三方系统对接

1. 「API 对接」页面 →「创建密钥」，把生成的 **API Key** 和 **Webhook Secret** 交给对接方（两者只显示这一次，请立刻保存）
2. 对接文档：[docs/erp-api.md](docs/erp-api.md)（可直接发给对方开发人员）
3. 在线接口调试页面：http://127.0.0.1:8787/docs

关于 API Key，有三件事要知道：

- **每把 Key 都有主人**（列表里的「归属」那一列，就是创建它的那个账号）。
  **用这把 Key 提交的任务，生图费用记在主人头上。** 今天所有 Key 都归 admin，
  行为和以前一样；但如果你按 7.4 节改成了「每人一把 Key」、并且给 admin 也配了
  个人 Key，那 ERP 的费用就开始从 admin 的个人余额走。
- **停用一个成员账号，会连带停用他名下所有还启用着的 Key**（停用时的确认弹窗和
  停用后的提示都会告诉你这次关掉了几把）。用这些 Key 对接的 ERP 会立刻调不通。
  **把账号重新启用回来时，这些 Key 不会自动恢复**——要恢复对接，得回到这一页，
  在对应的 Key 那一行点「启用」，一把一把地重开。
  只想断开某一条对接、不影响这个人用网页的，就在这一页把那把 Key 单独停用。
- **停用一把 Key，会让它此前发出去的所有图片链接立刻全部失效**。
  这是止血手段（Key 泄露时用），但也意味着：如果对接方突然反馈
  「所有历史图片集体打不开」，先看看是不是这把 Key 被停用了。

> ⚠️ **发给对接方的图片地址变了**：从 2026-08-10 起，图片链接后面带
> `?k=&e=&t=` 三个签名参数，默认 7 天有效，**必须整条保存**（截掉问号后面那段
> 就打不开了）。已经接入的系统请让对方看一遍 `docs/erp-api.md` 的第 6 节，
> 只有两处要改。

## 五、部署到服务器

项目已 Docker 化，**服务器上用 PostgreSQL**（本机开发仍是零安装的 SQLite）。
镜像由 GitHub Actions 自动构建并发布到 `ghcr.io`（同时提供 x86 和 ARM 版本），
部署时直接拉现成镜像，**不需要上传源码，也不需要在目标机器上编译**。

> 🎯 **正式部署的目标是一台公网服务器**（有域名、有 HTTPS、前面套一层反向代理）。
> 群晖 NAS 那份指南保留着，但它现在的定位是**局域网里的测试环境**：
> 用来先把功能跑顺、把备份练一遍，不是最终形态。
> 两者的区别不只是「换台机器」——公网上会有陌生人主动来敲门，
> 下面「公网服务器上必须做的四件事」那一节里的每一条，在群晖内网里都可以不做，
> 在公网上少做一条就是一个洞。
>
> - 局域网/群晖测试环境：[docs/deploy-synology.md](docs/deploy-synology.md)（照着做就行的分步指南，含权限、备份、排错）
> - 公网正式环境：本章（尤其是下面「公网服务器上必须做的四件事」）

在装有 Docker 的机器上建一个空文件夹，下载两个文件：

```bash
curl -fLo docker-compose.yml https://raw.githubusercontent.com/shinycheng/designkit/main/docker-compose.yml
curl -fLo .env https://raw.githubusercontent.com/shinycheng/designkit/main/example.env
```

改完 `.env` 后：

```bash
sudo docker compose up -d
```

`.env` 里的必改项：

| 环境 | 必改 |
|---|---|
| 任何环境（4 处） | `POSTGRES_PASSWORD`、`DESIGNKIT_DATA_LOCATION`、`PUID`/`PGID`、`DESIGNKIT_PUBLIC_BASE_URL` |
| 公网服务器再加 2 处 | `DESIGNKIT_BIND_HOST=127.0.0.1`（只让反代进得来）、`DESIGNKIT_TRUSTED_PROXY_HOPS`（反代有几层就填几） |

> **本章和第六章的命令，前面的 `sudo` 都不能省。** 你 SSH 上服务器（或群晖）用的是
> 自己的普通账号，而 Docker 只让 root 使唤，不加 `sudo` 会得到一句英文的
> `permission denied ... docker daemon socket`——那不是你装错了，只是少了 `sudo`。
> 敲下去如果提示输密码，输**你自己的登录密码**（屏幕上不会显示，输完直接回车）。

这一条命令会同时起两个容器：PostgreSQL 数据库 + DesignKit 应用，应用会等数据库
健康检查通过后再启动，首次会自动建表。

**必改项**：`.env` 里的 `POSTGRES_PASSWORD` 没设置容器会拒绝启动——这是故意的，
防止默认弱口令被带上生产。密码可以放心用特殊字符，应用会正确处理。

**文件权限**：`.env` 里的 `PUID`/`PGID` 填成数据目录属主的 uid/gid
（在目标机器上执行 `id` 查看）。一般情况下容器启动会自动把数据目录属主纠正过来，
不用手工 `chown`；填错了通常是你在文件管理器里打不开这些图，而不是系统不能用。

但如果你挂载的目录里还放着**别的文件**，容器出于安全考虑不会去动它——
这时启动日志里会有 `[entrypoint]` 开头的警告，按提示手工执行一次 `chown` 即可。
**建议给 DesignKit 单独建一个空目录挂载**，不要和别的东西混在一起。

**关于对外访问**：compose 默认把 8787 绑在所有网卡（`0.0.0.0`），同局域网可访问。
⚠️ **不要把 8787 直接映射到公网**——它说的是 HTTP 明文，登录密码会在网上裸奔。
公网访问一律走「反向代理（Nginx / Caddy）配好 HTTPS → 转给 8787」这条路，
见下面「公网服务器上必须做的四件事」。只想本机访问就在 `.env` 里设
`DESIGNKIT_BIND_HOST=127.0.0.1`。

### 公网服务器上必须做的四件事

这四件事在局域网里可以不做，在公网上少做一条就是一个洞。

它们和「开放自助注册」（邀请码、手机号**两条路都算**）的关系：
**第 ① 条和第 ④ 条是系统强制的硬前提**
（没做就打不开注册，见第八章 8.1；另一条硬前提「图片链接需要凭证」默认就是开的）。
**第 ② 条系统不强制，但不配对的话注册限速形同虚设**——那是一个不会报错、
只会在被刷的时候才发现的坑，**开了手机号注册的话它还直接关系到短信账单**
（见 [9.6](#96-短信是花钱的三层限速)）。第 ③ 条与注册无关，但公网上都该做。

> 🔴 **如果你打算开手机号注册，公网上线前还要多确认一件事：
> 「短信通道」必须已经切到阿里云，不能停在默认的「调试模式」。**
> 调试模式下验证码是**直接显示在注册页上**的，等于没有验证——公网上谁都能注册进来。
> 详见 [9.2](#92-先用调试模式把流程走一遍不花钱)。

**① HTTPS（反向代理）。**
用 Nginx 或 Caddy 在前面挡一层，证书用 Let's Encrypt 自动申请，
后面转发到 `127.0.0.1:8787`；同时把 `.env` 里的 `DESIGNKIT_BIND_HOST` 改成
`127.0.0.1`，让 8787 只监听本机，外面只能通过反代进来。
不做的后果不是「不太安全」，是**所有人的登录密码在传输途中是明文的**。

**② 告诉系统前面有几层代理**（`DESIGNKIT_TRUSTED_PROXY_HOPS`）。
套了反代之后，后端直接看到的来源地址是**反代自己**，全站所有人在限速那里
共用一个桶——一个人被限速，全公司都登不上。填法：

| 你的架构 | 填几 |
|---|---|
| 没有反代，浏览器直连 8787 | `0`（默认） |
| 一层 Nginx / Caddy | `1` |
| Cloudflare 等 CDN + 一层反代 | `2` |

⚠️ **宁可填小，不要填大**。填小了大家挤在一个桶里（严一点，但没有安全问题）；
填大了系统会去信客户端自己写的那一段地址，而那段是**攻击者随便填的**，
登录限速和注册限速当场作废。数一数请求真正经过几层，就填几。

**③ 缩小「允许跨站调用的地址」**（系统设置 → 图片访问与多用户 → 允许跨站调用的地址）。
默认 `*` 表示不限制。公网上改成你自己的域名（例如 `https://designkit.example.com`），
别人的网页就没法拿着你同事的登录状态偷偷读数据。**改完必须重启服务才生效。**

**④ 关掉「允许对外接口访问内网地址」**（系统设置 → 安全与网络）。
默认是**开着**的，因为内部部署时 ERP 常常在内网、要让系统去内网取图。
一旦上公网、尤其是要开放注册，这一项必须关掉——理由见第八章开头，
那不是「更安全一点」，是「不关就等于把内网的门连同钥匙一起发出去」。

**部署后必做**：在「系统设置」→「对外访问地址」填实际访问地址
（公网上应当是 `https://你的域名`），否则生成图片的链接和回调里还是本机地址，
外部系统打不开。（保存后回填的值可能和你输入的不完全一样——系统会自动去掉
末尾的斜杠，这是正常的。）

**更新版本**：`sudo docker compose pull && sudo docker compose up -d`。
升级会自动补数据库新增的列；灵感库的分类标签也会用本地缓存自动回填（约 1 秒、不联网），
不需要你手动做什么。

> ⚠️ **升级前必做两件事**，顺序不能反：
> 1. **先备份**（数据库 + `data` 目录，见「六、数据在哪里 / 怎么备份」）
> 2. **再钉版本**——把 `.env` 里的 `DESIGNKIT_VERSION` 从 `latest` 改成当前正在跑的
>    那个标签并抄下来，见「升级前先钉版本」。
>
> 不钉版本的话，新版出问题时你连「该退回哪一版」都说不清楚；而升级之后表结构变了，
> 旧备份要按「怎么恢复」里的步骤（先清空数据库再灌）才能往回灌。
> 这两件事一起做才有意义。

**关于「系统设置 → 图片访问与多用户」这一节**（部署后通常不用动，但要知道它在）：

| 设置项 | 默认 | 说明 |
|---|---|---|
| 生图费用怎么算 | 共用一把 Key | 改成「每人一把」的完整步骤见第七章 7.4 |
| 图片链接需要凭证才能打开 | **开启** | 关掉之后任何人知道地址就能打开平台上任何一张图。只用于临时兼容对接方手里的老链接 |
| 网页取图凭证有效期 | 7 天 | 范围 7–30 天。到期重新登录一次即可，一般察觉不到 |
| 对接方图片链接有效期 | 168 小时（7 天） | 范围 1–8760 小时 |
| 允许跨站调用的地址 | `*`（不限制） | **改完必须重启服务才生效**（`sudo docker compose up -d`）。页面提示保存成功也不会立刻起作用，这是正常的，不要反复保存 |

同一节里还有一个「无凭证访问统计」，显示本次启动以来有多少次没带凭证的取图请求。
它是判断「敢不敢临时关掉图片凭证限制」的唯一客观依据（服务重启后归零）。

### 把本机数据搬到服务器（可选，想保留本机的提示词库和记录时才做）

**顺序很重要**，请照这个来：

```bash
# 1) 在本机看看会搬多少（不写入任何东西，也不需要连上服务器）
.venv/bin/python -m backend.migrate_sqlite_to_pg --dry-run

# 2) 在服务器上起好数据库（此时先不要启动应用，避免它先写入数据）
sudo docker compose up -d db

# 3) 把本机的 data/ 整个传到服务器（图片和 SQLite 库文件都在里面）
#    ⚠️ 拷之前先在本机终端按 Ctrl+C 停掉 DesignKit——数据库开着 WAL 模式，
#    服务还在跑时拷到的库文件可能不完整，迁过去会少数据甚至打不开。
rsync -av data/ 用户@服务器IP:/volume1/docker/designkit/data/

# 4) 在服务器上，用应用容器自己跑迁移。
#    数据库端口没有对外开放，但应用容器本来就在同一个网络里，直接连得到；
#    目标库连接串由容器的配置自动组装，密码里有 @ % 等字符也不会出错。
sudo docker compose run --rm designkit \
    python -m backend.migrate_sqlite_to_pg --source "sqlite:////app/data/designkit.db"

# 5) 最后再启动应用
sudo docker compose up -d
```

脚本会按外键顺序搬、分批提交（带稳定排序，不会漏行），并自动把 PostgreSQL 的自增
序列推到当前最大 id——不做这步，迁完新建记录会主键冲突。

- **目标库已有数据时会直接中止**，避免误覆盖。如果是上一次迁移中途失败留下的半个库，
  确认可以清空后加 `--truncate` 重跑（该参数会**删光目标库里这些表的全部数据**，慎用）
- 迁移完成后，记得到「系统设置 → 对外访问地址」填服务器地址（迁移会把这项也一起搬过去，
  所以要在迁移**之后**改）

## 六、数据在哪里 / 怎么备份

数据分**四**部分，**四部分都要备份，缺一不可**：

| 内容 | 本机（SQLite） | 服务器（Docker + PostgreSQL） |
|---|---|---|
| 数据库（模板、任务、设置、成员账号） | `data/designkit.db` | **PostgreSQL 容器**（在 `pgdata` 数据卷里，**不在** `data/`） |
| 图片（上传图、生成图） | `data/` 下的子目录 | `data/` 下的子目录 |
| **登录密钥 `.secret_key`** | `data/.secret_key` | `data/.secret_key` |
| **凭据加密钥匙 `.enc_key`** | `data/.enc_key` | `data/.enc_key` |

> ⚠️ 服务器部署下只拷 `data/` **不会**备份到数据库——数据库在 Docker 数据卷里。

> ⚠️ **两个隐藏文件是最容易漏、后果又最难查的**。它们的名字以 `.` 开头，
> File Station 和 `ls` 默认都看不见，但少了任何一个，恢复出来的系统都是坏的：
>
> | 文件 | 丢了会怎样 |
> |---|---|
> | `data/.secret_key` | 所有人被踢下线要重新登录；**已经发给 ERP 对接方的 Webhook Secret 全部失效**，对方那边一路验签失败，且不会有任何报错提示你原因；已经发出去还没用掉的**短信验证码**也会全部作废（这一条影响就几分钟，用户重发一次即可） |
> | `data/.enc_key` | **全体成员的个人网关 Key 全部解不开**。表现是「所有人突然都不能生图」，而数据库看起来完好无损、界面上那些人还明明白白写着「已配置 Key」。只能到网关后台把每个人的 Key 重新抄一遍、在「成员账号」页逐个重填。**阿里云短信的 AccessKey Secret 也在里面**，同样解不开，需要到设置页重填一次（见 [9.4](#94-切到真实模式阿里云短信要填的四项)） |
>
> 好消息是下面的命令本来就会把这两个都带上——前提是你备份的是**整个 `data` 目录**，
> 而不是只挑里面的图片文件夹。备完请按下面的「检查」那步确认一遍。

> **`user_gateway_accounts` 这张表也丢不起**：它存着每个成员的网关 Key（密文）。
> 它在**数据库**里，不在 `data/` 目录里——所以「只拷 data 目录」和
> 「只备数据库」两种做法，各自都会让成员的 Key 变成一堆废数据。必须两样都备。
> 开了「自动开通」（7.6）之后，这张表还记着每个人在网关那边的账号编号和开通状态；
> 丢了它，那些账号在网关后台还在、系统这边却认不出来了，只能一个个手工重填 Key。

> 如果你在 `.env` 里显式设置了 `DESIGNKIT_SECRET_KEY` 或 `DESIGNKIT_ENCRYPTION_KEY`，
> 那么系统用的是这两个值，`data/.secret_key` / `data/.enc_key` 不再起作用——
> 这种情况下要备份的是 `.env` 文件。默认两个都没设置。

### 本机（SQLite）

```bash
# 先停止服务（Ctrl+C），再整个 data/ 目录拷走
cp -r data ~/designkit-backup-$(date +%Y%m%d)
```

数据库开了 WAL 模式，运行中只拷 `designkit.db` 会丢数据，必须停服后整目录一起拷，
或用 `sqlite3 data/designkit.db ".backup 'backup.db'"` 在线备份。

`cp -r data ...` 会连隐藏的 `.secret_key` 和 `.enc_key` 一起拷走，所以务必拷**整个目录**，
不要只挑 `designkit.db` 和图片文件夹。拷完检查一下这两个文件在不在：

```bash
ls -a ~/designkit-backup-$(date +%Y%m%d) | grep -E '^\.(secret|enc)_key$'
# 应该打印出两行：.enc_key 和 .secret_key。少一行就是没备全
```

### 服务器（PostgreSQL）

> 下面这些命令都在群晖上用 SSH 执行，**前面的 `sudo` 不能省**（Docker 只让 root
> 使唤）。提示输密码时，输你自己的登录密码。

```bash
cd /volume1/docker/designkit

# 1) 备份数据库（不用停服）
#    --clean --if-exists 一定要带：它让导出的 SQL 里自带「先删掉旧表」的语句。
#    不带的话，这份备份只能灌进一个空库，往有数据的库里灌会全程报「表已存在」。
sudo docker compose exec -T db pg_dump --clean --if-exists -U designkit designkit | gzip > db-$(date +%Y%m%d).sql.gz

# 2) 备份图片和两把钥匙（整个 data 目录，隐藏文件也在里面）
tar czf images-$(date +%Y%m%d).tar.gz -C /volume1/docker/designkit data

# 3) 检查备份是不是真的备到了东西 —— 这步别省
#    第一条应该打印一个大于 0 的数字（表的数量）
#    第二条必须打印出两行：data/.enc_key 和 data/.secret_key。只有一行就是没备全
gunzip -c db-$(date +%Y%m%d).sql.gz | grep -c 'CREATE TABLE'
tar tzf images-$(date +%Y%m%d).tar.gz | grep -E 'data/\.(secret|enc)_key$'
```

> 第 3 步为什么必须做：`pg_dump | gzip > 文件` 这种写法，万一数据库容器没起来，
> pg_dump 失败了，`gzip` 照样会给你生成一个**看起来正常、其实是空的** `.gz` 文件，
> 整条命令还返回「成功」。等到真要恢复的那天才发现备份是空的就来不及了。

### 怎么恢复

**先分清你要的是哪一种回退**，这一步决定了后面完全不同的两条路：

| 你的处境 | 该走哪条路 |
|---|---|
| 升级后新版本有毛病，但**数据本身是好的**（绝大多数情况都是这种） | **只把镜像钉回旧版本，数据库原样不动**——见下一节「升级前先钉版本」。这条路经过实测：旧版程序跑在升级过的库上一切正常，不用碰备份，也不会丢任何记录，是风险最小的一条 |
| **数据也要退回**到备份那天（误删了东西、数据被写坏了） | 才走下面这套「灌回备份」 |

> ⚠️ 「灌回备份」会把**备份那天之后产生的全部记录抹掉**（新建的账号、新生成的图、
> 改过的设置）。别把它当成「重启一下试试」来用，先试上面那条钉版本的路。

**恢复前先看一眼「升级前先钉版本」那段**：如果这份备份是升级之前导出的，
要先把版本改回当时那个，再恢复——新版本的表结构和旧备份对不上。

动手前先确认三件事：

- **备份文件在哪**：每日定时任务存到 `/volume1/docker/designkit-backup`，
  手工按上面那节备的则在 `/volume1/docker/designkit`。下面的命令按定时任务那个目录写，
  如果你恢复的是手工备的那份，把 `-backup` 去掉即可。
- **哪一天的**：把命令里的 `20260810` 全部换成你要恢复的日期。
- **这份备份不是空的**：先用上一节「检查备份是不是真的备到了东西」那两条命令验一遍
  （`grep -c 'CREATE TABLE'` 要打印出一个大于 0 的数字）。
  ⚠️ 下面第 2 步会**把数据库清成一张白纸**，清完了才发现备份是空的就没有退路了。

```bash
cd /volume1/docker/designkit

# 1) 先停应用。它一直占着数据库连接，不停的话第 2 步会卡住
sudo docker compose stop designkit

# 2) 把数据库清空。**这一步不能省**，原因见下面那段说明
sudo docker compose exec -T db psql -v ON_ERROR_STOP=1 -U designkit -d designkit \
  -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public;'

# 3) 灌回数据库
#    -v ON_ERROR_STOP=1 一定要带：出错就立刻停下并返回失败。
#    不带的话 psql 会「一路报错一路继续往下跑」，最后给你一个新旧混杂的库，
#    退出码还是 0，在群晖任务计划里显示成「执行成功」——这是最坏的情况。
gunzip -c /volume1/docker/designkit-backup/db-20260810.sql.gz \
  | sudo docker compose exec -T db psql -v ON_ERROR_STOP=1 -U designkit -d designkit

# 4) 恢复图片和两把钥匙（会覆盖 data 目录里的同名文件）
tar xzf /volume1/docker/designkit-backup/images-20260810.tar.gz -C /volume1/docker/designkit

# 5) 把应用起回来
sudo docker compose start designkit
```

> **第 2 步（清空数据库）为什么不能省**：升级会往数据库里**加新表**。旧备份是升级
> 之前导出的，里面根本不认识这些新表，所以它自带的「先删旧表」语句会被新表挡住，
> 灌到一半就停下来报一句纯英文的
> `cannot drop constraint users_pkey on table public.users because other objects depend on it`。
> 更糟的是**它是灌了一半才停的**：停下来之前已经把库里所有的外键和
> 「用户名不许重复」「API Key 不许重复」这些约束删光了，而系统还能照常启动、
> 页面一切正常——坏了但看不出来。先清空再灌就不会有这个问题，
> 清空之后旧备份是灌进一个空库，和它当初被导出时的情形完全一样。

恢复完打开网页，如果提示你重新登录，属于正常现象——第 4 步换回了旧的 `.secret_key`，
之前那把钥匙签发的登录状态就失效了。密码还是备份那天的密码。

> ⚠️ **第 3 步和第 4 步必须一起做，不能只做一个。** 数据库里存着每个成员的
> 网关 Key（密文），而解开它的钥匙是 `data/.enc_key`。只灌数据库不恢复
> `.enc_key`，或者反过来，结果都是「全体成员突然都不能生图」，
> 而界面上他们还写着「已配置 Key」——这种故障从现象上完全看不出根因。
> 万一真的只剩数据库、`.enc_key` 找不回来了，唯一的办法是到网关后台
> 把每个人的 Key 重新抄一遍，在「成员账号」页逐个重新填一次。

**万一第 3 步还是中途停下并报错**（屏幕上出现 `ERROR:` 开头的英文）：

1. **不要反复重试**，重试的结果一模一样。
2. 此时数据库是空的、应用还停着，**先别急**——这不是不可挽回的状态。
3. 先确认第 2 步真的执行成功了（它应该打印 `DROP SCHEMA` 和 `CREATE SCHEMA` 两行）。
   如果第 2 步被跳过或报错了，把它补做一次，再重来第 3 步。
4. 第 2 步没问题却还是报错，那多半是**这份备份文件本身坏了**（比如当初 pg_dump
   就失败了，只留下一个空的 `.gz`）。换一天的备份文件再试。
5. 手上没有能用的备份时，走这条保底路线：把 `.env` 里的 `DESIGNKIT_VERSION`
   改回纸上抄的旧版本，执行 `sudo docker compose up -d`，让系统用**当前这个空库**
   重新建表启动——数据回不来了，但系统能重新用起来，账号需要重新建。

### 升级前先钉版本（每次升级前都做，30 秒）

`docker-compose.yml` 里镜像版本默认是 `latest`，也就是「永远跟最新」。
一旦新版本出问题要往回退，你会发现说不清楚「原来跑的是哪个版本」——
`latest` 今天指向的东西和昨天不是一回事。所以升级前先把当前版本记下来并钉住：

1. 查出当前正在跑的是哪个版本，打印出来的是 7 位字符，例如 `6ca035d`：

```bash
cd /volume1/docker/designkit
sudo docker inspect --format '{{index .Config.Labels "org.opencontainers.image.revision"}}' designkit | cut -c1-7
```

2. **把这 7 位字符抄在纸上**（或记事本里），前面加 `sha-`，例如 `sha-6ca035d`
3. 编辑 `.env`，把 `DESIGNKIT_VERSION=latest` 改成 `DESIGNKIT_VERSION=sha-6ca035d`
4. 执行 `sudo docker compose up -d` 确认这个版本能正常起来（这一步不会换版本，
   只是把「跟随最新」换成「钉死在你现在跑的这一版」）
5. 之后要升级，就把 `.env` 里的版本改成新的标签（或改回 `latest`），再 `up -d`。
   出问题就把 `.env` 改回纸上抄的那个 `sha-xxxxxxx`，`up -d` 即可退回去

> 每次推送代码，GitHub 都会自动为该次提交打一个 `sha-` 开头的镜像标签，所以任何一版
> 都能这样退回去。如果第 1 步打印出来是空的（早期镜像没带这个标记），
> 就去 GitHub 仓库页面 → 右侧 **Packages** → `designkit`，在标签列表里挑日期对得上的
> `sha-xxxxxxx`。

- 建议把备份加到服务器的每日定时任务里（群晖的做法见
  [docs/deploy-synology.md](docs/deploy-synology.md) 第 6 步）
- `data/` 必须放在**本地磁盘**，不要放网络盘/云同步盘

## 七、给同事开账号（成员账号）

> 这是[三种开号方式](#先分清三种开号方式很容易混)里的**第一种**，也是唯一一种
> 一直可用、不需要任何前提条件的方式。别的路都走不通时，回到这一章总能开出号来。

系统里有两种角色：

| 角色 | 能看到什么 | 能做什么 |
|---|---|---|
| **管理员**（admin） | 全部 9 个页面 | 建成员账号、发邀请码、改系统设置、管 API Key、看所有人的生成记录 |
| **成员**（member） | 生成、记录、模板、灵感、我的 —— 五项 | 只能看到**自己**上传的图和自己的生成记录 |

> ⚠️ **角色是建号时选的，建完就改不了**——系统没有「把管理员降回成员」这个功能，
> 也没有「删除账号」（原因见 7.1 末尾）。也就是说选错一次，就会永久多出一个
> 能改系统设置、能看所有人记录的管理员，只能把这个账号「停用」了事。
> 建号时那个「角色」下拉**保持默认的『成员』**就对了，别顺手改。

成员之间是互相看不见的：别人的图片链接、别人的任务详情，一律显示「不存在」。
管理员能看到所有人的图（要帮人排障），但**不能替别人点「重新生成」或「补图」**——
那会花那个人的钱。

### 7.1 建一个成员账号

1. 管理员登录 → 左侧导航「成员」→ 标题右边的「新建成员」按钮
2. 弹窗里从上到下有**四项**：
   - **用户名**：登录时输入的名字，只能用字母、数字和 `.` `_` `-`，长度 3~32 位
     （例如 `zhangsan` 或 `li.si`）。**建号之后改不了**，想改只能重新建一个
   - **显示名**：界面上显示的名字，可以写中文，随便填。留空就显示用户名
   - **角色**：一个下拉框，默认已经选好「成员（只能看到自己的图和任务）」，
     **保持默认不动就对了**。只有当你确实需要「第二个人也能改系统设置、看所有人的
     记录、管所有人的 Key」时，才改成「管理员」。
     ⚠️ **建完之后角色改不了，账号也删不掉**——选错只能把这个账号停用，
     系统里就会永久留着一个多余的管理员
   - **初始密码**：至少 8 位，你自己定
3. 点「创建账号」后会弹一个窗口显示这个初始密码，并有「复制密码」按钮。
   **把它当面告诉本人**——这个密码不会再显示第二次
4. 本人第一次登录会被强制要求改掉这个密码，不改就什么都用不了

> **没有「删除成员」这个功能**，这是故意的：人删了，他名下的生成记录和商品图
> 就变成没人认领的孤儿数据，谁也说不清那些图是谁的、当时花了谁的钱。
> 人走了就用「停用」，记录原样保留，随时可以再启用回来。

### 7.2 停用一个成员（离职、账号可能泄露）

在「成员」页那一行点「停用」，会弹出二次确认。确认之后**立刻**生效：

- 他当前的登录状态作废，下一次点任何东西都会被踢回登录页
- **他手上的图片链接立刻打不开**（包括已经发给别人的）
- 他没法再用原来的密码登录
- **他名下所有还启用着的 ERP API Key 一起被停用**，用这些 Key 对接的 ERP 当场调不通
  （下面这条 ⚠️ 有更细的说明，尤其是「启用回来会怎样」）

他名下的商品图和生成记录**原样保留**，随时点「启用」他就能重新登录、这些记录照旧看得到。

> ⚠️ 停用成员账号**会**连带停用他名下所有还启用着的 API Key，用这些 Key 对接的
> ERP 会立刻调不通（确认弹窗里会先提醒你，停用之后的提示还会告诉你这次关掉了几把）。
> 而且**再把账号启用回来时，这些 Key 不会自动恢复**（这是有意的：停用往往就是为了
> 拔掉某条对接，自动接回去你不会察觉）。要恢复对接，请到「API 对接」页找到对应的
> Key，一行一行点「启用」重开。

### 7.3 他忘了密码怎么办

在「成员」页那一行点「重置密码」，由**你**输入一个新的初始密码（至少 8 位），
然后当面告诉他。他登录后会被再次要求马上改掉。

重置之后他在所有设备上的登录立刻失效。系统不提供「找回密码」邮件——
内部使用，当面给最省事也最安全。

### 7.4 让每个人花自己的钱（每人一把 Key）

默认情况下，全公司共用「系统设置 → 生图服务」里那**一把全局 Key**，
所有人的生图费用记在一起，账单上分不出是谁用的。

想让每个人各花各的：

**第一步**：给每个成员配一把他自己的网关 Key。
「成员」页那一行 →「配置生图 Key」→ 把网关那边给这个人开的 Key 整串粘进去 → 保存。
保存后可以点「测试连接」验证（只查一次模型列表，**不出图、不花钱**）。

> 这一步可以让系统自动办：见下面「7.6 让系统自动去网关开号、领 Key（可选）」。
> 自动开通只是**省掉你手工粘 Key 这一步**，不是取代它——手工这条路永远保留，
> 而且永远比自动快（粘进去立刻生效）。

**第二步**：「系统设置 → 图片访问与多用户 →「生图费用怎么算」改成
**「每人一把 Key（各花各的）」** → 保存。

> ⚠️ **两步都做完才生效**。只做第一步的话，界面提示「已保存」，
> 但费用照旧记在全局 Key 上；只做第二步的话，没配 Key 的成员一点生成就被拦住。
> 顺序建议：先给所有人配好 Key，最后再改这个开关。

改成「每人一把」之后：

- 成员点生成时用的是**他自己那把 Key**，费用从他自己的网关余额走
- **没配 Key 的成员会被直接拦住**，任务显示失败，原因写着
  「你的账号还没有开通生图额度，请联系管理员在『成员账号』页配置」。
  这种失败**重试多少次都一样**，别让他反复点重试，去把 Key 配上就好
- **管理员自己**如果没配个人 Key，仍然用全局那把（全局 Key 本来就是管理员配的）
- **ERP 对外接口**用的是「这把 API Key 的主人」那把 Key。今天所有 API Key
  都归 admin，所以行为和以前一样；哪天 admin 给自己配了个人 Key，
  ERP 的费用就开始从 admin 的个人余额走——这是预期行为，不是 bug
- **模拟生图模式（mock）不受影响**：没配 Key 也照样能出占位图，
  所以新部署时先用 mock 跑通流程这条路没被堵掉

> 🔒 **Key 在界面上永远看不到**，连末 4 位都不显示——已经配过的成员，
> 输入框里是 8 个星号占位符。想改就把新的整串重新粘一遍；
> 不动它直接保存，系统会认为「没改」，提示语是「没有填写新的 Key，原有配置保持不变」
> 而不是「保存成功」。
>
> Key 在数据库里是加密存放的，钥匙是 `data/.enc_key` 这个文件。
> **备份时千万别漏了它**，见上面「六、数据在哪里 / 怎么备份」。

### 7.5 成员自己能看到什么

成员登录后，左侧导航最下面的「我的」（我的账户）页里有：

- 自己的显示名 / 用户名 / 角色
- **「生图额度」**：只有「可以生图 / 暂时不能生图」两种显示。不能生图时会直接写清原因
  （通常就是「让管理员去『成员账号』页给你配 Key」）。
  开着 7.6 的自动开通时，新人刚建号的那几分钟里也会看到这句话——
  **成员这边看不到「正在开通中」这种中间状态**，他只知道现在还不能生图。
  他要是着急，最快的办法永远是你手工给他填一把 Key（粘进去立刻生效）
- **「余额」**：只有开了「每人一把 Key」、并且这个人的额度已经开通好了，
  才会显示一个数字；否则显示的是「你的账号没有单独的余额」或者「还在等第一次同步」。
  关于这个数字有两件事必须知道，页面上也写着：
  - **它是快照，不是实时值。** 后台每 **10 分钟**同步一轮，页面上会写着
    「余额数据 X 分钟前」。刚生成完一张图，这个数字**不会立刻变小**——
    那不是没扣钱，是还没同步到。超过 30 分钟没更新会自动变成黄色提醒，
    那通常意味着服务器一时连不上网关（不是余额出了问题）。
  - **单位是美元，因为账是在生图网关那边记的，网关本身就按美元计价。**
    系统这里**不做任何汇率换算**：编一个汇率进来，页面上的数和网关账单上的数
    就成了两个值，对不上时谁也说不清该信哪个。想知道折合人民币多少，
    按你充值那天的实际汇率自己乘一下。
  - 读不到余额时显示的是「—」而不是 `0`：「没钱了」和「读不到」在页面上
    长得完全不一样，看到 `$0.00` 就是真的快用完了（余额不足 1 分钱也会这么显示）
- 自测两个模型的连接（「测试生图连接」和「测试写提示词的模型」，不出图、不花钱）
- 修改自己的密码
- **「退出其他所有设备」**（页面最下面「登录设备」那一节里的红色按钮）：怀疑账号被
  别人用了就点它——手机、平板、别人电脑上的登录会立刻失效，别人手上已经拿到的
  图片链接也会立刻打不开；**你正在用的这台不受影响，不用重新登录**。
  点完请顺手用上面的「修改密码」换个密码，否则对方知道密码，还能再登进来一次。
  （右上角头像菜单里那个「退出登录」只退出你当前这一台，别搞混。）

**这一页没有任何 API Key 输入框**——成员不能自己填 Key，也看不到自己那把 Key
长什么样。这是有意的：Key 由管理员统一从网关后台开、统一配置，
免得出现「我自己填了一个，怎么还是不能用」这种谁也说不清的状态。

### 7.6 让系统自动去网关开号、领 Key（可选）

7.4 的第一步（去网关后台给每个人开号、把 Key 粘回来）可以让系统自己办：
新建一个成员时，系统跑到图片网关那边替他建账号、领一把只属于他的 Key，存进来。
**默认是关着的**，要用得自己去打开。

> 📖 **完整说明见 [docs/auto-provision.md](docs/auto-provision.md)**：
> 怎么配、怎么测、上线前必须做什么、每一种失败原因是什么意思该怎么办、
> 升级网关之后要复核什么。下面只讲最要紧的四件事。

**① 在哪填**：管理员 →「系统设置」→ 往下翻到**「网关自动开通」**这一节
（在「图片访问与多用户」和「自助注册（邀请码）」中间）。要填五项：

| 填什么 | 说明 |
|---|---|
| 网关地址 | 网关**管理后台**的地址，例如 `http://192.168.31.235:3000`。**注意它和「生图服务」里那个发图地址不是同一个**（那个带 `/v1`），也不要带 `/api` 或 `/api/v1` |
| 网关管理员 Key | **你自己**登录网关后台生成一把粘进来。填完只显示星号，连末 4 位都不显示 |
| 目标分组 id | 一个数字，网关后台里那个分组的编号 |
| 成员邮箱后缀 | 默认 `designkit.local`，不用改。系统用「dk + 成员编号 + @后缀」在网关那边建号，这个邮箱不用真实存在 |
| 保管成员在网关的登录密码 | **保持关闭**（默认，更安全，理由见 ③） |

填完先点这一节的「保存此区域」，再回到最上面把「自动给新成员开通」打开，**再保存一次**。
然后点「测试能不能自动开通」——它只去网关那边看几个设置，**不建账号、不发 Key、不花钱**，
给你一盏红/黄/绿灯和一段人话结论。

> ⚠️ **两个开关是分开的**：自动开通发下来的是「每个人自己的 Key」，
> 要真的用上它，7.4 第二步那个「生图费用怎么算」也得改成「每人一把 Key」。
> 只开自动开通、不改计费方式的话，Key 发了但没人用，费用照旧记在全局 Key 上。

> ⚠️ **打开开关之后，已经在册、但从来没有过网关记录的人也会被一起开通——
> 包括管理员你自己。** 在「每人一把 Key」模式下，这意味着你自己的生图、
> 以及所有 ERP 对外接口的任务（那些 API Key 都归 admin），会开始从
> 管理员这个**新开的**网关账号扣，而不是「生图服务」里那把全局 Key。
> 不是 bug，但事先不知道的话会看成「全局 Key 的余额怎么不动了」。
> 另外：**在开关关着的时候建的成员不会被自动补开通**，要到「成员账号」页
> 对他点一次「重新开通」。四种情况的完整对照见
> [docs/auto-provision.md](docs/auto-provision.md) 第三点五节。

> ⚠️ **上线前必须做两件事**：① 点一次「测试能不能自动开通」，把它读回来的
> **你那台机器上的实际设置**看一遍（源码默认值不等于你机器上的现状）；
> ② 建一个测试成员，等它显示「已开通」后，用这个账号**真的生成一张图**——
> 自检只能证明网关愿意受理这把 Key，证明不了真能出图。两件事的细节都在
> [docs/auto-provision.md](docs/auto-provision.md) 第五节。

**② 它一定会有开不通的人，这是设计的一部分，不是 bug。**
中间有一步是「系统代替这个成员登录网关」，而只要这个成员自己在网关那边
开了两步验证、或者自己改过网关密码，系统就永远进不去他的账号——既拦不住也修不好。

卡住的人会在「成员账号」页标成 🟡 **需要手工处理**，下面写着人话原因、
已经自动试过几次、下次什么时候再试，并给两个按钮：

- **「重新开通」**：重新排队，后台通常一分钟内跑完（点完页面不会自己变，点列表上方的「刷新」看结果）
- **「改用手工填 Key」**：**这是终点，也永远可用**。去网关后台给他开一把 Key 粘进来，
  存进去立刻能用，后台从此不再动这一行

能自动重试的失败（网络不通、网关重启、被限流），系统自己会按
1 分钟 → 5 分钟 → 30 分钟 → 2 小时 → 12 小时的节奏重试；不能自动重试的，
点一百次也是同一个结果。**别在「重新开通」上反复点。**

**③ 系统默认不长期保管成员的网关密码。**
开通过程中系统会给这个成员在网关那边生成一个随机密码（加密存放），
**开通成功那一刻就把它清空**。因为取回一把已经发出去的 Key 只要管理员 Key 就够了，
只有「新建 Key」那一次才需要密码——留着没用，删掉之后系统里长期保管的
就只是一堆 Key，而不是一堆能登进网关的账号密码。

代价要知道：这一行以后**不能再自动重建 Key** 了。哪天这个人的 Key 在网关后台被删了，
只能你手工填一把。想留着就把那个开关打开，但那意味着系统里长期躺着一堆可登录凭据。

> 🔒 不管开还是关，**界面上永远看不到这个密码**，任何接口都不返回它——
> 这不是藏起来了，是系统里压根没有「查看密码」这个功能。

**④ 开不通不影响任何人登录和使用。** 网关整个断电、地址填错、Key 过期，
表现都只是「新成员照常进得来，只是生图要等你手工发一把 Key」，
绝不会变成「新人一个都进不来」。

## 八、让别人自己注册（邀请码）

> 这是[三种开号方式](#先分清三种开号方式很容易混)里的**第二种**。
> 第三种（手机号 + 短信验证码）见第九章，两条自助注册路互不影响，可以只开一条。

第七章那条路是「你逐个建号、当面把初始密码给他」。人一多就受不了：
每来一个人你都得在场。这一章讲另一条路——**你发一串邀请码给他，他自己注册**。

> **默认是关着的。** 不打开的话，这一章描述的一切都不会发生，系统的行为和以前
> 一模一样。**先读完 8.1 再决定要不要开**，那一节讲的是「不满足前提就开放注册」
> 会发生什么，不是走过场的免责声明。

### 8.1 打开之前必须满足的三条硬前提

> 📌 **这三条是两条自助注册路（邀请码、手机号）共用的**，第九章不再重复一遍。
> 只要**任意一条**注册路开着，这三条就必须全部成立。
> 手机号那条路还多一条自己的前提（短信通道要能用），见 [9.3](#93-打开手机号注册)。

这三条不是建议，是**系统强制**的：不满足就存不进去，保存时会弹一段中文告诉你
是哪一条、怎么改。而且是**双向**的——注册开着的时候，你也改不回去
（想改就得先把注册关掉）。

**① 必须关掉「允许对外接口访问内网地址」**（系统设置 → 安全与网络）。

这条最要紧，用大白话讲一遍：

本系统的对外接口允许调用方说「这几张图在这个网址上，你去取一下」，
以及「生成完了往这个网址回调一声」。**去取、去回调的是服务器，不是调用方。**
也就是说，调用方能指挥你的服务器去访问一个地址。

「允许访问内网地址」开着的时候，这个地址**可以是你内网里的任何东西**：
路由器管理页、NAS 管理页、打印机、监控、以及最要命的——**生图网关的管理后台**
（那上面能建账号、能改余额、能读出任何一个人的明文 Key）。
这些东西平时之所以安全，靠的是「外面的人碰不到内网」。

平时这不是问题，因为**能拿到对外接口 Key 的只有你自己和你信任的 ERP 对接方**——
今天这把 Key 只有管理员能创建，普通成员在界面上根本看不到「API 对接」这一页。
所以现在这条链是断的：一个刚注册进来的陌生人拿不到 Key，也就指挥不动你的服务器。

**那为什么还要强制关掉它？** 因为「这条链是断的」靠的是一件太容易变的事——
「只有管理员能建 Key」这一条在代码里就是一行判断，哪天为了方便让成员自己建
对接 Key（一个很自然的需求），链就接上了，而做那个改动的人**不会想到**
它同时把内网的门打开了。除此之外还有两条更普通的路：你把一把 Key 发给某个
外部对接方（开放注册之后，这类「外面的人」只会越来越多），或者有人从你这儿
把 Key 要走。这三条路都通向同一件事：**内网的门连同钥匙一起发了出去。**

安全设置的价值就在于「哪怕别的地方出错，这里也拦得住」。开放注册＝你不再认识
系统里的每一个人，这时候把一道随时可能被绕开的门锁死，代价是内网取图要换个方式，
收益是这一整类事故都不会发生。所以系统把它做成了**强制**，而不是提醒。

关掉之后，指向内网/本机的取图和回调地址会被系统直接拒绝
（云服务商的元数据地址无论开关怎么设都一直是拦的）。

✅ **关掉它不影响生图本身。** 这个开关只管**别人在对外接口里填的地址**
（`image_urls` 取图、`callback_url` 回调）。你在「系统设置 → 生图服务」里填的
生图网关地址是**你自己填的**，不受这个开关限制——网关在内网（比如
`http://192.168.31.235:3000`）照样连得上，生成、自动开通、余额同步全都照常。
同理，「灵感库同步」和它的代理设置也不受影响。

⚠️ **代价要知道**：如果你的 ERP 就在同一个内网里、靠内网地址给系统传图，
关掉之后那条路会断。这时要么把 ERP 的图放到一个公网能打开的地址上，
要么改用「直接上传文件」或「base64」这两种给图方式（见
[docs/erp-api.md](docs/erp-api.md)），**要么就别开放注册**——
内部几个人用的系统，本来也不需要自助注册。

**② 「对外访问地址」必须是别人真能打开的地址**（系统设置 → 安全与网络）。

不能是 `127.0.0.1`、`localhost`、`0.0.0.0` 这种「服务器自己」的意思，也不能留空。
新注册的人拿到的图片链接、回调地址全按它拼——填错了他会拿到一堆打不开的链接，
而系统这边**一个报错都不会有**，两边都查不出原因。

**公网域名还必须是 `https://`**（内网地址如 `http://192.168.x.x:8787` 允许用 http，
群晖那个测试环境不会被误伤）。理由很直白：注册页要陌生人在上面输入密码，
用 http 等于让他的密码在网上裸奔。

**③ 必须打开「图片链接需要凭证才能打开」**（系统设置 → 图片访问与多用户，默认就是开的）。

关着它的话，只要知道图片地址就能下载平台上任何人的商品图和出图结果。
自己人几个用还能凑合；**谁都能注册之后，就等于谁都能进来翻别人的图**。

### 8.2 怎么打开、怎么关掉

管理员登录 →「**系统设置**」→ 往下翻到「**自助注册（邀请码）**」这一节
（在「网关自动开通」和「短信服务（手机号注册）」中间）。

这一节顶上有一份**前提条件清单**，直接告诉你 8.1 那三条现在满足了几条、
还差哪一条、该去哪里改。三条都满足时它会变成绿色的「前提条件已满足」。

> ⚠️ **那三条前提分别住在本页另外两节里**（「安全与网络」和「图片访问与多用户」），
> 而每一节都是**各自单独保存**的。所以你在上面改完并点了那一节的「保存此区域」之后，
> 这份清单**不会自己刷新**——点一下清单下面的「**重新检查**」它才会更新。
> 不点的话你会对着一份过期的「还差 3 条」怀疑自己没改对。

清单变绿之后，把「**开放自助注册**」勾上，点这一节的「**保存此区域**」。
同一节里还能顺手改两个防刷阈值和邀请码的两个默认值（见 8.7、8.3）。

打开之后，到登录页刷新一下，主按钮下面会多出一行
**「还没有账号？我有邀请码，去注册」**（如果手机号注册也开着，这行字会变成
「去注册一个账号」，点进去再选用哪种方式）。

**要关掉**：把勾去掉，再保存。「关掉注册」这条路**永远畅通**，不会被任何前提条件挡住。

关掉之后：已经注册成功的人**不受影响**（照常登录、照常用），只是不再接受新注册；
已经发出去的邀请码也不会失效，重新打开后照旧能用。
要彻底作废某张码，去「邀请码」页点作废（见 8.5）。

### 8.3 发邀请码

管理员登录 → 左侧导航「**邀请码**」→ 右上角「生成邀请码」。四项：

| 填什么 | 默认 | 怎么想 |
|---|---|---|
| 每张码可以用几次 | 1 | **保持 1**。一张码只能开一个号，谁用了这张码一目了然。填大了，这张码被转发到群里之后，你只知道「有 20 个号是它开的」，不知道该停哪一个 |
| 几天后过期 | 7 | 填 `0` 表示**永不过期**——那是一张躺在系统里的长期通行证，发出去就收不回来了（只能事后作废）。真填了 0，「邀请码」页顶上会一直提醒你 |
| 这次生成几张 | 1 | 要拉一批人就在这里填张数（一次最多 20 张），**不要去调「可以用几次」**。10 张一次性码 = 10 个人各一张，谁是谁分得清 |
| 备注（选填） | 空 | **写上发给谁了**（「给张三」「9 月新人第一批」）。这是事后唯一能对上号的线索，一行字，别省 |

> 注册开关还没打开时，这个弹窗上会出现一条黄色提示，写着「记得到『系统设置』里
> 把开关打开」。**码可以先发**，但对方现在注册不进来——照 8.2 去
> 「系统设置 →『自助注册（邀请码）』」把开关打开。

点「生成」之后会弹一屏列出这批码，每张一个「复制」按钮，还有「复制全部」。
**这一屏关掉之后码还能在列表里看到**（码是明文存的，就是为了让你能再发一次）。

码长这样：`CRSR-WZBQ-HC13`。连字符只是为了好抄，
**对方填的时候大小写、连字符、空格都无所谓**，系统会自己收拾；
连「1 打成了 I」「0 打成了 O」这种也会自动纠正。

### 8.4 谁用了这张码

「邀请码」页每一行都写着：码、状态、备注、**被谁用了**（用户名 / 什么时候 /
从哪个 IP 注册的）、已用几次 / 共几次、有效期、谁发的、什么时候发的。

状态有四种：**可用**、**已用完**（次数用光了）、**已过期**、**已作废**。

### 8.5 作废一张码

那一行右边的「作废」按钮 → 二次确认。作废之后这张码立刻不能再用来注册。

> ⚠️ **作废只管「还没用掉的名额」，不会停掉已经用这张码开出来的账号。**
> 点完之后页面顶上会常驻一句话，告诉你这张码此前已经开出了几个号——
> 要停那些号，得到「成员账号」页逐个「停用」。这两件事是分开的，因为
> 「这张码不该再用了」和「用它注册的那几个人有问题」通常不是同一个判断。

**系统没有「删除邀请码」这个功能**，这是有意的：删掉码，等于把「这张码开过
哪些账号」这份唯一的记录一起删了——而你想删码的那一刻（码被转发到群里刷号了），
恰恰是最需要这份记录的时候。作废之后码还在，流水还在，谁用过一目了然。

### 8.6 对方注册完之后会发生什么

对方在登录页点「我有邀请码，去注册」，进到「用邀请码注册」这一页，
填四项（邀请码、用户名、显示名可不填、密码）点「**注册并进入**」，
页面会**自动帮他登录进去**，然后弹一屏欢迎语，说明「生图额度正在后台开通中，
通常一两分钟」。

（他也可以直接打开 `你的地址/#/register`——这个地址可以直接发给他。）

这里要理解的一件事：**账号是立刻建好的，生图额度是后台慢慢开的，两件事是分开的。**
这样设计是为了让生图网关出任何问题（关机、升级、换地址）都不会变成
「谁都注册不了」——最坏的表现只是「注册照常，但暂时不能生图」。

所以会出现这种情况：他登进来了，点「生成」却被拦住，提示还没开通额度。

**怎么办**（按顺序）：

1. **等一两分钟刷新**。后台每 60 秒推进一轮，绝大多数情况自己就好了
2. 超过十分钟还不行 → 你去「成员账号」页看他那一行的状态。
   显示 🟡 **需要手工处理** 的，下面会写着人话原因、已经自动试过几次
3. 点那一行的「**改用手工填 Key**」，去生图网关后台给他开一把 Key 粘进来，
   **粘进去立刻生效**。这条路永远可用，是所有失败情况的终点
4. **他那边什么都不用做**，也不用重新注册——重新注册只会白废一张邀请码

> 开着「网关自动开通」时才有 2、3 那一套；没开的话，新注册的人本来就要等你
> 手工给他配 Key（和第七章手工建号的成员一样）。自动开通怎么配、每种失败
> 是什么意思，见 [docs/auto-provision.md](docs/auto-provision.md)。

### 8.7 防刷：三道闸

开放注册之后，注册接口是对着整个互联网开的。系统自带三道闸，都不用你配：

| 闸 | 默认 | 说明 |
|---|---|---|
| 邀请码本身 | — | 没有码就注册不了。码是 12 位随机串，猜不出来 |
| 同一个 IP 每小时 | 20 次 | 成功失败都算。真人一次注册撑死试三五次 |
| 全站每天 | 50 个 | 最后一道兜底（万一某张码的次数填错了）。只算**注册成功**的 |

被挡住的人会看到「请 X 分钟后再试」，写着具体时间，不会让他反复重试。

> ⚠️ **全站每日名额用完之后，把上限调大不会立刻解封**。真到了那一刻，
> 要让某个人今天就进来，正确做法是到「成员账号」页**直接给他建号**——
> 那是针对具体某个人的决定，比把全站的闸门开大安全得多。
>
> ⚠️ 套了反向代理却没配对 `DESIGNKIT_TRUSTED_PROXY_HOPS`（见第五章第 ② 条）时，
> 上面这个「同一个 IP」会退化成「全站所有人共用一个桶」——正常人会互相挤。
> **公网部署前务必把那一项配对。**

### 8.8 注册页上的规则，别在别处再抄一遍

注册页显示的用户名规则和密码规则，是**系统自己给出来的**，页面上没有第二份。
当前的规则是：

- 用户名：字母、数字和 `.` `_` `-`，3~32 位
- 密码：**至少 10 位**，必须同时有字母和数字，不能和用户名相同或包含用户名，
  不能是常见弱口令，不能是同几个字符重复

> 密码要求比第七章管理员建号那条路（8 位）**更严**，这是有意的：管理员设的初始
> 密码只活几分钟（本人首次登录必须改掉），而自己注册时设的密码是要一直用下去的，
> 还是在公网上用。

如果你要在别的地方（群公告、内部文档）写一遍注册说明，
**请写「按页面上的提示填」，不要把规则数字抄过去**——抄岔了就会出现
「公告上写着 8 位，填了 8 位却被拒」这种谁也说不清的情况。

## 九、让别人用手机号自己注册（短信验证码）

> 这是[三种开号方式](#先分清三种开号方式很容易混)里的**第三种**。
> 对方填一个手机号，收一条验证码短信，填进去就注册好了——不用你发码，也不用你在场。

> **默认是关着的**，而且默认处在「**调试模式**」（不发真短信、不花钱）。
> 不打开的话，这一章描述的一切都不会发生。

**这一章和第八章最大的区别：短信是真花钱的，而且被刷的后果不只是花钱。**
邀请码被刷，最坏是多几个僵尸账号，停掉就完了；短信被刷是直接扣钱，
而且刷狠了阿里云会以「疑似恶意」为由**封掉你的短信签名**——那时不是花钱的问题，
是整条手机号通道停摆，重新申请签名要**按工作日算**。
所以 9.6 那一节（限速）不是调优建议，请当成必读。

### 9.1 什么时候用这条路

| 你的情况 | 建议走哪条 |
|---|---|
| 就几个同事，你认识每一个 | 第七章，管理员建号。别折腾短信 |
| 人不多但陆续来，你能一个个发码 | 第八章，邀请码 |
| 人多、陆续来、你不想每次都在场 | **本章**，手机号注册（**建议同时要求填邀请码**，见 9.3） |
| 要真的对外开放，谁来都行 | 本章，并关掉「注册时还要填邀请码」。**关之前先读完 9.6** |

> 手机号注册和邀请码注册**可以同时开**。两条都开的时候，登录页上的入口会变成
> 「去注册一个账号」，点进去有一个「手机号注册 / 邀请码注册」的选择器；
> 只开一条时不显示选择器，直接进那一条——少一次无谓的选择。

**这条路上对方要填的东西**：手机号、验证码、显示名（可不填）、
邀请码（如果你要求填的话）、密码（**可不填**）。

- **密码是可选的**。不设密码的话，他以后每次登录都收一条验证码进来（每次都花钱）。
  设了密码就多一种登录方式，平时用密码登录不花钱。
- **用户名是系统随机生成的**（形如 `u6c5m17ss`），不让他自己起，也**绝不会用手机号
  当用户名**（用户名会出现在成员列表和记录里，那等于把手机号散播到全系统）。
  注册成功的欢迎窗口里会把这个用户名显示给他，让他记一下。

### 9.2 先用调试模式把流程走一遍（不花钱）

**「调试模式」是系统的默认通道，它根本不连阿里云、不发任何短信、不花一分钱**：
验证码直接显示在注册页面上，同时写进服务器日志。用途只有一个——
在你还没申请阿里云短信、或者还没决定要不要用之前，先把整条注册流程走通看看。

在本机试的话，什么都不用配，直接照 9.3 打开开关就行（通道保持默认的「调试模式」）。
点「获取验证码」之后，注册页上会出现一块醒目的黄色提示，标题是
**「调试模式：短信没有真的发出去」**，验证码就印在里面，
而且**已经自动帮你填进输入框了**——点一下「获取验证码」，直接就能点「注册」。

> 🔴 **调试模式绝对不能带到公网上。**
> 验证码是**直接显示在注册页上、还自动填好**的，也就是说这时候的「手机号验证」
> 形同虚设：**任何人填任意一个手机号（哪怕不是他的），页面直接把码给他，
> 他点两下就注册成功了。**
> 内网自己试流程没问题，公网上这就是一个谁都能进的大门。
>
> 系统会拦你一下：手机号注册开着、通道却还是调试模式时，设置页「短信服务」
> 那一节顶上会常驻一条警告，日志里也会记一条。**但系统不会替你关掉它**——
> 它没法判断你是在内网试用还是已经上了公网。这一条只能你自己盯。

**「忘了从调试模式切回真实模式」会怎样**，说清楚这两种误会：

- **你以为短信发出去了、其实没发**——这种误会在本系统里比较难发生，因为注册页上
  那条黄色提示写得很直白。但如果你只在自己电脑上看过设置页、没看过注册页，
  就可能一直以为在发短信。
- **真正的后果是上面那条**：验证码白送给页面上任何一个人，等于没有验证。
  公网 + 开放注册 + 调试模式 = 谁都能注册进来，而且**不会有任何报错**，
  界面上、日志里都风平浪静，等你发现时账号已经进来一批了。

**怎么确认现在到底是哪种模式**：管理员 →「系统设置」→「短信服务（手机号注册）」，
这一节顶上有一句话直接写着：

- 「现在是【调试模式】：短信不会真的发出去，也不花钱……」
- 「现在是【真实模式（阿里云）】：每一次『获取验证码』都会真的发出一条短信……」

### 9.3 打开手机号注册

管理员登录 →「**系统设置**」→ 往下翻到「**短信服务（手机号注册）**」这一节
（在「自助注册（邀请码）」下面）。

**前提条件**：和邀请码注册**共用** [8.1](#81-打开之前必须满足的三条硬前提) 那三条硬前提
（关掉内网访问、对外访问地址填对、图片链接需要凭证）。这一节顶上同样有一份清单，
告诉你还差哪几条；改完上面几节之后记得点「**重新检查**」，清单才会刷新。

**手机号这条路还多一条自己的前提**：短信通道得是能用的。
具体是——通道选「调试模式」永远算能用（不花钱，就是给你试流程的）；
通道选了「阿里云」，那四项就必须填齐，否则开关存不进去。
这一条是为了避免「开关打开了，但每个人点『获取验证码』都看到一串英文报错」。

然后是这一节里的两个勾：

| 勾 | 默认 | 怎么想 |
|---|---|---|
| **开放手机号注册** | 关 | 打开之后，登录页/注册页才会出现「手机号注册」这条路 |
| **注册时还要填邀请码** | **要求填** | **保持默认**。这时手机号只负责证明「这个号是他的」，能不能进来仍然由邀请码说了算 |

勾完点这一节的「**保存此区域**」。

> 🔴 **关掉「注册时还要填邀请码」意味着什么，说白话**：
> **任何人，只要有一个能收短信的手机号，就能注册进来**，没有任何名单限制。
> 只有你真的想对外开放（比如做一次公开试用）时才关。
> 关之前先把 9.6 那四个限速数字、以及「自助注册（邀请码）」那一节里的
> 「全站每天最多注册几人」都调到你能承受的数——
> **每个新账号都要去网关开通、都要花钱，每一条验证码短信也要花钱。**

**要关掉**：把「开放手机号注册」的勾去掉再保存。关掉之后入口立刻消失，
**已经注册进来的人不受影响**，照样能用手机号登录。

### 9.4 切到真实模式：阿里云短信要填的四项

先说清楚顺序：**阿里云那边的申请（开通服务、签名、模板）要先办完**，
才有东西往这里填。签名和模板都要审核，一般几小时到 1~2 个工作日。

在「短信服务（手机号注册）」这一节里，把「**短信通道**」从
「调试模式（不发短信、不花钱）」改成「**阿里云短信（真的发、真的花钱）**」，
然后填下面四项：

| 填什么 | 去阿里云控制台哪里拿 |
|---|---|
| **AccessKey Id** | 右上角头像 →「AccessKey 管理」。**建议建一个 RAM 用户**（子账号）专门用来发短信，别用主账号那对 Key。这一项相当于「用户名」，所以界面上**不打码**——你要能看出自己填的是哪一把 |
| **AccessKey Secret** | 和上面那一项**同时**生成、成对出现。⚠️ **它只在创建那一刻显示一次**，关掉窗口就再也看不到了，当场复制保存好；丢了就重新建一对 |
| **短信签名** | 「短信服务」控制台 →「国内消息」→「签名管理」里那个**审核通过**的签名，例如某某电商。必须**一字不差**，多一个空格都发不出去 |
| **模板 CODE** | 「短信服务」控制台 →「国内消息」→「模板管理」里那个**审核通过**的模板的编号，形如 `SMS_123456789` |

还有一项「**短信接口域名**」，默认 `dysmsapi.aliyuncs.com`，**正常情况下不要改**
（留空会自动填回默认值）。

> 🔑 **AccessKey 请你自己在网页上填，我们不代填、也不写进任何配置文件。**
> 这一对 Key 是**阿里云账号级别**的凭据——拿到它的人能做什么，取决于你给这个
> RAM 用户开了多大权限，可能远不止发短信。填进去之后，Secret 在界面上
> **只显示一串星号**（连末 4 位都不给），任何接口都不会把它吐回来；
> 它在数据库里也是**加密存放**的。

**三个必须注意的坑**：

1. **RAM 用户要有发短信的权限**。在阿里云 RAM 控制台给它授予 `AliyunDysmsFullAccess`，
   否则报 `isp.RAM_PERMISSION_DENY`。
2. **签名不要带方括号**。手机上收到的短信长这样：`【某某电商】您的验证码是 123456`，
   那对方括号是短信平台自动加的，**签名本身不含它**。填进去带了方括号，
   系统会当场拒绝并告诉你原因。
3. **模板正文里的验证码变量必须叫 `code`**（写成 `${code}`），类型选「验证码」。
   变量名对不上，发出去会是一条没有验证码的短信。

模板正文可以照这个意思写：`您的验证码是 ${code}，5 分钟内有效，请勿泄露给他人。`

填完点这一节的「**保存此区域**」。

> ⚠️ 加密存放带来一个备份上的连带影响：`data/.enc_key` 这把钥匙**必须和数据库一起备份**。
> 只恢复了数据库、没恢复 `.enc_key` 的话，AccessKey Secret 解不出来，
> 设置页上会写着「AccessKey Secret 读不出来」，届时重填一遍即可。
> 备份要备哪些东西见[第六章](#六数据在哪里--怎么备份)。

### 9.5 试发一条：唯一能确认「真的能发出去」的办法

配置填得对不对，除了**真发一条出去**没有别的办法验证——签名、模板、账号
三者的匹配关系只有阿里云知道。与其让第一个真实用户当小白鼠，不如你先花四分钱确认。

这一节最底下有「**试发到这个手机号**」输入框和「**试发一条**」按钮。
**填你自己手上这台手机**，点一下，然后看那台手机有没有真的收到。

> 🔴 **这是全系统唯一一个「点一下就真的花钱」的按钮**，而且
> **处在调试模式时它也照发不误**——试发的全部意义就是验证阿里云那条链路通不通，
> 而你需要它的时候，多半正是「还没切过去」的时候。按钮旁边就写着这句话。

结果分三种：

- **绿灯**：「试发成功：阿里云已经受理这条短信（回执号 ……）」。
  ⚠️ **「受理」不等于「送达」**，中间还隔着运营商。**一定要去看那台手机**。
  过几分钟还没收到，就拿那个回执号去阿里云控制台的「发送记录查询」里查它卡在哪一步。
- **红灯**：会直接显示**给管理员看的具体修复步骤**（不是给用户看的那句笼统的话），
  外加阿里云的原始错误码和 RequestId。照着做即可，对照表见 9.7。
- **「还不能试发，阿里云的配置没填齐：……」**：这种情况一条短信都没发出去，
  也没花钱，把缺的填上再来。

> 试发按钮**同样受 9.6 那套限速管着**（它花的是一模一样的钱），
> 而且同一时刻只允许一次试发，防你手抖点两下。

### 9.6 短信是花钱的：三层限速

国内短信**约 4 分钱一条**。这个数字单看很小，所以要把话说明白：
**注册接口是对着整个互联网开的，「获取验证码」这个按钮谁都能点，而且不用登录。**
没有限速的话，一个脚本一晚上就能把它跑成四位数的账单。

而且**钱不是最坏的后果**。被刷狠了会有两种更麻烦的事：

- **阿里云封掉你的签名**。理由是「疑似恶意」或者被机主投诉骚扰。
  签名一封，整条手机号通道停摆，**重新申请要按工作日算**——那几天里谁也注册不进来。
- **你在骚扰真实的机主**。攻击者刷的是别人的号码，收到短信的是那些人，
  投诉的也是那些人，而投诉又会导致上一条。

所以系统自带**三层限速**，默认全都开着，你只需要看看数字合不合适。
（三层落到设置页上是**四个数字**——「同一个号」那一层有两个口径：
隔多久能再发一条，和一天总共几条。）

| 层 | 设置项 | 默认 | 可填范围 | 为什么是这个数 |
|---|---|---|---|---|
| 同一个号<br>（隔多久） | 同一个号隔多少秒才能再发 | **60 秒** | 60–600 | 挡「按住重发按钮连点」。阿里云自己也限「同一个号 1 分钟 1 条」，填得比 60 小没有意义 |
| 同一个号<br>（一天几条） | 同一个号一天最多几条 | **10 条** | 1–20 | 挡「拿一个号当靶子反复发」。真人一天注册一次撑死重发两三回。机主一投诉，阿里云封签名 |
| 同一个来源 IP | 同一个来源每小时最多几条 | **20 条** | 1–200 | 挡「换手机号不换机器」。20 条留了「同一间办公室多人共用一个出口」的余地 |
| 全站 | 全站每天最多几条 | **200 条** | 1–2000 | 最后一道保险丝。万一前两道被绕过、或哪个数字填错，一天的损失也就止于 **200 × 4 分 ≈ 8 块钱**，第二天自动恢复 |

**为什么要三层、少一层会怎样**：

- 只限手机号 → 攻击者拿一万个号轮着发，每个号都没超限，一晚上就是一万条的账单
- 只限 IP → 换一批代理 IP 就绕过去了，成本几乎为零
- 只限全站 → 一个人就能把当天的名额占光，正常用户全被挡在门外

三层叠在一起，任何一条路径被打满都会先撞上其中一堵墙。
**任何一层没过，这一次一条短信都不会发出去**（不是发了再拦——那样钱已经花了）。

另外两项和验证码本身有关：

| 设置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 验证码几秒内有效 | 300 秒（5 分钟） | 60–1800 | 短信到达一般十几秒，5 分钟够一个人切回来填；再长就是给「慢慢猜 6 位数」留时间 |
| 一条码最多填错几次 | 5 次 | 1–10 | 真人填错一两次很常见，但放得越宽，猜码越划算。超了这条码作废，要重新获取 |

> ⚠️ **套了反向代理却没配对 `DESIGNKIT_TRUSTED_PROXY_HOPS`**（见[第五章第 ② 条](#公网服务器上必须做的四件事)）时，
> 「同一个来源 IP 每小时」会退化成「全站所有人共用一个桶」——三层里的一层当场作废。
> **公网部署前务必把那一项配对。**

> ⚠️ 阿里云自己也有一套限制（同一签名 + 同一手机号默认 1 条/分钟、5 条/小时、
> 10 条/天），比我们这边还严的时候，用户看到的是「这个手机号收验证码太频繁了」。
> 经常出现就说明你这边的阈值比阿里云还松，把「同一个号」那两项调严一些。

> ⚠️ **全站每日名额用完之后，把上限调大不会立刻解封**（已经用掉的数不会回退）。
> 真到了那一刻，要让某个人今天就进来，正确做法是到「成员账号」页**直接给他建号**——
> 那是针对具体某个人的决定，比把全站的闸门开大安全得多。

### 9.7 发现异常，怎么紧急关掉

先说一件很容易搞错的事：

> 🔴 **只把「开放手机号注册」的勾去掉，并不能停掉全部短信。**
> 已经注册过的人还要能**登录**，所以「发登录验证码」这条路不看注册开关——
> 只要系统里还有一个手机号账号，这个接口就还在，还会真的发短信。
> **要一条短信都不再发出去，得把「短信通道」切回「调试模式」。**

发现账单不对、或者收到一堆陌生号码的发码记录，按这个顺序做：

**① 立刻止血**：「系统设置」→「短信服务（手机号注册）」→
把「**短信通道**」改回「**调试模式（不发短信、不花钱）**」→「保存此区域」。
**这一步之后一条真短信都不会再发出去**（注册和登录两条路一起停），也不用重启服务。

**② 关掉入口**：把「**开放手机号注册**」的勾去掉 →「保存此区域」。
注册页上的手机号入口立刻消失。

**③ 去阿里云那边也踩一脚刹车**。上面两步只管住**你这套系统**；
如果 AccessKey 已经泄露出去，别人可以完全绕过你的系统直接发。所以：

- 阿里云「短信服务」控制台 →「安全设置」，把**日发送总量上限**调低。
  这是最后一道、任何人都绕不过的保险丝，平时就该按你的实际用量设一个值，别留着不管。
- **怀疑 AccessKey 泄露**：到「AccessKey 管理」里**禁用**那一对 Key，
  重新生成一对，再回设置页重填。禁用是立刻生效的。

**④ 事后查**：服务器日志里每一条发码都有记录（手机号是 `138****8000` 这种脱敏形式），
可以看出是集中在几个号还是撒开在很多号上。前者多半是有人在骚扰某个机主，
后者是在刷你的钱。查完再决定把哪个阈值调严。

> 通道切回调试模式之后，手机号注册的开关**照样可以保持打开**（系统允许这个组合，
> 因为调试模式本来就是给你试流程用的）。但请记住 9.2 那条红字：
> 公网上这等于谁都能注册。**紧急处理时请两步都做。**

### 9.8 常见错误怎么办

**先说去哪看错误**。普通用户看到的永远是一句笼统的
「验证码暂时发不出去，请稍后再试，或者联系管理员帮你开通账号」——
这是**有意的**：「阿里云余额不足」这种话对公网上的陌生人来说是一份免费的内部情报。

**具体原因只给管理员看，在两个地方**：

1. **设置页点「试发一条」**，红灯下面就写着人话原因 + 该怎么办 + 原始错误码 + RequestId
2. **服务器日志**（`sudo docker compose logs -f designkit`），每一次发送失败都记了一条

下面是最常撞上的几类。左边那一列是阿里云的原始错误码，
在日志和试发结果里都能看到：

| 错误码 / 现象 | 什么意思 | 怎么办 |
|---|---|---|
| `isv.AMOUNT_NOT_ENOUGH` | **余额不足** | 去阿里云控制台给「短信服务」充值。**充完立刻恢复，不用重启系统** |
| `isv.OUT_OF_SERVICE` | **欠费被停用**（比上一条严重一级） | 同上，充值后自动恢复 |
| `isv.SMS_SIGNATURE_ILLEGAL` | **签名不对**或没审核通过 | 对照阿里云控制台里那个审核通过的签名**逐字**检查（注意别多打空格）；确认 AccessKey 和签名属于**同一个**阿里云账号 |
| `isv.SMS_TEMPLATE_ILLEGAL` | **模板 CODE 不对**或没审核通过 | 对照控制台里的模板编号（形如 `SMS_123456789`）；确认模板已通过审核 |
| `isv.TEMPLATE_PARAMS_ILLEGAL` | 模板变量对不上 | 确认模板里的验证码变量叫 `code`、类型选的是「验证码」 |
| `isv.SMS_SIGNATURE_SCENE_ILLEGAL` | 签名和模板**类型不匹配**（比如拿「通知类」签名发「验证码类」模板） | 在控制台把签名改成「通用」类型，或换一个验证码类型的签名 |
| `isv.BUSINESS_LIMIT_CONTROL` | **被阿里云自己的流控挡了**（同号 1 条/分钟、5 条/小时、10 条/天） | 等一等。经常出现说明你这边限速比阿里云松，去 9.6 把「同一个号」那两项调严 |
| `isv.DAY_LIMIT_CONTROL` / `isv.MONTH_LIMIT_CONTROL` | 撞上你在**阿里云控制台**「安全设置」里设的日/月总量上限 | 确认不是被刷之后，去控制台调整；或等第二天/下月自动恢复。**这个上限本身是防盗刷的保险丝，别调太大** |
| `SignatureDoesNotMatch` | **AccessKey ID 或 Secret 填错了**，最常见是复制时带进了空格或换行 | 回设置页把这两项重新填一遍，保存后再试发。（签名算法本身已用阿里云官方算例对拍验证过，两种签名版本也都试过，基本可排除是程序算错） |
| `InvalidAccessKeyId.NotFound` | AccessKey ID 查不到，可能填错、也可能已被停用或删除 | 到阿里云重新生成一对 AccessKey，再填进设置页 |
| `isp.RAM_PERMISSION_DENY` | 这把 Key **没有发短信的权限** | 在 RAM 控制台给这个子账号授予 `AliyunDysmsFullAccess` |
| `isv.PRODUCT_UN_SUBSCRIPT` | 这个阿里云账号**还没开通短信服务** | 先到控制台开通 |
| `PORT_NOT_REGISTERED` | 还没完成运营商的**企业实名报备** | 在控制台提交报备，一般 5~10 个工作日。这期间先用调试模式或后台建号 |
| `isv.BLACK_KEY_CONTROL_LIMIT` / `MOBILE_IN_BLACK` | **这个手机号被拉黑了**（多半是以前回复过退订短信），解除不了 | 让他换一个手机号，或者你到「成员账号」页直接给他建号 |
| `InvalidTimeStamp.Expired` | **服务器时间不准**（和阿里云差了 15 分钟以上） | 检查这台机器的系统时间，把自动对时打开。⚠️ 时钟不准还会影响验证码有效期和限速，尽快处理 |
| 日志里出现「还没登记过的错误码」 | 阿里云加了新错误码 | 把那一整行发给开发者；也可以在阿里云的「国内消息错误码」文档里查这个码 |

> 💡 **所有这些情况的兜底都一样**：到「成员账号」页**直接给这个人建号**
> （[第七章](#七给同事开账号成员账号)）。那条路不依赖短信、不依赖网络、永远可用。
> 短信排查可以慢慢来，但别让人干等着。

### 9.9 对方注册完之后会发生什么

和邀请码那条路[基本一样](#86-对方注册完之后会发生什么)，两处不同：

- **他会直接登录进去**，不用再登一次。（邀请码那条路要求他注册完再登一次，
  是为了确认他真记住了自己设的密码；手机号这条路上密码是可选的，
  再让他登一次就得再收一条验证码——多花一条短信的钱，还多一道可能收不到的坎。）
- 欢迎窗口里会**告诉他系统给的用户名**（形如 `u6c5m17ss`）。
  平时用手机号登录就行，这个用户名只有想用「用户名 + 密码」登录时才要填。

和邀请码那条路完全相同的是：**账号是立刻建好的，生图额度是后台慢慢开的。**
他登进来之后点「生成」可能会被拦住，等一两分钟刷新即可；
超过十分钟就去「成员账号」页看他那一行，走「改用手工填 Key」那条终点路。

**登录**：登录页上会多一个「手机号」的选项，两种登录方式——
收验证码登录（每次都花一条短信的钱），或者「手机号 + 注册时设的密码」（不花钱）。
注册时没设过密码的人只能用验证码登录。

> 登录失败时，「这个号没注册过」「验证码错了」「密码错了」**回的是同一句话**
> （「手机号或验证码不正确」）。这是有意的：分开说的话，这个接口就成了一台
> 「查某个手机号在不在这个系统里」的机器，拿一份手机号名单跑一遍就全知道了。
> 同理，「获取验证码」对已注册和未注册的号**响应一模一样，也照样真发一条短信**。

### 9.10 手机号在系统里是怎么存的

一句话：**除了必须能认出「这个号是谁」的那一处，系统里到处都不留手机号明文。**

- **限速表**里存的是**带密钥哈希**，不是号码本身。这张表是长期留存的，而且会为
  「每一个曾经请求过验证码的号码」留一行——包括打错的、试探的、从没注册成功的。
  存明文的话，它会慢慢攒出一份「所有来过的手机号」名单，而这些人里绝大多数
  系统本来就没有任何理由保存他们的号码。
- **服务器日志**里只有 `138****8000` 这种脱敏形式。
- **验证码**本身也只存带密钥哈希，不存明文，还带过期时间和最大尝试次数。
- **用户名不会用手机号生成**（用户名会出现在成员列表、任务记录、日志里）。

> 用的是「带密钥哈希」而不是普通哈希，因为中国大陆手机号的可能取值不到百亿，
> 普通哈希用一台笔记本几分钟就能全表反查回明文，等于没哈希。
> 那把密钥（`data/.secret_key`，也可以用环境变量 `DESIGNKIT_SECRET_KEY` 指定）
> **不在数据库里**——只拿到数据库的人算不出号码。
>
> 连带影响：换掉这把密钥会让**已经发出去、还没用掉的验证码**全部作废
> （影响面就几分钟，用户重发一次即可），「同一个手机号」那两层的限速计数
> 也会重新从零开始。（换它主要是「怀疑登录令牌泄露」时的应急动作，平时不用动。）

## 十、技术说明（给开发者）

- 后端：Python 3.9+ / FastAPI / SQLAlchemy 2.0；数据库本机 SQLite（WAL）、服务器 PostgreSQL，
  切换只改 `DESIGNKIT_DATABASE_URL`（或分开传 `DESIGNKIT_DB_*`）；搜索统一用 SQLAlchemy 的
  `icontains`（在 PostgreSQL 上编译成 ILIKE，在 SQLite 上编译成大小写不敏感的 LIKE），
  保证两边行为一致
- 生成任务：数据库任务队列 + 线程池 worker，失败自动重试。
  服务重启时会把上次中断的任务捞回队列，但只捞已经开始超过 75 分钟的——
  如果恰好在某个任务刚开始时重启，它会卡在「生成中」，既不能重试也删不掉，
  要等一个多小时后再重启一次服务才会被自动恢复
- 生图：OpenAI 兼容 Images API（`/v1/images/edits` 图生图、`/v1/images/generations` 文生图），
  base_url / key / model 均可配置；中转网关拒绝单请求多图时，会自动拆分为
  多次单图请求并聚合结果；另有 mock 模式
- 前端：无构建纯 JS SPA（`frontend/`），零 Node 依赖，由后端直接托管。
  **不请求任何外部域名**——第三方组件（lord-icon 播放器、TagCloud、Lucide 图标）
  和素材（两个 Lottie 动画、平台图标 SVG）全部复制进了仓库，按本地路径加载，
  `index.html` 里也没有 `preconnect`。
  这么做的原因不是省流量：公共 CDN（jsdelivr / unpkg 之类）一旦被投毒或被中间人
  替换，它送来的 JS 是**以我们自己站点的身份**执行的，等于全站 XSS，
  能把当时所有在线用户那份 7 天有效的登录令牌整包读走——面向公网开放注册之后，
  这不是「概率低所以先放着」的事。
  附带好处：**完全离线（内网、断网、CDN 被墙）也能正常使用**，
  登录页的动画和标签云照转，也不会把访客 IP 泄露给第三方。
  素材出处、许可与升级规矩见 [docs/AUTH_VISUAL_ATTRIBUTIONS.md](docs/AUTH_VISUAL_ATTRIBUTIONS.md)；
  自查一条命令：`grep -rn "https://" frontend/` 的结果里应当只剩注释、
  文档链接和输入框示例，没有任何真会发出去的请求
- 对外 API：`/api/v1/*`，X-API-Key 鉴权，异步任务 + HMAC-SHA256 签名回调；
  另有 `GET /api/v1/generations/{job_id}/images/{index}` 凭 Key 直接取图（不过期）
- 图片访问：`/files/<相对路径>` 是**带鉴权的路由**（`backend/app/routers/files.py`），
  不是静态目录。网页端靠登录时下发的 httpOnly Cookie `dk_files`（`path=/files`）取图，
  对外 API 靠 `?k=&e=&t=` 签名；两者都验归属，越权一律 404、无凭证 403。
  改密码 / 停用账号 / 退出登录都会让已发出的凭证立刻失效
- 多用户：`users` + `user_gateway_accounts` 两张表；自助注册另加五张
  （`auth_identities` 认证身份，已落地 `password` 和 `phone` 两种 `provider`，
  `(provider, identifier)` 上有唯一索引兜并发；密码方式的 `credential` 恒为 NULL、
  密码的唯一真相仍在 `users.password_hash`；
  `invite_codes` 邀请码；`invite_redemptions` 使用流水；
  `phone_verification_codes` 短信验证码（只存带密钥哈希，带过期、尝试上限、
  发送回执，由 `create_all` 自动建出，对存量数据零影响）；
  `rate_limit_state` 限速状态，落库因而多进程安全）。成员的网关 Key 用 AES-256-GCM
  加密存库，钥匙是独立的 `data/.enc_key`（与 `.secret_key` 刻意分开：后者随时可换，
  前者一换就等于所有凭据永久作废）。「谁的任务花谁的 Key」只在
  `settings_service.resolve_for_user()` 一处决定，且找不到 Key 时**绝不回落全局 Key**
- 自动开通（Sub2API 代客建号，默认关）：`services/sub2api.py`（只读探针 + 24 个失败分类码）
  + `services/provisioning.py`（七状态可重入状态机：`pending` → `user_created` →
  `key_issued` → `active`，外加 `failed` / `manual` / `disabled`）。
  建成员接口只**登记一行**（零网络请求、失败也不回滚建号），真正的开通在
  `services/scheduler.py` 的后台线程里跑，每 60 秒一轮；已开通的人每 10 分钟同步一次余额。
  全程不调用任何删除接口、不碰余额接口。设计与运维说明见
  [docs/auto-provision.md](docs/auto-provision.md)
- 网页接口：`/api/web/users`（管理员，8 条，含 `POST /{id}/gateway/provision` 重新开通）、
  `/api/web/account`（用户侧）、
  `/api/web/auth/{login,me,change_password,set_password,logout}`、
  `/api/web/settings/{test_provisioning,provisioning,provisioning/resume}`（自动开通自检与面板）、
  `/api/web/settings/sms`（短信当前状态，不发任何网络请求）、
  `/api/web/settings/test_sms`（「试发一条」，**会真的发短信、真的花钱**，
  发送结果一律 200 看 `ok`/`level`，只有号码非法 422 和被限速 429 才回 4xx）
- 自助注册（邀请码）：`/api/web/invites`（管理员：建码 / 列表 / `POST /{id}/revoke` 作废，
  **没有删除接口**）+ `/api/web/register`
  （`GET` 回「开不开放 + 填写规则」，`POST` 拿码换账号）。
  角色写死 `member`、请求体里的 `role` / `is_active` / `monthly_quota` 一概不读；
  邀请码用「带条件的 UPDATE + 看 rowcount」原子扣减，注册失败会把名额退回；
  三张表（`users` / `auth_identities` / `invite_redemptions`）同一个事务提交。
  报错刻意不做成探测器：码不存在 / 打错 / 作废 / 过期 / 用完回同一句话，
  用户名占用只说「不能用」。限速走 `services/ratelimit.py`
  （scope `register` 按 IP、`register_daily` 全站，429 带 `Retry-After`）
- 自助注册（手机号 + 短信）：`routers/phone.py` 四条**免登录**接口
  （`GET /api/web/phone/status`、`POST /code`、`POST /register`、`POST /login`）
  + `services/sms.py`（`debug` / `aliyun` 双通道；阿里云签名默认 V3
  `ACS3-HMAC-SHA256`，撞 `SignatureDoesNotMatch` 时自动降 V2 `HMAC-SHA1` 重试
  **一次**——那一步是网关在校验签名时就拒了、确定没发出短信没花钱，
  和「绝不自动重试」的铁律不冲突；签名算法自己实现而不装阿里云 SDK，
  是因为镜像双架构构建写死了 `--only-binary=:all:`）。
  这条路**共用**邀请码那条的开放注册闸门、IP 限速桶、全站每日名额和邀请码原子扣减
  （直接 import `routers/register.py` 的内部函数，刻意不另抄一份——各写一份的表现是
  「全站每天 50 人」实际放进来 100 个）。
  发码顺序刻意排定：**格式 → 闸门 → 三层限速只查不扣 → 配置齐不齐 → 写库 →
  扣配额 → 才发送**；配额必须在调上游**之前**扣，否则攻击者靠制造超时就能
  无限花钱而配额一次不减。验证码与限速桶的手机号都是
  `hmac_sha256(SECRET_KEY, …)`（**不能用裸 sha256**：6 位码只有 100 万种、
  手机号不到百亿，裸哈希用笔记本几分钟就能反查回明文）。
  `sms_aliyun_access_key_secret` 走 `services/secrets_box.py` 加密落库，
  并登记在 `config.SECRET_SETTING_KEYS` 里全星号打码（`access_key_id` **故意不打码**，
  它相当于用户名）
- 限速统一走 `services/ratelimit.py`（按 scope + key 计数、状态落
  `rate_limit_state` 表，因而**多进程/多 worker 安全**——原来登录限速那份
  进程内的 `defaultdict + Lock` 已删除）。登录桶的 key 是「客户端 IP|小写用户名」，
  阈值由 `ratelimit_login_max_attempts` / `_window_minutes` / `_block_minutes`
  三个设置项控制，改完立即生效、不用重启（这三项目前没有界面入口）。
  客户端 IP 由 `deps.client_ip` 按 `trusted_proxy_hops` 从 `X-Forwarded-For`
  **右侧**往回数——不能取最左边那一段，那是客户端可以随便伪造的
- 开放注册的硬前置闸门在 `routers/settings_router.py` 的 `_apply_open_register_updates`：
  合并 current + updates 之后判断，**双向**（开注册时不许内网为 true，
  注册开着时不许把内网改回 true），422 的 `detail` 是可直接显示的多行中文。
  **它同时管着 `self_register_enabled` 和 `phone_register_enabled` 两条路**，
  任意一条开着三条前提就都要成立；手机号那条另加一条
  （`_phone_register_blockers`：通道选了 aliyun 就必须配齐四项，选 debug 一律放行）。
  `routers/register.py` 和 `routers/phone.py` 每次注册还会**各自再复查一次**——
  那是兜底，防的是「有人直接改数据库」和老库遗留状态。
  `allow_internal_targets` 的**默认值刻意没改**（仍是 `true`），
  改默认会静默打断现有的 ERP 内网取图；要开注册的人自己去关，这就是闸门存在的意义
- 目录结构：`backend/app/`（routers 路由 / services 业务 / models 模型），`frontend/`（页面：
  `css/` 分层样式、`js/core/` 应用外壳与轮询、`js/views/` 各页面），`tests/`（回归测试），
  `docs/`（文档），`data/`（运行数据，勿提交）
