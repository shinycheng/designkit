# 只允许安装官方预编译好的包（轮子），不允许下载源码在本机现编译。
#
# 为什么要加这一行：镜像基于 python:3.9-slim，里面没有 gcc、没有 Rust 工具链，
# 群晖 NAS 用的 arm64 镜像在 GitHub 上还是靠 QEMU 模拟出来的，
# 任何需要现场编译的依赖轻则慢上几十倍、重则直接构建失败。
# 加上这一行以后，一旦哪天某个依赖没有 arm64 的预编译包，
# pip 会立刻报「找不到符合条件的版本」并停下，而不是闷头编译一小时再失败——
# 后者只在 GitHub 的构建机上出现，本机 Mac 永远复现不了，极难排查。
# 万一将来真有个包必须源码编译，就把这一行删掉，同时在 Dockerfile 里装编译工具。
--only-binary=:all:

# 直接依赖（钉死版本，保证本地与 Docker 环境完全一致，均在 Python 3.9 实测通过）
fastapi==0.128.8
uvicorn==0.39.0
SQLAlchemy==2.0.51
httpx==0.28.1
python-multipart==0.0.20
Pillow==11.3.0
pillow-heif==1.1.0
PyJWT==2.13.0
pydantic==2.13.4
python-dotenv==1.2.1
# 用来加密存进数据库的网关 API Key（AES-256-GCM，见 backend/app/services/secrets_box.py）。
# 44.0.2 这个版本在 amd64 与 arm64 上都有官方预编译包，装的时候不会触发源码编译。
cryptography==44.0.2
# PostgreSQL 驱动（服务器部署用；本机 SQLite 不需要也无妨）
psycopg[binary]==3.2.10

# 间接依赖（本来不用写，但这一个必须钉死）
# cffi 是 cryptography 的底层依赖，本身也是要编译的 C 扩展。
# 不钉死的话，将来 cffi 发了新版而 arm64 的预编译包还没跟上，
# NAS 用的 arm64 镜像构建就会当场失败——而那天我们大概率正在改别的东西，
# 完全想不到是这里出的问题。
cffi==2.0.0
