# designkit 图像预处理服务的依赖。版本全部钉死。
#
# ─────────────────────────────────────────────────────────────────────────
# 只允许安装官方预编译好的包（轮子），不允许下载源码在本机现编译
# ─────────────────────────────────────────────────────────────────────────
# 镜像基于 python:3.12-slim，里面没有 gcc、没有 Rust 工具链，而群晖 NAS 用的
# arm64 镜像在 GitHub Actions 上是靠 QEMU **模拟**出来的：任何需要现场编译的
# 依赖，轻则慢几十倍，重则直接构建失败。
#
# 加上这一行以后，一旦哪天某个依赖没有 arm64 的预编译包，pip 会**立刻**报
# 「找不到符合条件的版本」并停下，而不是闷头编译一小时再失败——后者只在
# GitHub 的构建机上出现，本机 Mac 永远复现不了，极难排查。
#
# 万一将来真有个包必须源码编译，就把这一行删掉，同时在 Dockerfile 里装编译工具。
--only-binary=:all:

# ─────────────────────────────────────────────────────────────────────────

# 已核对：1.4.0 在 PyPI 上同时提供
#   cp312 manylinux_2_26_aarch64.manylinux_2_28_aarch64（NAS / arm64 用）
#   cp312 manylinux_2_27_x86_64.manylinux_2_28_x86_64（服务器 / amd64 用）
# 两个预编译轮子，所以 --only-binary 不会把 arm64 构建卡住。

# 「高清放大」的 ONNX 推理引擎（models/realesr-general-x4v3.onnx，CPU 推理）。

#   cp312 manylinux_2_27_aarch64.manylinux_2_28_aarch64（NAS / arm64 用）
#   cp312 manylinux_2_27_x86_64.manylinux_2_28_x86_64（服务器 / amd64 用）
# bookworm 的 glibc 是 2.36，满足 manylinux_2_28。
onnxruntime==1.23.2

# onnxruntime 的张量输入输出全走 numpy。2.2.6 提供
#   cp312 manylinux_2_17_aarch64.manylinux2014_aarch64
#   cp312 manylinux_2_17_x86_64.manylinux2014_x86_64
# 双架构预编译轮子（manylinux_2_17 比 onnxruntime 的要求还宽）。
numpy==2.2.6
