## 第 1 步 🔴 开放注册（并配好三道门槛）

**在哪**：系统设置 → 「安全与认证」→ 注册设置

你要的是让人自己注册，不用你一个个开号。但**注册一开，有三样东西必须同时配好**，
否则就是给人免费烧你的钱。

| 开关 | 设成 | 为什么 |
|---|---|---|
| 🔴 **开放注册** | **打开** | 这就是你要的 |
| 🔴 **启用邀请码** | **打开** | 见下面 |
| 🔴 **注册邮箱后缀白名单** | 填你们的邮箱域名，比如 `@yourcompany.com` | 见下面 |
| 🔴 **新用户默认余额** | **保持 0** | 见第 1.3 节 |

### 1.1 邀请码：谁能注册由你发码决定

打开之后，**没有邀请码就注册不了**。你在「兑换码」菜单里生成码，发给要用的人。

这样既省了你一个个开号，又不会有不相干的人进来。

### 1.2 邮箱后缀白名单：现在填，将来放公网时要清空

⚠ **这两道门槛是「都要满足」，不是「满足其一」。**

填了 `@yourcompany.com` 之后，用 QQ 邮箱、163 邮箱的人**即使有邀请码也注册不了**。

| 阶段 | 邀请码 | 邮箱白名单 | 结果 |
|---|---|---|---|
| **现在**（内网试运行） | 开 | 填公司域名 | 只有拿到码 + 用公司邮箱的人能注册 |
| **以后放公网** | 开 | **必须清空** | 有邀请码就能注册，外人也可以 |

**白名单留空 = 放行所有邮箱**（不是「禁止所有」）。所以将来放公网时，
把这一栏清空即可，邀请码继续当门槛。

### 1.3 新用户默认余额保持 0（**这条最重要**）

**在哪**：系统设置 → 用户默认值 → **默认余额**

**保持 0。** 意思是：**人可以自己注册进来，但要出图得你给额度。**

花钱这件事始终在你控制下——就算有不相干的人拿到邀请码注册了，也烧不了你的钱。

> 如果哪天你想让新人注册完能马上试两张，再把这里改成一个小数目（比如 `1`，
> 大约几张图）。但要接受「每多一个注册的人就多花一点」。

### 1.4 那个会绕过所有门槛的开关

同一页往下有个「**开放钉钉注册**」。它开着的话，别人从钉钉登录**直接就进来了**，
上面三道门槛全部绕过。

默认是关的，**确认一眼，保持关闭**。

**怎么确认做对了**：退出登录 → 打开注册页 → 应该要求填邀请码；
随便填个不存在的码，应该被拒绝。

## 第 3 步 🔴 建一个分组

**在哪**：分组管理 → 创建分组

**必须排在建账号之前**——建账号时要勾分组，分组不存在就没得勾。

| 填什么 | 填成什么 | 注意 |
|---|---|---|
| 名称 | 随便，比如 `出图` | |
| **平台** | **改成 OpenAI** | 默认是 Anthropic。**保存后永久锁死改不了**，选错只能删掉重建 |
| 费率倍数 | 保持 `1.0` | |
| 专属分组 | **关掉** | 关 = 公开分组，所有人自动能用，省掉后面逐个授权 |

**同一个表单往下拉，找到「图片生成计费」区块：**

| 填什么 | 填成什么 |
|---|---|
| 🔴 **允许当前分组生图** | **必须打开**。OpenAI 平台默认是**关**的 |
| 1K / 2K / 4K 三档单价 | **先留空**，第 8 步实测完再回来填 |

> 🔴 **「允许生图」这个开关有个陷阱**：在第 7 步给内部钥匙绑分组**之前**，
> 这个开关不生效（没绑分组时系统一律放行）。所以**第一次出图成功了不代表这项配对了**。
> 绑完分组之后它才开始把关，不开就每张都失败。

> 🔴 **三档单价留空不等于免费。** 留空的话系统会按它自己的默认价扣
> （约 $0.134 / $0.201 / $0.268 一张）。你用的是 Plus 包月，
> 那个数字对你毫无意义，还会让「余额」和「还能出几张」完全对不上。
> **第 9 步必须回来把三格都填成 `1`。**

## 第 4 步 🔴 建账号（用 ChatGPT 账号登录）

**在哪**：账号管理 → 添加账号

你用的是 **ChatGPT Plus 账号登录**（不是填 API 密钥那种）。

| 填什么 | 填成什么 |
|---|---|
| 平台 | **OpenAI**（必须和第 3 步的分组一致） |
| 账号类型 | **OAuth / ChatGPT 账号登录** |
| 🔴 **分组** | **必须勾上第 3 步建的那个** |

然后按界面提示完成 ChatGPT 授权登录。

> ⚠ **Base URL 那一格不用填，填了也没用。**
> 代码里只有「API Key 类型」的账号才读它；ChatGPT 账号登录一律走 OpenAI 官方通道。

### 4.1 下一页那一堆开关：只有 4 项要管

| 项 | 填什么 |
|---|---|
| **并发数** | 保持 **10**。第 6 步「同时出几张」设成 4，还剩 6 个余量给你自己点单张 |
| 负载因子 / 优先级 | 保持默认。多个账号之间分流量用的，你只有一个 |
| **账号计费倍率** | 保持 **1**。⚠ 别填 0——填 0 这个账号的消耗就不进统计，你看不出用了多少 |
| 过期时间 | **留空**（= 不过期） |

**下面那一串开关全部保持关闭**：自动透传、摊平 Codex namespace、WS mode、
API 长上下文计费、Codex 指纹收敛——它们要么给写代码的工具用，要么给语音用，跟出图无关。

> ⛔ **「仅允许 Codex 官方客户端」千万不要开。**
> 开了之后只有 Codex 那类工具能用这个账号，**我们的出图请求会被直接拒掉**，
> 而且报错只说「访问被拒绝」，你根本想不到是这个开关。

**怎么确认做对了**：保存后重新打开这个账号，分组那一格显示第 3 步建的分组名。

## 第 5 步 ⛔ 什么都不要做：不要建渠道

**在哪**：渠道管理 → 渠道定价

**保持一条都不建。** 这是最安全的做法。

**为什么**：查不到渠道定价时，出图自动按「按张收费」走，用的就是第 3 步分组里那三档单价。

**建了会怎样**：一旦建了渠道并加了一条包含 `gpt-image-2` 的定价，
里面「**计费模式**」那一格会**默认预选成 Token**。出图就变成按文字计费，
你按张配的单价完全不生效——**费用可能算成 0，也可能算成文字的价钱，而且账面上看不出来**。

这一条不是「用不到」，是「**别建**」。

## 第 6 步 🔴 配「商品图设置」

**在哪**：左侧「管理」区最下面、紧挨「系统设置」**上面一格**，叫「**商品图设置**」

这一页管的是「出图这件事按什么规矩跑」。

| 项 | 默认 | 说明 |
|---|---|---|
| 🔴 **出图模型** | `gpt-image-2` | **原样复制**，别改大小写、别加空格。**填错不会有任何提示**，只会每张都失败。（这是 OAuth 账号出图时代码里的默认模型，不用去别处查） |
| 🔴 **出图比例** | 1:1 / 3:4 / 4:3 / 16:9 / 9:16 | 一行一个，写成「宽:高」，中间是**英文冒号**。这里的顺序就是运营看到的按钮顺序，第一个默认选中 |
| 🟡 图片最长边 | 2048 | **2048 及以下算 2K 档，超过就是 4K 档，4K 明显更贵**。下面那张预览表会跟着变，用它看档位跳变 |
| 🟡 同时出几张 | 4 | **不要填超过 4**。真正卡住的是**每用户并发上限**（`users.concurrency`，默认 5），不是账号并发——出图队列跑的正是运营自己名下的请求，填 4 就只剩 1 个槽位给他手动操作。填满 5 的表现是「点什么都慢」但哪儿都不报错 |
| 🟡 单张出图超时 | 180 秒 | 填太短会把本来能出的图判成失败，**而钱可能已经花了**。没把握别动 |
| 🔴 **管理员联系方式** | 空 | **必须填**一个微信号或手机号 |
| 单次最多出几张 | 50 | 运营一次能提交多少张（图数 × 提示词数） |
| 三档单价 | 空 | **先留空**，第 8 步实测完再填 |
| 价格倍率 | 空 | 留空 = 按原价 |

> 🔴 **管理员联系方式必须填。** 不填的话，运营余额不足时界面只会说「请联系管理员」，
> **却说不出该找谁**——而充值和兑换码菜单对运营是隐藏的，等于死路一条。

> **⚠ 2026-08-14 更正：原来这里写「三档单价留空是对的」，那是错的，会出大问题。**
>
> 留空的真实后果**不是**「显示价格待确认」，而是：**冻结额记 0 → 决策 14 的
> 「余额不够就拒绝提交」这道拦截整个失效**，而健康检查仍然是绿的，你看不出来。
>
> 按决策 23，**三档全填 1**（见第 9 步）。而且要填**两处**：这里管预估和冻结，
> 分组那三格管真正扣钱，只填一处会对不上。

```bash
designkit/bin/dk-nas.sh up
```

**为什么现在重启**：第 6 步里的「同时出几张」「单张出图超时」「图片最长边」这三项，
出图队列**只在服务启动那一刻读一次**。趁还没开始出图先重启，省得后面再停一次。

> ⚠ 特别是「**图片最长边**」：不重启会出现最难查的一种状态——
> 工作台上显示的出图尺寸已经是新值，**真正发给 OpenAI 的还是旧值**，
> 两边对不上而且不报错。

## 第 8 步 🔴 开运营账号 + 出第一张图

### 8.1 让运营注册，然后你给额度

因为第 1 步开了自助注册，**你不用一个个建号了**：

1. 在「兑换码」菜单里生成一个邀请码，发给运营
2. 运营自己去 http://192.168.31.235:13000 注册
3. 🔴 **你去「用户管理」找到他，在那一行的操作菜单里点「充值」给额度**（单位美元）

**第 3 步没给额度的话，他注册了也出不了图**——因为新用户默认余额是 0。
这是故意的：花钱这件事始终在你手上。

> 不要直接改余额那一格，要用「充值」按钮——界面上也是这么说的。

> **也可以自己建号**：用户管理 → 创建用户，填邮箱密码、角色选普通用户。
> 急着测的时候比走注册流程快。

### 8.2 让运营提交一次（**这次一定会失败，是设计如此**）

用刚建的账号登录 → 生成工作台 → 传图 → 选比例 → 写提示词 → **提交**。

预期报错：「暂时没有可用的出图账号…」

**这一步的唯一作用**是让系统自动建出一把内部专用钥匙（名字固定 `designkit-internal`）。
这把钥匙**只在提交那一刻创建**，光打开页面不会创建。

### 8.3 🔴 给那把钥匙绑分组（**漏了这步就永远出不了图**）

**在哪**：管理员账号 → 用户管理 → 那个运营那一行 → 操作菜单 → **API 密钥** →
找到 `designkit-internal` → 改分组 → 选第 3 步建的分组

**为什么**：系统挑账号时只看「钥匙的分组」和「账号的分组」是不是同一个。
这把钥匙创建时**不绑任何分组**，而你的账号在第 4 步绑了分组，两边对不上，
于是永远挑不到账号。

**这是整条主线里最容易漏、漏了症状最难懂的一步**——账号明明建好了，
却一直说「没有可用的出图账号」。

**怎么确认做对了**：改完界面会提示「分组修改成功，已自动为用户添加「X」分组权限」。

### 8.4 再提交一次

这次应该能出图了。**一张图约 20 秒。**

> ⚠ **提醒运营：右上角头像菜单里的「API 密钥」那一页不要动。**
> 他能看到甚至删掉 `designkit-internal`。删掉之后下次提交会自动重建一把，
> 但**又是不绑分组的**，直接回到出不了图的状态。

## 第 9 步 🔴 把余额当成「还能出几张」

### 9.1 先理解一件事：你没有「每张多少钱」

你用的是 **ChatGPT Plus**，每月固定 $20，出多少张都是这个价。
**OpenAI 不会因为你多出一张图而多收你钱。**

| | 按张付费（API 密钥） | **你的情况（Plus）** |
|---|---|---|
| 上游怎么收费 | 出一张扣一笔 | 每月 $20，包月 |
| 「真实单价」 | 存在，能量出来 | **不存在** |
| 真正的限制 | 余额花完 | **出图次数上限**，撞到就出不了 |

所以系统里那些金额**不是真花出去的钱，是你给运营记的内部账**。

### 9.2 做法：一张图 = $1

**三档全填 1。** Plus 的额度按张算、跟图片大小无关，所以分档对你没意义。
这样余额数字直接就是「还能出几张」。

> ⚠ **要填两处，只填一处会对不上**（2026-08-14 实测踩过）：
>
> | 填哪 | 在哪 | 管什么 |
> |---|---|---|
> | **商品图设置 → 出图单价** | 左边菜单「商品图设置」 | **预估和冻结** |
> | **分组 → 图片单价 1K/2K/4K** | 分组管理 → 你那个分组 | **真正扣钱** |
>
> 只填第一处：预估显示 $1，实际只扣 $0.20（回落到上游默认价），余额掉得比账面慢。
> 只填第二处（第一处留空）：**更糟**——冻结额记 0，「余额不够就拒绝提交」
> 这道拦截**整个失效**，而健康检查仍然是绿的，你根本看不出来。
>
> 2026-08-14 实测确认：两处都填 1 之后，出一张图余额正好掉 1.00。

⚠ 另外记住：**分档不是「图越大越贵」**。系统按输出图的最长边分 1K/2K/4K，
实测请求 1:1 返回 1254×1254 → 落 **2K 档**。三档都填 1 就不用管这个。

### 9.3 给运营多少额度：按 Plus 额度的 80%

**我不知道你的 Plus 现在给多少张出图额度**——这个数 OpenAI 一直在调，
我编一个给你只会害你。两种办法测出来：

**办法一（准，但要花点时间）**：用你的 ChatGPT 账号在官网连续出图，
直到它提示到达上限，数一下出了多少张。

**办法二（省事）**：先按一个保守的数给（比如每人每月 30 张），
用一个月看看有没有人撞到「上游拒绝」。没撞到就往上加。

**然后**：给运营的额度 = 你测出来的月额度 × 80%。

留 20% 余量是因为：你自己也会用，而且撞到上限时出图会直接失败，
留点空间比刚好卡满强。

**在哪给**：用户管理 → 那个人那一行 → 操作菜单 → **充值**。

### 9.4 到底撞没撞上限，在这套系统里看不出来

Plus 的次数限制在 **OpenAI 那边**，我们这套系统不知道你还剩多少张。

撞上限的表现是：出图失败，错误信息里是上游返回的拒绝原因。
看到运营连续几张都失败、而之前一直好好的，**先怀疑是不是这个月的额度用完了**。

**怎么确认做对了**：运营在工作台选好图和比例后，角落显示的预估价不再是「价格待确认」，
而且数字等于张数。

## 第 9 步·b 🟡 知道「AI 挑提示词」要花多少钱

工作台第二步是让 AI 配提示词，**这一步也花钱**（跟出图共用同一个 ChatGPT 账号）。

| 分类 | 条数 | 一次推荐 | 耗时 |
|---|---|---|---|
| 社交媒体帖子 | 3978 | **$0.335** | ~110 秒 |
| 产品营销 | 3752 | ≈ $0.32 | ~110 秒 |
| 电商主图 | 428 | **$0.093** | ~30 秒 |

对比出一张图 $1，推荐占 **10%~33%**。

要告诉运营的两句话：

1. **反复点「重新推荐」是真的在花钱。** 虽然比出图便宜得多，但不是免费的。
2. **余额不再是整数了。** 你会看到 `98.97` 而不是 `99`，那些小数就是推荐的花费。

⚠ 这部分消耗**不算进「本月出图 N 张」**——那个数只统计真的出了图的。
但**算进「花费」**。所以运营会看到「张数 0、花费不是 0」，这是正常的。

如果觉得太贵，可以让运营**先选具体分类**（比如「电商主图」）而不是「全部分类」：
分类越小粗筛越便宜，428 条那个分类只要 $0.09。

## 第 10 步 🔴 备份

**这是唯一能把数据捞回来的东西。**

系统自带的备份要配 S3 云存储，你没有。所以用下面这条命令，
**我已经在你 NAS 上实测过一遍**（备份 31MB，恢复到临时库里 15045 条提示词一条不差）。

### 备份（在 Mac 上敲）

```bash
ssh dk-nas 'sudo sh -c "
  mkdir -p /volume3/docker/designkit-dev/backups
  S=\$(date +%Y%m%d-%H%M%S)
  /usr/local/bin/docker exec sub2api-postgres-dev pg_dump -U sub2api -d sub2api --clean --if-exists \
    > /volume3/docker/designkit-dev/backups/db-\$S.sql
  tar czf /volume3/docker/designkit-dev/backups/images-\$S.tar.gz \
    -C /volume3/docker/designkit-dev/src/deploy/data designkit
  ls -lh /volume3/docker/designkit-dev/backups/ | tail -4
"'
```

**两样都要**：数据库备份**不含图片**，图片在另一个目录里。

### 恢复（真出事的时候）

```bash
# 把 20260814-003500 换成你要恢复的那个时间戳
ssh dk-nas 'sudo sh -c "
  /usr/local/bin/docker exec -i sub2api-postgres-dev psql -U sub2api -d sub2api \
    < /volume3/docker/designkit-dev/backups/db-20260814-003500.sql
  tar xzf /volume3/docker/designkit-dev/backups/images-20260814-003500.tar.gz \
    -C /volume3/docker/designkit-dev/src/deploy/data
"'
```

> ⚠ **恢复会覆盖现在的数据。** 恢复之前先备份一次当前状态。

**多久备一次**：出图多的话每天一次。备份文件在
`/volume3/docker/designkit-dev/backups/`，**记得定期删旧的**，别把 NAS 撑爆。

# 放到公网之前必须做的事

你说了以后要放公网给外人用。**现在这套只在内网，很多东西是「内网够用」的状态，
放到公网就是漏洞。** 真要放之前，按下面这张表逐条过一遍再放。

**不要先放上去再补。** 公网上被人扫到只要几个小时。

## 🔴 必须做的（少一条都别放）

| 事 | 为什么 | 在哪 |
|---|---|---|
| **域名 + HTTPS** | 现在是 `http://` 明文。公网上明文传密码等于公开 | 需要买域名、配证书、加反向代理 |
| **备案** | 中国大陆的服务器对公众提供服务需要 | 服务器商那边办 |
| **清空邮箱后缀白名单** | 不清的话外人一律注册不了（见第 1.2 节） | 系统设置 → 安全与认证 |
| **打开人机验证** | 不开的话机器人几分钟能刷几千个号。上游支持 Cloudflare Turnstile / 腾讯 / 阿里云三选一 | 系统设置 → 人机验证 |
| **打开邮箱验证** | 不开的话随便填个不存在的邮箱就能注册 | 系统设置 → 安全与认证 |
| **默认余额保持 0** | 一旦大于 0，每个注册的人都在花你的钱，机器人刷号会直接变成账单 | 系统设置 → 用户默认值 |
| **改掉管理员密码** | 现在这个是系统自动生成的，而且出现在过我们的对话里 | 右上角头像 → 个人资料 |

## 🟡 建议做的

| 事 | 为什么 |
|---|---|
| **限流调紧** | 默认阈值是按内网自己人定的，公网上要防刷 |
| **注册邮箱域名配额** | 限制同一个邮箱域名最多注册几个号，防有人用临时邮箱批量注册 |
| **告警通知** | 出图失败率突然变高、余额被刷空，得有人知道 |
| **日志留存** | 现在日志只在容器里，重启就没了。出了事查不回去 |
| **定时备份** | 第 10 步那条命令目前要手动敲，放公网后应该做成自动的 |

## ⚠ 一件必须知道的事：**只能跑一个后端**

现在的代码**只允许跑一个实例**。公网流量大了想扩容，不能简单地多起几个——
起第二个会把同一批任务结算两遍，**用户余额凭空少一截而且不报错**。

真要扩容之前告诉我，那需要先补一样东西（分布式锁）。
