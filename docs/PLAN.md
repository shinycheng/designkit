> 面向已知人群的多人系统（管理员建号 **或** 发邀请码让对方自助注册，后者默认关闭），
> 架构上预留对外 SaaS 能力，提供标准 API 供 ERP 等系统对接。

## 三、第二期：接入真实生图（进行中）

**目标**：从"模拟出图"切换到"真实 AI 出图"，并把提示词库灌进系统。

| 2.7 | 比例放开 | AI 助手 | ✅ 已完成：护栏校验取代白名单，覆盖 1:1/3:4/4:5/2:3/9:16/3:2/4:3/16:9 八个电商版位；画幅措辞按尺寸计算 |
| 2.8 | 透明底出图 | AI 助手 | ✅ 功能已完成（提示词白底措辞改写、输入图透明补边、缩略图防黑块）；⚠️ **当前网关不支持**：实测 gpt-image-2 返回「Transparent background is not supported for this model」，换支持的模型即可用 |

**验收标准**：你的常用商品品类，每个核心模板都能稳定出可用的商品图。

**实测结论（2026-08-09，自建 Sub2API + gpt-image-2）**：
- 画质良好；网关**忽略 size 参数**，按输入图方向吸附比例
- **新放开的比例已实测通过**：竖长的可乐罐 → 3:4 出图 1086×1448（比例 0.750，精确）、
  16:9 出图 1672×941（比例 1.777，精确）。16:9 是最难的一档（竖罐塞进宽画幅），
  说明「按尺寸计算画幅措辞 + 输入图补边」这套控制手段是可靠的
- **该网关不支持 background=transparent**（明确 400 报错，不是静默忽略）
- 网关偶发 502「Upstream request failed」，重试即可——不是配置问题
- 耗时：网关空闲时可快到 20 秒，但实测区间是单张 1~5 分钟（参考图越多越慢），
  所以请求超时默认设成 360 秒
- 「按比例预处理」开关是控制出图比例的唯一手段，**必须保持开启**
- 因为比例由输入图决定，**自定义任意比例可行**（补边到目标比例即可），
  不受 gpt-image 三种官方尺寸限制。✅ 已落地（2.7）：白名单换成
  `backend/app/services/sizing.py` 的护栏校验，现有 8 个电商版位，加新版位只改一处

**风险提示**：
- 中转平台质量参差：接口不稳定/排队慢/悄悄换模型。选平台时优先支持 `gpt-image` 系列
  原生接口、按张计费透明的（当前默认对接自建 Sub2API 网关，模型 gpt-image-2）；系统已做自动重试和参数兼容重试，但平台跑路风险无法技术兜底，先小额充值。
- 生图费用：gpt-image 系列高画质单张成本明显高于低画质，建议日常用 medium、出正式图用 high。

**目标**：从局域网 NAS 搬到一台公网服务器，有域名、有 HTTPS，
陌生人可以自己注册（拿邀请码，或者用手机号收短信验证码）。

以前「能访问到这台机器」本身就是一道门，现在这道门没有了。

**这一期还剩什么**（代码侧的收尾，不挡上线）：

- **CORS 的设置层没有 422 闸门**：`allowed_origins` 填成 `*` 时，接口层照样存得进去，
  只是启动时被自动收窄。也就是说管理员在设置页上看到的仍是 `*`，
  和实际生效的值不一致。更好的做法是在开着注册时直接拒绝保存 `*`（像
  `allow_internal_targets` 那道闸门一样给一句可直接显示的中文），
  但那要改 `routers/settings_router.py`，另开一项。
- **CSP（Content-Security-Policy）**：前端是无构建原生 JS，内联脚本、`blob:` 图片预览
  都要一条条放行，需要整体规划一遍，单独一期。
> 「多 worker 下并发上限」的常驻回归已经补上（`tests/test_multiprocess.py`：
> 真起 uvicorn 多进程，盯住派发权唯一、领导者被杀后的接管时间、多进程首启建库、
> 限速不被进程数除、反代下的真实 IP）。**项数与怎么跑以
> [tests/README.md](../tests/README.md) 为准**——这里不抄数字，抄了必然某天对不上。

**验收标准**：从公司外网用域名打开是 `https://`；发一张邀请码给一个外部的人，
他能自己注册、登录、并在几分钟内生成第一张图；把 `trusted_proxy_hops` 配错时，
限速的表现能被观察到（说明这一项真的生效了）；登录响应的 `Set-Cookie` 末尾带
`Secure`（说明 `forwarded_allow_ips` 也配对了）。
多进程那条另加一条：开 `DESIGNKIT_WORKERS=2` 之后，日志里
「取得生成派发权」**只出现一次**，另一个进程打的是「转入待命」——
这就是「同时生成几张不会被乘以进程数」的现场判据。
手机号那条路额外加一条：**上线前必须在设置页点一次「试发一条」并确认那台手机
真的收到**——配置对不对没有别的验证办法；同时确认「短信通道」已经从默认的
调试模式切到阿里云（还停在调试模式的话，验证码直接显示在注册页上，等于没有验证）。

**已知的取舍（写下来免得以后当成 bug）**：

- `allow_internal_targets` 的**默认值故意没改**（仍是 `true`）。改默认会静默打断
  现有的 ERP 内网取图，而要开放注册的人会被闸门强制去关它——这就是闸门存在的意义。
- 群晖那个测试环境**可以继续用 http**：闸门对内网地址（RFC1918 私网 IP、
  无点主机名、`.local` / `.lan` / `.internal` 等）放行 http，只有公网主机才强制 https。
  否则合法的内网用法会被误判成配置错误。
- **`DESIGNKIT_FORWARDED_ALLOW_IPS` 的默认值故意是 `127.0.0.1` 而不是
  `172.16.0.0/12`**。后者对绝大多数 Docker 部署更方便，但它是「放宽信任」这个方向
  的改动——升级镜像就静默生效，而没人会记得自己什么时候放宽过。默认保持与改造前
  一字不差，要放宽由部署的人自己在 `.env` 里写一行。
- **CORS 收窄是在启动时做的，不是在保存设置时拦的**。因此设置页上显示的仍是 `*`，
  和实际生效的值不一致——这是已知的粗糙处，见上面「这一期还剩什么」第一条。
  当时选启动时收窄而不是保存时拦，是因为老库里可能已经存着 `*` 且注册也开着，
  保存时拦管不到那种存量状态，而启动时收窄两种都覆盖得到。
- **交接派发权的瞬间可能短暂超出并发上限一点点**：旧领导者手上已经在跑的图会跑完
  （半路掐断等于白花钱）。这与「进程崩溃」是同一类情况，无法也不必消除；
  正常运行期间上限是严格的。

## 八、固定注意事项

- **备份**：分两种情况，别搞混——
  - 本机开发（SQLite）：`data/` 目录就是全部数据，**停服后**整目录拷贝
  - 服务器 / NAS（PostgreSQL）：数据库在 docker 卷里，**只拷 `data/` 会丢掉全部模板和生成记录**。
    必须 `pg_dump` 备数据库 + `tar` 备整个 `data` 目录两份，命令见
    README「六、数据在哪里 / 怎么备份」
  - 两种情况都一样：`data/.secret_key`（登录令牌 + webhook 签名）和
    `data/.enc_key`（成员网关 Key 的解密钥匙）这两个隐藏文件必须在备份里，
    `tar` / `cp -r` 整个目录本来就会带上它们，但**要检查一遍**
- **升级依赖**：requirements.txt 已锁版本，升级前先按 `tests/README.md` 跑一遍回归
- **升级 Sub2API 网关之后必须复核自动开通**：这套功能依赖的是网关的实现细节
  （接口路径、409 的语义、Key 能否原样读回、合规版本号），**不是公开契约**，
  网关升一个版本就可能整条链路失效（表现是所有新成员都开不通，老成员照常生图）。
  升级后按 [docs/auto-provision.md](auto-provision.md) 第九节做三件事：
  点一次「测试能不能自动开通」比对两个版本号、跑 `test_provision*.py`、
  建个测试成员真出一张图。若网关某版本给管理端加上了「替用户签发 Key」的接口，
  整条「保管密码 + 代登录」的链路就该废弃（文档里给了两条 grep 命令）
- **自动开通的取值必须在真机上验一遍**：所有「默认值」都是网关源码的默认值，
  不等于那台实例（192.168.31.235）上的现状。上线前请用设置页的自检读一遍真实取值
  （后台模式 / 三个人机验证 / 两步验证 / 合规确认 / 远端账号的并发与分组）
- **密钥**：`.env`、`data/.secret_key`、`data/.enc_key`、API Key 明文只出现一次——
  都不要提交到 GitHub（.gitignore 已配好）。
  `.enc_key` 尤其要单独记一笔：它解的是全体成员的网关 Key，丢了的表现是
  「所有人突然都不能生图」而数据库看起来完好，根因极难查
- **开放自助注册之前，三条硬前置必须先满足**（系统会强制拦，但要知道为什么）：
  关掉「允许对外接口访问内网地址」、「对外访问地址」填成别人真打得开的地址
  （公网必须 https）、「图片链接需要凭证才能打开」保持开启。
  最要紧的是第一条：对外接口的取图/回调地址是**由服务端去访问**的，
  允许内网时它可以指向内网里的任何东西（含生图网关管理端口）。
  今天这条链是断的（对外接口 Key 只有管理员能建），
  但「只有管理员能建 Key」在代码里只是一行判断——`routers/apikeys.py`
  的文件头自己就写着「哪天改成 get_current_user 是一行改动」。
  强制关闭正是因为「断」得太脆弱。完整说明见 README 第八章 8.1。
  **这三条对「邀请码」和「手机号」两条路一视同仁**——只管住其中一条等于没管
- **手机号注册：短信是花钱的，而且被刷的代价不止是钱**。默认通道是 debug
  （不发真短信、不花钱），**上公网前必须切到阿里云**——还停在 debug 的话，
  验证码会直接显示在注册页上，等于没有验证，任何人都能注册进来，
  而且界面和日志都风平浪静，发现时账号已经进来一批了（设置页会常驻警告，
  但系统不会替你关，它分不清你是在内网试流程还是已经上了公网）。
  三层限速（同号冷却 + 每日、单 IP 每小时、全站每日）是这条通道能上线的前提，
  不是调优项：被刷狠了阿里云会以「疑似恶意」封掉签名，**重新申请按工作日算**，
  那几天谁也注册不进来。出事时一步止血的动作是**把通道切回调试模式**——
  注意只关「开放手机号注册」是不够的，已注册用户的登录发码不看那个开关。
  阿里云 AccessKey 一律让使用者自己在网页上填，**任何文档、配置模板、测试数据里
  都不许出现真实密钥**。详见 README 9.6 / 9.7
- **套了反向代理，两个配置项都要配，缺一不可**：
  `DESIGNKIT_FORWARDED_ALLOW_IPS`（**地址**：谁可以自称反代，默认 `127.0.0.1`；
  反代同机跑 Docker 填 `172.16.0.0/12`）回答「**信不信**代理头」，管 uvicorn；
  `DESIGNKIT_TRUSTED_PROXY_HOPS`（**层数**，一层填 `1`）回答「信到**第几段**」，
  管应用自己的限速取值。
  只配后者：限速对了，但协议仍是 http，取图 Cookie 的 `Secure` 判断还是错的。
  两个都不配的表现一样：「全站所有人共用一个限速桶」，一个人被限速全公司登不上。
  层数配大了更糟——系统会去信客户端自己伪造的那段地址，登录/注册限速当场作废。宁小勿大。
  **地址那一项永远不要填 `*`**：那会让 uvicorn 取最左边那一段，而最左边是客户端写的
- **开多个 uvicorn worker（`DESIGNKIT_WORKERS`）不会让「并发生成数」翻倍**，
  但这件事是 2026-08-12 才修的，之前的版本会。修法是给派发循环加一把数据库租约
  （`sync_state` 表的 `generation` 任务名），只有拿到租约的进程派发。
  排查时在日志里搜「取得生成派发权」——它**只应该出现一次**。
  另外 `DESIGNKIT_WORKERS > 1` **只能配 PostgreSQL 用**：建表/补列那把进程锁是
  PG 的咨询锁，SQLite 上直接跳过，多进程首启会有几个进程以「表已存在」崩掉再被拉起
- **前端不许出现外部域名**：不要把本地路径改回 CDN，不要新增 `preconnect`、
  外部字体、统计脚本。升级某个组件＝重新下载覆盖本地文件 + 更新
  `docs/AUTH_VISUAL_ATTRIBUTIONS.md` 里的版本号。自查：
  `grep -rn "https://" frontend/` 的结果里只应剩注释、文档链接和输入框示例
- **提示词是核心资产**：定期用「提示词模板」页的「导出」备份提示词库
