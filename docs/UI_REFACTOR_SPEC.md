# DesignKit UI 与交互重构开发规范

> **文档状态**：本文是界面重构的设计规范（意图与目标），不是实现现状的逐条对照。
> 与代码不一致时以代码为准；已知差异见文末「与当前实现的差异」。


> 状态：可进入设计实现评审
> 版本：v1.0
> 日期：2026-08-08
> 参考产品：[美图设计室](https://www.designkit.cn)
> 适用仓库：当前 DesignKit v0.1（FastAPI + 原生 ES Modules）

## 1. 结论

本次重构不是给现有后台“换皮”，而是把产品从通用 AI SaaS 后台改造成商品视觉生产工作台。

核心结构应由当前的“深色侧栏 + 白色卡片纵向表单 + 右侧结果卡”改为：

```text
┌──────────────────────────── 54px 顶栏 ────────────────────────────┐
│ 产品名称 / 新建任务                           帮助 / 用户菜单      │
├──── 68px 工具栏 ────┬──── 400px 任务配置 ────┬──── 弹性预览画布 ────┤
│ 生成工作台           │ 上传商品图             │ 空状态 / 生成进度     │
│ 生成记录             │ 模板与变量             │ 结果图网格 / 详情     │
│ 提示词模板           │ 尺寸、张数、画质       │ 下载 / 重试 / 对比    │
│ API 对接             │                        │                       │
│ 系统设置             │  sticky 主操作         │                       │
└──────────────────────┴────────────────────────┴───────────────────────┘
```

需要借鉴的是参考站的任务结构、信息密度、分栏方式、持续可见主操作与中性视觉语言；不得复制其 Logo、品牌色组合、示例商品图、营销文案、会员入口或其他品牌资产。

## 2. 背景与问题定义

当前界面功能完整，但视觉与交互呈现具有明显的“AI 生成模板”特征：

- 靛蓝主色、紫色渐变 Logo、浅灰背景、悬浮白卡、胶囊标签与 Emoji 图标同时出现。
- 所有页面都使用近似的 `.card / .row / .table` 骨架，业务场景缺少专属布局。
- 生成页是一次性展开的长表单，上传、模板、参数、主操作和结果被滚动距离割裂。
- 216px 深色侧栏抢占视觉权重，真正重要的商品图与生成结果反而不突出。
- 模板、上传区、历史卡等使用 `div + onclick`，键盘操作和语义不足。
- 模板切换与上传完成会重建整列 DOM，可能导致焦点丢失、滚动跳动。
- 当前移动端基本不可用：390px 视口下，216px 侧栏仍常驻，正文只剩约 174px。

重构目标是让用户感知到“这是一个成熟的商品视觉工具”，而不是“一个套了 AI 主题的管理后台”。

## 3. 目标与非目标

### 3.1 目标

1. 以生成工作台为产品核心，形成“配置持续可见、结果持续可见”的创作布局。
2. 建立可复用的设计令牌、图标、表单、反馈、弹窗和数据展示体系。
3. 保留现有全部业务能力、API 契约、Hash 路由和用户数据。
4. 保持零框架、零构建：继续由 FastAPI 托管原生 HTML/CSS/ES Modules。
5. 解决现有移动端横向溢出、键盘不可达和对比度不足的问题。
6. 为后续商品套图、批量任务等能力预留可扩展的工作台结构。

### 3.2 非目标

- 不复制美图设计室的 Logo、插画、商品案例、会员体系、文案和代码。
- 不引入 React、Vue、Vite 或运行时状态库。
- 不修改 `/api/web/*`、`/api/v1/*` 的契约。
- 不在本轮新增商品套图、A+ 详情、AI 模特等业务能力。
- 不以“像素级复制整个目标站”为目标；只对齐与当前产品相关的工作台模式。
- 不改变 `admin/member` 权限语义和 API Key 一次性展示规则。

## 4. 调研范围与证据限制

### 4.1 本次查看的参考流程

| 步骤 | 页面/状态 | 健康度 | 关键观察 |
|---|---|---:|---|

### 4.2 证据限制

- 参考站仅审计公开、未登录页面；未注册、未上传图片、未发起生成、未检查付费流程。
- 未验证参考站完整移动端策略；本项目的响应式规范应独立达到可用标准，而不是复制参考站的桌面限制。
- 截图只能支持视觉和可见交互结论，不能证明参考站符合完整 WCAG 要求。
- 参考站控制台出现一条 `MaxListenersExceededWarning`；该实现问题与本项目重构目标无关，不应照搬。

## 5. 参考站可借鉴的设计语言

### 5.1 页面结构

在 1280×720 视口实测：

| 区域 | 尺寸/行为 |
|---|---|
| 顶栏 | 54px 高，白底，底部 `#EAEDF2` 细边框 |
| 工具栏 | 68px 宽，白底，右侧轻边框，图标与文字纵向排列 |
| 任务配置面板 | 400px 宽，独立滚动，底部主操作固定 |
| 预览画布 | 剩余宽度自适应；1280 视口下约 812px；背景 `#F3F5F7` |
| 画布内容边距 | 约 32px 纵向、24px 横向 |
| 主按钮 | 44px 高，8px 圆角，黑底白字，600 字重 |

这种布局的价值不是“看起来像参考站”，而是让配置与结果形成稳定的左右关系，用户在整个生成过程中都知道：当前输入是什么、下一步是什么、结果会出现在哪里。

### 5.2 视觉特征

- 大面积中性灰白，而不是紫蓝渐变背景。
- 主要文字接近 `#1C1D1F`，次级文字使用半透明中性色。
- 黑色承担主操作，蓝色只承担选中、链接、焦点和 AI 辅助提示。
- 边框多于阴影；阴影仅用于浮层和必要的层级分离。
- 组件常用 8px、12px 圆角；胶囊仅用于筛选或状态，不用于所有按钮。
- 正文基准约 14px/22px，重点标题通过字重与留白建立层级。
- 图像和画布是主角，控件视觉保持克制。

### 5.3 交互特征

- 主操作持续可见，不要求用户滚到表单末尾。
- 参数采用渐进展开，复杂项不一次性铺满页面。
- 选项切换原位更新，不重建整个页面或改变画布位置。
- 空状态同时解释结果区域的用途，并预示最终产出形态。
- 模板浏览依赖真实缩略图、分类和筛选，不依赖长描述文本。
- 工具栏提供稳定位置记忆，当前工具以背景块和图标状态共同标识。

## 6. 不应照搬的部分

1. 不使用参考站 Logo、彩色品牌图标、营销横幅和示例耳机素材。
2. 不加入会员价格、礼物入口、批量托管等当前项目不存在的功能。
3. 不复制首页的 AI 团队、多业务场景和营销内容层级。
4. 不照搬参考站可能存在的低对比度次要文字、无标签 switch 或桌面最小宽度限制。
5. 不让内部管理页面为了“像参考站”而失去数据密度和操作效率。
6. 不把目标站的 hashed class、CSS 或静态资源带入本仓库。

## 7. 重构设计原则

### 7.1 工具优先，不是后台优先

生成页采用创作工具布局；管理页采用高效数据布局。两类页面共享壳层和令牌，但不强行共享同一种卡片结构。

### 7.2 结果优先

商品图、生成状态和结果图占据最大视觉面积。上传说明和模板描述退居辅助层级。

### 7.3 逐步披露

默认只展示完成当前任务所需的信息。变量、补充要求、高级参数和危险操作按需展开。

### 7.4 稳定的空间记忆

导航、配置面板、主操作和结果画布在任务过程中不换位。状态变化尽量局部更新。

### 7.5 克制的 AI 表达

“AI”通过效率、状态、智能默认值和结果质量体现，不再依赖渐变、Emoji、发光阴影和大面积紫色。

### 7.6 可访问性是组件契约

字段关联、键盘操作、焦点管理、live region、错误定位和对比度由共享组件保证，不由每个页面临时处理。

## 8. 信息架构与导航

现有 Hash 路由全部保留：

| 现有路由 | 新导航名称 | 参考模式 | 布局类型 |
|---|---|---|---|
| `#/generate` | 生成工作台 | 商品套图 | 工具栏 + 配置面板 + 画布 |
| `#/history` | 生成记录 | 最近打开 / 项目 | 工具栏 + 内容网格 |
| `#/templates` | 提示词模板 | 模板中心 | 工具栏 + 搜索筛选 + 模板内容 |
| `#/inspiration` | 灵感库 | 素材/灵感浏览 | 工具栏 + 搜索筛选 + 卡片列表 + 详情抽屉 |
| `#/apikeys` | API 对接（仅管理员） | 独立管理工具 | 工具栏 + 数据表/指南 |
| `#/settings` | 系统设置（仅管理员） | 设置页 | 工具栏 + 分组表单 |

「灵感库」浏览内置的开源提示词库，可把某条提示词一键带到生成工作台，或（管理员）采用为正式模板。

桌面工具栏顺序：生成、记录、模板、灵感、API、设置。其中 API 与设置带 `adminOnly`，
普通成员登录后侧栏只显示前四项。退出登录与用户信息放在顶栏用户菜单，不作为主导航项。

## 9. 应用壳层规范

### 9.1 桌面（≥1200px）

- 顶栏：54px，固定在应用顶部。
- 工具栏：68px，固定在左侧；每个操作区至少 56×56px。
- 当前项：`#F3F5F7` 背景、`#1C1D1F` 图标与文字；不能只依靠颜色。
- 非当前项：透明背景、次级文字；hover 使用 `rgba(0,31,92,.06)`。
- 生成页在工具栏右侧增加 400px 配置面板；其他页面直接进入内容区。
- 顶栏显示产品名、页面级动作、帮助和用户菜单。

### 9.2 中等宽度（960–1199px）

- 工具栏仍为 68px。
- 生成配置面板缩至 360px。
- 结果画布继续可见，不改为纵向长表单。
- 复杂模板列表可使用抽屉，但主操作保持可见。

### 9.3 窄屏（<960px）

- 隐藏桌面工具栏，改为底部导航或顶部菜单抽屉。
- 生成页切换为“配置 / 结果”两个视图，状态和已填内容保留。
- 主按钮固定在安全区域上方，不能遮挡表单。
- 数据表转为卡片行或受控横向滚动，不允许页面级横向滚动。
- `<640px` 弹窗改为全宽底部面板；使用 `100dvh` 和安全区变量。

### 10.1 使用规则

- 主操作使用黑色；蓝色用于链接、选择、AI 辅助、焦点和信息提示。
- 危险操作保持红色，但默认不与主操作并列抢占注意力。
- 普通内容区主要依靠边框和背景分层，避免所有模块都有阴影。
- 只有筛选、状态和小型模式切换允许使用胶囊形态。
- 12px 文本只能用于非关键辅助信息，并必须达到 WCAG AA 对比度。

## 11. 图标与资产规范

- 删除导航、上传、模板、空状态、按钮中的系统 Emoji。
- 使用真实开源图标库，推荐将 Lucide 的浏览器版本按许可证本地化到 `frontend/vendor/`，运行时不依赖 CDN。
- 默认图标为 20×20px、1.75px stroke；工具栏图标可为 22×22px。
- 所有纯图标按钮必须提供 `aria-label` 和 tooltip。
- 不制作参考站 Logo 的近似版本。没有正式品牌资产时使用纯文字产品名，不伪造图形标志。
- 模板与历史卡优先使用真实 `thumbnail_url` 和生成结果；没有图片时使用图标库图标 + 简短文案。
- 如需要插画型空状态，应在实现阶段用自有资产或 ImageGen 生成，不使用参考站插画。

## 12. 共享组件规范

### 12.1 Button / IconButton

- 变体：`primary / secondary / quiet / danger`。
- 高度：32 / 40 / 44px；触控场景最小 44×44px。
- loading 时保持原宽，显示 spinner 与进行中文案。
- disabled 必须提供可见原因，不能只降低透明度。
- 焦点使用 2px outline + 2px offset。

### 12.2 Field

- 自动生成并关联 `label[for]`、control `id`、help/error `aria-describedby`。
- 错误紧邻字段，toast 只做补充通知。
- placeholder 不承担字段标签职责。
- 输入高度 40px，textarea 最小 96px。

### 12.3 FilterChip / SegmentedControl

- **筛选胶囊（实际在用）**：模板分类、记录状态筛选用 `.dk-filter-chip`，
  可横向滚动，选中态为深色底 + `aria-pressed="true"`。
- **模板卡片**：用 `role="option"` + `aria-selected`，配合父级 `role="listbox"`。
- **共享分段控件**：`ui.js` 里的 `segmentedControl` 内部是单选组语义
  （`role="radio"` + `aria-checked` + `data-selected`），**目前尚无页面使用**。
  新页面若要用分段控件，直接复用它，不要再造一套。
- 选中状态同时使用背景与文字权重，不只靠颜色。
- 左右方向键可在组内移动。
- 胶囊仅用于短标签，不包裹长描述。

### 12.4 Dialog / Drawer / Lightbox

- 使用 `role="dialog"`、`aria-modal="true"` 和可关联标题。
- 打开后焦点进入，Tab 被限制在浮层内，Escape 关闭，关闭后返回触发器。
- 危险确认必须明确对象名称和后果。
- 图片预览提供明确关闭、下载、上一张/下一张按钮。

### 12.5 Toast / InlineAlert

- `aria-live` 区域常驻 DOM。
- 关键错误必须保留在页面对应区域；toast 不作为唯一错误反馈。
- 成功 toast 约 2.6 秒自动消失；错误在用户确认或状态改变前保持更久。

### 12.6 EmptyState / Skeleton

- 空状态包含：发生了什么、如何开始、唯一主操作。
- 首次加载使用 skeleton，避免整页 spinner。
- 生成中的画布保留已有缩略图和任务信息，不能清空为纯 spinner。

## 13. 生成工作台详细规范（P0）

生成工作台是第一阶段唯一必须完成视觉闭环的页面。

### 13.1 工具栏

- 生成工作台为当前项。
- 管理员专属入口继续按角色隐藏。
- hover 显示简短 tooltip，当前项同时使用 `aria-current="page"`。

### 13.2 配置面板

从上到下：

1. 商品原图
2. 模板与提示词
3. 模板变量（选中模板后出现）
4. 生成设置
5. 补充要求（默认折叠或弱化）
6. sticky 主操作

面板自身滚动；主操作固定在面板底部，不随内容滚出视口。

### 13.3 商品上传

- 初始为紧凑虚线上传区，支持点击和拖拽。
- 上传后虚线框缩成一条窄按钮（`is-compact`），不保留大面积空 dropzone；
  已上传的图以**纵向列表**呈现，每行是「52×52 缩略图 + 文件名/状态 + 重试/删除」。
- 单项状态：`queued → uploading → uploaded / failed / removed`。
- 展示剩余可上传数量和失败原因。
- 删除按钮至少 32×32px，并提供文件名对应的可访问名称。
- 保留现有最多 4 张、单张 20MB 规则；格式为 **PNG / JPG / WEBP / HEIC（含 HEIF）**。
  HEIC 是 iPhone 拍照的默认格式，运营可以直接拖 iPhone 原图进来，不必先转 JPG。

### 13.4 模板选择

- 顶部用分类**筛选胶囊**（可横向滚动）；下方使用紧凑模板列表或 2 列卡片。
- 有 `thumbnail_url` 时以图片为主；无图时使用图标和名称，不显示 Emoji。
- 选中后展示名称、变量和默认参数摘要；列表本身不堆叠完整长描述。
- 自由提示词作为一种明确模式，与模板模式互斥。
- 切换模板只更新模板区、变量区和派生参数，不重建上传区或画布。

### 13.5 生成设置

- 尺寸使用带比例示意的选项；保留三个现有尺寸值。
- 张数使用 stepper 或紧凑 select，范围仍为 1–4。
- 画质默认 high，保留 auto/high/medium/low。
- 主按钮文案由 `deriveSubmitState` 派生，共 9 种，**自上而下短路判定**：

  | 顺序 | 条件 | 文案 | 可点 |
  |---|---|---|---|
  | 1 | 正在提交 | `正在创建任务…` | ✗ |
  | 2 | 任务执行中 | `任务生成中…` | ✗ |
  | 3 | 没选生成方式 | `请选择生成方式` | ✗ |
  | 4 | 自由模式没写描述 | `请填写画面描述` | ✗ |
  | 5 | 还有图在上传 | `等待商品图上传` | ✗ |
  | 6 | 模板要求原图但没传成功 | `请先上传商品图` | ✗ |
  | 7 | 必填变量没填 | `请填写{变量名}` | ✗ |
  | 8 | 上次失败且配置没变 | `重新生成` | ✓ |
  | 9 | 满足条件 | `生成 N 张商品图` | ✓ |

- **是否必须上传商品图取决于所选模板的 `requires_input_image`**：
  自由模式和不要求原图的模板，可以一张图都不传就直接生成。

### 13.6 结果画布

画布状态必须覆盖：

| 状态 | 呈现 |
|---|---|
| `none` | 结果形态预览 + 简短引导，不使用 Emoji |
| `pending` | 任务摘要、排队状态、已选模板和输入缩略图 |
| `processing` | 保持输入与摘要，显示进度感和“可离开页面”的说明 |
| `succeeded` | 结果网格、选中图大预览、下载、重新生成 |
| `failed` | 原位错误说明、可恢复建议、重试；不清除输入配置 |
| `missing` | 任务不存在或被删除，回到新任务的明确入口 |

结果图是最大视觉元素。桌面画布不得继续缩为普通 400px 卡片。

### 13.7 轮询与生命周期

- 用串行 `setTimeout` 或共享 Poller 替换异步 `setInterval`，避免请求重叠。
- 上一次请求结束后再调度下一次。
- 终态、404、401、路由销毁时停止。
- 页面隐藏时暂停或降低频率。
- 每次请求携带 sequence 或 AbortController，忽略迟到响应。

## 14. 生成记录规范（P1）

- 顶部工具条：状态筛选、搜索、结果数量、刷新。
- 有数据时使用视觉画廊；图片、状态、模板名、时间形成清晰层级。
- 空状态只保留“还没有生成记录”和“去生成工作台”主操作。
- 任务详情在桌面用侧边 Drawer，在窄屏用全屏页面/底部面板。
- `pending/processing` 卡片局部自动刷新，不重绘整个列表。
- 删除后自动处理空页回退；危险确认明确会删除图片文件。

## 15. 提示词模板规范（P1）

模板页分为“浏览”和“管理”两个视觉层次，但不新增路由：

- 顶部：搜索、分类筛选、状态筛选；管理员显示新建/导入/导出。
- 默认以带缩略图的模板网格呈现，更接近模板中心。
- 管理员可切换到紧凑表格视图，处理变量、状态和批量管理。
- 模板编辑使用 Drawer 或大 Dialog，分为基本信息、提示词、变量、默认参数。
- 变量编辑器不再使用固定 7 列；每个变量是一条可折叠编辑单元。
- 导入 JSON 前展示校验结果和“将新建/更新多少项”，确认后再写入。

## 16. API 对接规范（P2）

- 页面分为 API Key 列表和接入指南，不把所有说明放进一个大卡片。
- 创建 Key 使用 Dialog；完整 API Key 和 Webhook Secret 的“一次性显示”必须显著提示。
- SecretReveal 提供复制状态，但关闭后不可再次从前端恢复完整值。
- 额度、已用量、启停状态使用清晰列和文字，不只依赖 Badge 颜色。
- 代码示例使用可横向滚动的 code block 和单独复制按钮。

## 17. 系统设置规范（P2）

- 分为生图服务、运行参数、安全与网络、账号安全四个 section。
- 每个 section 有独立 draft、dirty、saving、success/error，不保存一个区域时重绘其他区域。
- OpenAI API Key 保持掩码；“测试连接”与“保存”是两个不同动作。
- 需要重启才生效的设置在字段旁明确说明。
- 危险或安全相关选项使用 InlineAlert 解释影响。

## 18. 登录与首次改密规范（P2）

- 去掉紫粉渐变背景和 Emoji Logo，使用中性背景与纯文字产品名。
- 字段必须有可见 label，密码支持显示/隐藏。
- 登录错误显示在表单内，并将焦点移到错误摘要或首个错误字段。
- 首次改密是阻断流程：不能通过普通关闭按钮绕过；取消应明确退出登录。
- 新密码要求和匹配状态实时可见，但不暴露密码内容。

## 19. 状态模型

| 模块 | 状态机 |
|---|---|
| 会话 | `checking → anonymous / authenticated / password-change-required` |
| 页面数据 | `idle → loading → ready / empty / error` |
| 写操作 | `idle → validating → submitting → success / error` |
| 上传项 | `queued → uploading → uploaded / failed / removed` |
| 模板选择 | `unselected / free-prompt / template(id)` |
| 生成任务 | `none → pending → processing → succeeded / failed / missing` |
| Overlay | `closed → opening → open → closing` |

规则：

- `canSubmit`、可见模板、默认参数等均由当前 state 派生，不存重复布尔值。
- 写操作只锁定相关区域，不让整页失去可读性。
- 错误保留用户已填内容，除非数据本身不再有效。
- 路由销毁时关闭所属 overlay、清理 timer / 轮询、解除 listener。
  **未返回的普通请求不会被 abort**——靠序号比对丢弃迟到结果即可
  （目前只有上传队列和轮询用了 `AbortController`）。
- **生成工作台是例外，跨页面保留状态**：离开时只做「存配置快照 + 停轮询 + 退订上传通知」。
  正在上传的图片请求、已提交但还没返回的生成任务都继续跑；回到该页会自动接回上传队列
  和那笔在途提交，上传图 / 模板 / 变量 / 尺寸张数画质 / 当前任务全部还在。
  只有**退出登录**才清空（`clearGenerateSessions`）。

## 20. 可访问性要求

目标为 WCAG 2.2 AA 的可实现范围：

- 使用 `header/nav/main/aside`、真实 H1 和 skip link。
- 路由导航使用 link，当前页使用 `aria-current="page"`。
- Dropzone、模板卡、历史卡使用真实 button/link 或完整键盘等价交互。
- 字段拥有 label、help、error 关联；placeholder 不代替 label。
- Dialog 具备焦点陷阱、Escape、返回焦点。
- Toast 和生成状态通过 live region 宣布。
- 状态不只靠颜色；图标必须有替代文字或正确隐藏。
- 所有业务图片有 `alt`、显式尺寸和懒加载策略。
- 控件触控目标不小于 44×44px。
- 支持 `prefers-reduced-motion`，禁止 `transition: all`。
- 视觉回归之外必须做纯键盘流程和 200% zoom 检查。

## 21. 工程重构方案

### 21.1 不可破坏的兼容面

1. `/api/web/*`、`/api/v1/*` method/path/query/body/status/response 不变。
2. 生成请求继续提交：`template_id/prompt/variables/extra_instructions/upload_ids/n/size/quality`。
3. 状态继续使用：`pending/processing/succeeded/failed`。
4. Hash 路由继续使用：`#/generate`、`#/history`、`#/templates`、`#/inspiration`、`#/apikeys`、`#/settings`。
5. 首轮保留 `dk_token`、`dk_user` 和 `dk-unauthorized`，避免用户被强制退出。
6. API Key 和 Webhook Secret 继续只在创建后完整展示一次。
7. 保留 FastAPI 静态入口 `/js/app.js`、`/css/app.css`。

### 21.2 建议 CSS 结构

```text
frontend/css/
├── app.css
├── tokens.css
├── reset.css
├── base.css
├── shell.css
├── components.css

- `app.css` 继续作为聚合入口。
- 旧 CSS 变量在迁移期映射到新语义令牌，迁移完成后删除。
- 现有 JS 中约 49 处内联 style 迁移为语义类；只有运行时计算值可保留内联。
- 状态优先使用 `[data-state]`、`[data-selected]`、`[aria-current]`，减少泛化 `.active/.green/.sm`。

统一视图接口：

```

### 21.4 深模块边界

只建立能隐藏复杂性的模块：

- HTTP Client：鉴权、FormData/JSON、401 和错误归一化。
- Overlay Manager：Dialog、Drawer、Lightbox 的焦点与生命周期。
- Poller：串行调度、暂停、取消、退避和终态停止。
- Generate Model：模板默认值、变量、校验、请求体和任务状态。

不要把每个 `<div>` 或单个 API 请求包装成无价值的浅模块。

## 23. 验收标准

### 23.1 视觉

- 1440×900 与 1280×720 下生成页符合“三栏工作台”结构。
- 画布是最大视觉区域；配置和结果无需在同一页面纵向追逐。
- 全站不再出现 Emoji 功能图标和紫粉渐变背景。
- 主操作、选中态和链接使用不同语义，不再全部使用同一紫色。
- 普通 section 主要依靠边框和背景，不滥用阴影。

### 23.2 响应式

- 390×844、768×1024、1280×720、1440×900 均无页面级横向滚动。
- 390px 下导航不常驻占用 216px；生成配置和结果可明确切换。
- 表格、变量编辑器和 Dialog 有确定的窄屏形态。
- sticky 主操作不遮挡最后一个字段。

### 23.3 交互

- 纯键盘可完成登录、上传、选模板、填变量、生成、下载、重试。
- 模板或参数变化不重建上传区和结果画布。
- 轮询不重叠；离开路由后不继续更新 DOM。
- 所有写操作有 loading/success/error 状态，失败保留用户输入。
- 未满足生成条件时，主按钮附近显示具体缺失项。

### 23.4 业务兼容

- 现有 `e2e_core.py` 和 `e2e_security.py` 在隔离数据环境中保持通过。
- OpenAPI path/method/schema diff 为零。
- admin/member 导航与权限行为不变。
- API Key 一次性 Secret 语义不变。
- mock 与 OpenAI provider 请求参数不变。

### 23.5 可访问性

- 关键正文和辅助文字达到 WCAG AA 对比度。
- Dialog 焦点限制、Escape 和焦点返回通过。
- 所有字段有 label/error 关联；状态与 toast 可被读屏宣布。
- 所有 icon-only button 有可访问名称。
- `prefers-reduced-motion` 下关闭非必要动画。

## 25. 已知风险与取舍

| 风险 | 处理 |
|---|---|
| 一次性重写导致业务回归 | 以现有路由接口为迁移缝，逐路由替换 |
| 为追求相似度误复制品牌资产 | 只复制布局规律与交互原则，资产独立 |
| 原生 JS 拆分后模块过多 | 只对复杂边界建深模块，避免一元素一组件 |
| 新旧 CSS 互相污染 | 新样式使用 `dk-` 前缀，旧变量做短期 alias |
| 轮询与渲染互相竞争 | 抽共享 Poller，局部更新并支持 abort |
| 移动端为桌面布局的缩小版 | 使用独立导航和“配置/结果”视图，不缩放三栏 |
| 图标库增加依赖 | 本地 vendoring、固定版本、记录 ISC 许可证，无 CDN |
